## Results

### Blind instance overwrite

The baseline instance was `192.0.2.10:443`, custom attribute `role=primary`, and healthy. A role with only `servicediscovery:RegisterInstance` on the exact service called `RegisterInstance` with the same ID and changed it to `198.51.100.66:8443`, `role=attacker`. Its `ListInstances` and `GetInstance` calls were denied. Admin polling showed the async operation succeeded and discovery returned the replacements.

This is expected behavior and a useful traffic-redirection/persistence primitive, not a defect.

### Custom health suppression

After replacing the policy with only exact-service `UpdateInstanceCustomHealthStatus`, the role submitted `UNHEALTHY`; its health read was denied. The change appeared after tens of seconds. Healthy-only clients then exclude the instance. The action can also restore a stale/rogue instance with `HEALTHY`.

### Discovery authorization and telemetry

A `DiscoverInstances` policy containing only the exact service ARN failed on the namespace ARN. Adding both exact ARNs succeeded and returned all custom attributes. Both CLI `--no-sign-request` and direct unsigned data-endpoint calls returned `MissingAuthenticationTokenException`.

`DiscoverInstances` and `DiscoverInstancesRevision` are CloudTrail data events. They did not appear in Event history. AWS documents that advanced selectors for namespace/service resources are required.

| Management event | Observed fields |
| --- | --- |
| `RegisterInstance` | Service/instance IDs, full attribute map, creator token, operation ID |
| `UpdateInstanceCustomHealthStatus` | Service/instance IDs and requested status |
| `DeregisterInstance` | Service/instance IDs and operation ID |
| create/delete namespace/service | IDs, tags/configuration and operation IDs |
| successful reads | Request selectors; response omitted |

### Cross-account boundary

Official RAM behavior was reviewed. Namespace sharing is organization-scoped. Consumers can create services/register instances in their services and discover the shared namespace; the owner retains management control. `PutResourcePolicy`, `GetResourcePolicy`, and `DeleteResourcePolicy` are permission-only AWS RAM dependencies. No second authorized organization account was available, so no share was created.
