# AWS Pricing Plan Manager audit — 2026-09-30

## Result

The September 2026 Pricing Plan Manager API creates a significant financial-control surface for CloudFront flat-rate plans:

- `ApprovePaidSubscription` activates an existing pending paid plan and starts billing.
- `UpdateSubscription` independently upgrades an active plan immediately, up to Premium level 6 ($10,000/month), or requests a downgrade that immediately removes higher-tier-exclusive features.
- `CancelSubscriptionChange` reverses a scheduled cancellation/downgrade and can extend the existing tier into another billing cycle.
- `CancelSubscription` ends a paid plan only at the end of the current billing period; no refund/current-period reversal is available.

Added a missing enum page and two post-exploitation techniques: financial abuse and protection/allowance downgrade. These are expected AWS functions, not vulnerability candidates.

## New-service provenance

The system AWS CLI 2.34.45 does not include this service. AWS CLI 2.37.6 includes the `pricing-plan-manager` client and nine operations:

`ApprovePaidSubscription`, `AssociateResourcesToSubscription`, `CancelSubscription`, `CancelSubscriptionChange`, `CreateSubscription`, `DisassociateResourcesFromSubscription`, `GetSubscription`, `ListSubscriptions`, and `UpdateSubscription`.

The endpoint rules route every configured Region to `https://pricingplanmanager.us-east-1.api.aws` and sign for `us-east-1`. The API currently supports only the CloudFront plan family.

## Cost and lifecycle boundary

- Paid `MANUAL` creation produces `PENDING_APPROVAL`, no billing, no automatic expiry, and consumes quota.
- `ApprovePaidSubscription` or paid `IMMEDIATE` creation starts billing.
- One-step paid creation requires both `CreateSubscription` and `ApprovePaidSubscription`; AWS recommends separating them.
- Active plan upgrades and higher Premium usage levels take effect immediately and are prorated.
- Downgrades and cancellations financially complete at the end of the calendar-month billing period.
- AWS documents an important immediate downgrade effect: higher-tier-exclusive features become unavailable immediately even while current-tier billing/allowances persist to period end.
- Active paid plans cannot be reverted or refunded in the current billing period. For this reason no create, approve, update, cancel, association or disassociation mutation was performed.

## Inventory and authentication

Administrator `ListSubscriptions` returned an empty list. Supplying `eu-west-1` also returned the same empty global inventory because the endpoint rule routes it to `us-east-1`; public commands use `us-east-1` explicitly. An unsigned list request failed with `MissingAuthenticationTokenException`.

## IAM scoping: documented table drift and live behavior

The Service Authorization Reference currently:

- leaves the resource-type column blank for all nine actions;
- defines a regionless template `arn:${Partition}:pricingplanmanager::${Account}:subscription/${SubscriptionId}`;
- defines no service-specific condition keys.

AWS's getting-started examples instead return regional ARNs. Live restricted-session tests showed the effective boundary:

| Probe | Matching synthetic ARN | Different synthetic ARN | Conclusion |
| --- | --- | --- | --- |
| `ListSubscriptions` with `Resource: "*"` | Empty success | n/a | Wildcard-only discovery |
| `ListSubscriptions` with exact subscription ARN | Access denied | n/a | Exact ARN cannot scope the list action |
| `GetSubscription` with exact ARN A | Passed IAM, then invalid/nonexistent ARN validation | Access denied on ARN B | Exact target scoping works |
| `UpdateSubscription` with exact ARN A | Passed IAM, then validation | Access denied on ARN B | Exact target scoping works |
| `ApprovePaidSubscription` with exact ARN A | Passed IAM, then validation | Access denied on ARN B | Exact target scoping works |
| `CancelSubscriptionChange` with exact ARN A | Passed IAM, then validation | Access denied on ARN B | Exact target scoping works |
| `CancelSubscription` with exact ARN A | Passed IAM, then validation | Access denied on ARN B | Exact target scoping works |
| `DisassociateResourcesFromSubscription` with exact ARN A | Passed IAM, then validation | Access denied on ARN B | Exact target scoping works |

The session policies were the only grants constraining `ChackBotAdministratorRole`, so the A/B denials prove request-resource binding. The public page tells defenders to use the exact ARN returned by the API rather than constructing it from the inconsistent reference template. The documentation mismatch is not a security-impact vulnerability and does not warrant a private report.

AWS-managed `PricingPlanManagerReadOnlyAccess` and `PricingPlanManagerFullAccess` both use `Resource: "*"`, even though narrower target grants work live.

## Attack boundary

### Charge activation and escalation

- Existing pending plan: exact `ApprovePaidSubscription` plus current ETag. A current ETag can come from exact `GetSubscription` or wildcard `ListSubscriptions`.
- Existing active plan: exact `UpdateSubscription` plus current ETag. The authorization table documents no `ApprovePaidSubscription` dependency for upgrades.
- One-step new paid plan: wildcard `CreateSubscription` plus approval authority, an eligible same-account distribution and global WAF web ACL. No dependent CloudFront/WAF action is listed, but service resource/account compatibility still applies.
- Extend current charges: exact `CancelSubscriptionChange` plus current ETag against a scheduled cancellation/downgrade.

### Protection/allowance downgrade

Exact `UpdateSubscription` can request a lower tier and higher-tier-exclusive features become unavailable immediately. Exact `CancelSubscription` returns the resources to pay-as-you-go after period end. Exact `DisassociateResourcesFromSubscription` can remove optional hosted-zone/KeyValueStore coverage, but required distribution/WAF resources cannot be removed.

This does not directly mutate or delete the CloudFront, WAF, Route 53 or KeyValueStore resource. Impact is plan features, allowances, and cost treatment.

## Telemetry

CloudTrail indexed all restricted probes under `pricingplanmanager.amazonaws.com` in `us-east-1`:

- `ListSubscriptions` was `readOnly: true`;
- targeted operations were `readOnly: false`;
- request parameters retained ARN, ETag, tier, usage level and generated idempotency token;
- targeted events populated `resources` with type `AWS::PricingPlanManager::Subscription` and the request ARN;
- both validation failures and exact-resource access denials were retained.

This makes the techniques low-stealth. Billing/invoice changes and live subscription state are independent detection sources.

## Cleanup

No Pricing Plan Manager, CloudFront, WAF, Route 53, KeyValueStore, IAM or other resource was created or changed. Only empty list calls, unauthenticated controls, nonexistent-resource authorization probes and expiring STS sessions were used. Final lists through both Region inputs remained empty.
