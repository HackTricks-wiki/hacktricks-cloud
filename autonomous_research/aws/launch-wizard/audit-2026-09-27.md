## Results

### Workload discovery

`ListWorkloads` exposed the currently active catalog, including AWS Solutions, Remote Desktop Gateway, SAP, SQL Server, and Microsoft Active Directory. `GetWorkloadDeploymentPattern` returned every accepted specification name and description. The RDGW existing-VPC pattern included network IDs, AMI, key pair, allowed CIDR, administrator username/password, domain name, host count, instance type, rollback, and notification settings.

### Dry run and dependency validation

`CreateDeployment --dry-run` returned `deploymentId: "Dry run is successful"` and created no deployment. CloudTrail still recorded it as `readOnly: false`, with the specification map replaced by `***`.

A role allowing only `launchwizard:CreateDeployment` on `arn:aws:launchwizard:us-east-1:228478051196:deployment/*` did not gain implicit downstream privileges. A tagged request first required the dependent `launchwizard:TagResource`. An untagged request was then rejected because it lacked `resource-groups:DeleteGroup`. No deployment, group, or parameter was retained. This negative result excludes `CreateDeployment` as a standalone generic privilege-escalation primitive.

### Deployment read oracle

An administrator created one intentionally invalid RDGW deployment using nonexistent VPC, subnet, AMI, and key-pair identifiers. Before any compute could launch, the workflow created a Resource Group and SecureString setup material.

`GetDeployment` returned the saved specification map. `AdminPassword` was masked as `******`; the administrator username, domain, VPC/subnet/AMI/key-pair identifiers, CIDR, host count, and instance type were returned literally.

A least-privilege role with only `launchwizard:GetDeployment` on the exact deployment ARN returned that same data while `ListDeployments` was denied. Thus a known deployment ID/ARN removes the need for list permission, but this probe did not demonstrate password disclosure.

The Service Authorization Reference and live behavior support deployment ARN scoping for `GetDeployment`. `ListDeploymentEvents` has no resource type and therefore requires `Resource: "*"`; its event data contains stage names, status reasons, and timestamps.

### Mutation and deletion

`UpdateDeployment` accepts a complete replacement specification map and supports dry-run. Depending on the workload pattern, the fields include security-sensitive CIDRs, machine images, keys, credentials, domains, and notification settings. This is direct workload control, but not a generic permission bypass: the selected workflow validates additional permissions.

`DeleteDeployment` moved the test deployment through `DELETE_INITIATING` to `DELETED`. It removed the Resource Group and SecureString setup material. Launch Wizard retains a non-operational `DELETED` tombstone in `ListDeployments`; the public API exposes no harder-delete action.
