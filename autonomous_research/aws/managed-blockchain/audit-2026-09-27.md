## Live results

### Inventory

- `us-east-1`: no account-created networks, Fabric invitations, or Ethereum nodes; the service-defined `n-ethereum-mainnet` network returned `AVAILABLE`.
- `eu-west-1`: no account-created networks or accessors.
- Some sampled Regions had no Managed Blockchain endpoint; organization SCPs explicitly denied others.
- The account initially had no accessors.

### Accessor minimum-permission checks

1. A temporary role allowed only `managedblockchain:CreateAccessor` on `*`.
2. It created a `POLYGON_MAINNET` `BILLING_TOKEN` accessor and received a 42-character token in the creation response.
3. The same session was denied `GetAccessor`, confirming there was no implicit read permission.
4. A separate role allowed only `managedblockchain:GetAccessor` on one exact accessor ARN. It retrieved the 42-character token and was denied `ListAccessors`.
5. The test was independently repeated with a second accessor.
6. Both accessors were deleted. Each changed to `PENDING_DELETION` and a harmless `eth_blockNumber` request returned HTTP `403` with an invalid-token response, confirming immediate revocation.

AWS documents that an accessor in `PENDING_DELETION` rejects new HTTP/WebSocket requests; a WebSocket opened before deletion can remain until expiry for up to two hours. The API has no force-delete/purge operation, and AWS states revoked tombstones disappear from `ListAccessors` within 48 hours.

### AMB Query minimum-permission check

1. A temporary role allowed only `managedblockchain-query:GetTokenBalance` with `Resource: "*"`.
2. `GetTokenBalance` for a public Ethereum address succeeded.
3. `ListTransactions` was denied, proving action separation.
4. An unsigned `GetTokenBalance` failed with `MissingAuthenticationTokenException`.
5. The role and inline policy were deleted.

AMB Query exposes public blockchain data. It supports no resource-level permissions or service-specific condition keys, so every allowed query action is account/Region-wide (`Resource: "*"`).

### CloudTrail checks

- Successful list/get/create/delete control-plane calls appeared as management events under `managedblockchain.amazonaws.com`.
- Reads were `readOnly:true`; writes were `readOnly:false`.
- An explicit `LookupEvents` read was itself present as a CloudTrail management event.
- AMB Query did not appear in the ordinary Event History sample. Current AWS documentation/EventBridge reference should be used when designing explicit collection.
- Public-chain JSON-RPC calls require explicit Managed Blockchain data-event selectors; management-event history alone is insufficient.

One unexpected security issue was reproduced twice and moved to a private report under `/home/tester/cloud_bb/aws`; details are intentionally withheld pending AWS review.

## Strong expected techniques promoted

### Enumeration

- Enumerate Fabric networks, members, proposals, votes, invitations, CA endpoints, peer endpoints and logging state.
- Enumerate dedicated Ethereum nodes on the fixed `n-ethereum-mainnet` network even when `ListNetworks` shows no account-created network.
- Treat accessor objects as credentials: list IDs, then retrieve tokens only under strict authorization.
- Enumerate AMB Query actions separately under the `managedblockchain-query` prefix.

### Post-exploitation

1. **Accessor credential recovery:** exact-ARN `GetAccessor` returns a reusable bearer token; `ListAccessors` is needed only to discover IDs.
2. **Fabric log suppression:** `UpdateMember` and `UpdateNode` can disable CA, peer and chaincode CloudWatch logging.
3. **Destruction:** delete owned nodes/members, reject invitations, and recognize that deleting the last member deletes the network.
4. **Governance manipulation:** create and vote on invitation/removal proposals, constrained by the immutable voting threshold.

### Privilege escalation and cross-account persistence

- A compromised member with sufficient governance influence can invite an attacker-controlled AWS account. That account can accept the approved invitation, choose its bootstrap administrator credentials, create a member/peer and become an independent consortium participant.
- This is service/network privilege escalation and cross-account persistence, not generic AWS administrator access. It fails when the attacker cannot satisfy the network's voting policy.

### Persistence

1. **Mint an accessor token:** `CreateAccessor` alone returns a bearer credential that outlives the creator's AWS session until deletion. Scope is AMB service/account access, not general AWS-account persistence.
2. **External consortium member:** an approved and accepted invitation creates an independently owned network member that survives remediation of the originally compromised victim identity.

### Unauthenticated capability use

- A leaked `BILLING_TOKEN` can replace SigV4 for compatible Ethereum/Polygon calls. The token is the credential; account IDs, ARNs and node IDs alone are insufficient.
- The capability authorizes AMB requests/billing but does not expose wallet private keys. Public-chain writes require an already signed raw transaction.

## Ideas investigated but not promoted

| Idea | Disposition | Reason |
| --- | --- | --- |
| AMB Query as sensitive-data theft | Not promoted as an attack | It returns public-chain data. Cost abuse/address intelligence are real but weak compared with accessor credential compromise. |
| Identifier-only unsigned native API enumeration | Rejected | Native control-plane and Query APIs require SigV4; no public-by-account-ID path was found. |
| Directly delete another account's Fabric member | Rejected | `DeleteMember` is limited to a member owned by the caller's account; cross-account removal requires an approved proposal. |
| Proposal creation alone immediately changes membership | Rejected | The submitting member must vote and the network threshold/comparator must be satisfied. |
| Accessor token as wallet compromise | Rejected | AMB does not store wallet private keys and accepts only raw signed public-chain transactions for state changes. |
| CA endpoint alone as Fabric takeover | Rejected | Enrollment still requires bootstrap/admin credentials and the required private network path. |
| Create nodes/network for live authorization tests | Deferred | Billable and provisioning lifecycle was unnecessary to establish documented IAM/governance boundaries. |
| Disable CloudWatch logs as total anti-forensics | Narrowed | The mutation remains a CloudTrail management event and peer metrics are separate; only optional CA/peer/chaincode log delivery is suppressed. |
| Tags as durable access-control bypass | Rejected | AMB supports ABAC on tagged resources; no cross-account/resource-policy primitive or tag authorization defect was found. |
