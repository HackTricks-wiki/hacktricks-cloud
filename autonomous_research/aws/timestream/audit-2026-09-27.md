Resource types and exact ARN forms:

```text
database        arn:aws:timestream:REGION:ACCOUNT:database/DB
table           arn:aws:timestream:REGION:ACCOUNT:database/DB/table/TABLE
scheduled-query arn:aws:timestream:REGION:ACCOUNT:scheduled-query/GENERATED_NAME
```

Key authorization conclusions:

- `Query` maps to conditional IAM actions including `Select` on every table accessed, plus metadata actions where used. Table-free SQL uses `SelectValues` on `*`.
- `Unload`, `Select` and `WriteRecords` support exact table ARNs.
- `CreateScheduledQuery` supports no resource-level ARN and has dependent `iam:PassRole`; tag-on-create adds `TagResource`.
- `UpdateAccountSettings` also lists `iam:PassRole` as a dependent action for provisioned-query-compute notifications, but the passed role is restricted to the notification workflow and did not produce a useful general privilege-escalation technique.
- `UpdateScheduledQuery` accepts only `ScheduledQueryArn` and `State`. It cannot repoint the role, change SQL, target, SNS, S3 or KMS settings.
- LiveAnalytics has no resource-based policies or service-linked role. Scheduled queries nevertheless use a caller-supplied execution role trusted by `timestream.amazonaws.com`.
- Normal CLI/SDK calls use `DescribeEndpoints` on `*`. AWS documents that `DescribeEndpoints` and `WriteRecords` generate no CloudTrail events.

The installed AWS CLI `2.34.45` did not yet expose the new backup commands even though the current official Service Authorization Reference does. Public documentation follows the current official surface, not the locally lagging client.

Resource types:

```text
db-backup          arn:aws:timestream-influxdb:REGION:ACCOUNT:db-backup/ID
db-cluster         arn:aws:timestream-influxdb:REGION:ACCOUNT:db-cluster/ID
db-instance        arn:aws:timestream-influxdb:REGION:ACCOUNT:db-instance/ID
db-parameter-group arn:aws:timestream-influxdb:REGION:ACCOUNT:db-parameter-group/ID
```

Key conclusions:

- No resource-based policies. Cross-account control-plane access requires assuming a role in the owning account.
- `GetDbInstance` exposes endpoint/network configuration and `influxAuthParametersSecretArn`; the newer `GetDbBackup` response also exposes the auth-secret ARN captured for the backed-up resource.
- The automatically created Secrets Manager value is a read-only copy of the initial organization, bucket, username and password. Editing/deleting the secret does not change the engine credential.
- Initial username/password can obtain an operator token, after which native InfluxDB tokens can be created. These tokens are independent of AWS IAM.
- `UpdateDbInstance` can change log delivery, parameter group, port, instance/storage/deployment settings and maintenance schedule. It does not accept username/password, public-access or security-group changes.
- InfluxDB supports a public endpoint option, but the native plane still requires username/password or token authentication.
- AWS CloudTrail covers InfluxDB control-plane DDL/API calls, not native database query/write/token operations.

### Request-shape validation

AWS CLI `--generate-cli-skeleton input` confirmed:

- `CreateScheduledQuery` requires name, SQL, schedule, SNS configuration, execution role and S3 error-report configuration; target configuration is optional; KMS key and tags are optional.
- `UpdateScheduledQuery` has exactly `ScheduledQueryArn` and `State`.
- `ExecuteScheduledQuery` has scheduled-query ARN and invocation time, plus optional query-insights mode.
- `CreateDbInstance` / `CreateDbCluster` accept initial username/password/org/bucket, VPC subnets/security groups and `publiclyAccessible`.
- `UpdateDbInstance` has no field to reset password or change public accessibility/security groups.

## Hypothesis matrix

| Hypothesis | Status | Value / evidence | Publication decision |
| --- | --- | --- | --- |
| Known-table query needs only `Select` plus endpoint discovery | High-confidence expected behavior | IAM docs distinguish `Select` from metadata actions and scope it to table ARN | Published as post-exploitation |
| `UNLOAD` can bulk-export results to same-Region S3 | High-confidence expected behavior | Official syntax, prerequisites and output manifest/metadata docs | Published as post-exploitation |
| `WriteRecords` can inject and higher-version-upsert without read access | High-confidence expected behavior | Official upsert semantics and exact table resource support | Published as post-exploitation |
| Highest signed 64-bit version pins an individual record against later upserts | High-confidence inference from documented 64-bit `Version` and strict greater-than rule | No higher valid long exists; requires exact record identity | Published with caveat; not treated as AWS defect |
| `WriteRecords` is CloudTrail-invisible | Confirmed current documented behavior | Explicit AWS CloudTrail warning | Published; high-stealth distinction |
| Create scheduled query + PassRole can use role source/target/S3/SNS permissions | High-confidence expected behavior | API and SAR explicitly identify assumed role and dependent PassRole | Published as privesc |
| Rejected scheduled-query rows can disclose source values to S3 | High-confidence composition | AWS error format includes complete rejected records or raw lines; requires role permission to chosen bucket | Published with precise prerequisite, not claimed as defect |
| `UpdateScheduledQuery` can repoint execution role | Rejected | API accepts only state | Explicit negative in privesc/persistence |
| `ExecuteScheduledQuery` alone reuses stored role | High-confidence expected behavior | Execute API has no role/PassRole input and uses existing resource | Published as constrained privesc/workflow invocation |
| Recurring scheduled query persists after creator revocation | High-confidence expected behavior | Service stores schedule and assumes execution role on each run | Published as service-level persistence |
| `GetDbInstance` + secret read yields initial Influx admin credential | High-confidence expected behavior | AWS documents exact secret ARN and contents | Published as post-exploitation |
| `GetDbBackup` + secret read is an alternate credential-discovery path | High-confidence expected behavior | Current official response includes `influxAuthParametersSecretArn`; useful only while that secret exists | Published in enum/post-exploitation |
| Editing/deleting the generated secret rotates engine password | Rejected | AWS explicitly says secret is a read-only copy and engine is unaffected | Defensive warning published |
| Native Influx token survives AWS IAM revocation | High-confidence expected behavior | Native token plane is separate from IAM; official docs show token creation | Published as service-level persistence |
| Direct cross-account resource policy on Timestream resources | Rejected | Both IAM integration pages state resource-based policies unsupported | Negative documented in enum |
| Account-ID-only or unsigned control-plane enumeration | Rejected | SigV4 required; no public resource policy surface | Negative documented in enum; existing native-endpoint page retained |
| Known public InfluxDB v2 endpoint health/version oracle | Expected native behavior | `/health` and `/ping` do not require a token; data APIs still authenticate | Existing unauthenticated page corrected and linked |
| Publicly accessible Influx endpoint is unauthenticated | Rejected | Public controls routing only; native password/token still required | Negative documented in enum |
| Batch load adds a distinct high-value attack | Excluded as redundant | Bulk S3-to-table ingestion requires `CreateBatchLoadTask` + `WriteRecords` and same-account/same-Region S3; direct `WriteRecords` already covers data poisoning more simply | Ledger only |
| Repoint magnetic-store rejected-data S3 with `UpdateTable` exfiltrates normal writes | Excluded | Only asynchronous lower/equal-version magnetic-store rejections are reported, and writers also need destination `s3:PutObject`; not a general table exfil path | Ledger only |
| Shorten retention with `UpdateTable` | Expected but not published | Destructive and logged, but obvious configuration tampering with lower incremental value than delete/write techniques | Ledger only |
| Pass role through `UpdateAccountSettings` | Excluded | Role is for provisioned query-compute notifications; no useful arbitrary role execution or sensitive result sink identified | Ledger only |
| Tags/ABAC manipulation | Excluded | Generic tag-based authorization concern, not Timestream-specific or independently high value | Ledger only |
| Influx backup/restore for exfil or credential cloning | Not promoted | New APIs inventoried; no instance to test and current docs do not establish that restored copies preserve a readable admin credential or cross-account destination | Revisit when a safe existing fixture is available |
