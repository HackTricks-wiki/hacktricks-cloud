# Amazon Managed Grafana attack-surface audit — 2026-09-26

## Scope and live evidence

- Reviewed workspace control/data planes, IAM resources, authentication, Identity Center grants, bearer credentials, data-source roles, network controls, cross-account access, and CloudTrail.
- Authorized account `228478051196`, `us-east-1`, explicit JSON/Region variables. Initial/final `ListWorkspaces`: zero, so no paid workspace was created.
- A disposable IAM user received only `CreateWorkspaceApiKey`, `CreateWorkspaceServiceAccount`, `CreateWorkspaceServiceAccountToken`, `UpdatePermissions`, and `UpdateWorkspaceAuthentication` on exact nonexistent ARN `arn:aws:grafana:us-east-1:228478051196:/workspaces/g-0000000000`.
- Every corresponding API reached `ResourceNotFoundException`, not `AccessDeniedException`, confirming exact-workspace authorization without list/describe prerequisites. The user/policy/key were deleted and final matching-user inventory was zero.
- Plaintext response, role, TTL, version, SAML, and workspace-role behavior comes from current official API/user guides; no token was minted.

## Technique decisions

| Candidate | Result and boundary | Decision |
| --- | --- | --- |
| Legacy chosen-role API key | Exact workspace action; max 30 days; being phased out | Retain with warning |
| Token for existing service account | One exact action and known ID; inherits role | Retain |
| Create `ADMIN` service account + token | Two exact actions; Grafana 9+ | Add to token technique |
| `UpdateWorkspace` + PassRole | Changes service-mediated data-source role; needs useful data source/admin access; no direct credentials | Add bounded privesc |
| `UpdatePermissions` | Adds Identity Center user/group as workspace admin | Add workspace persistence |
| `UpdateWorkspaceAuthentication` | Attacker SAML metadata and admin mapping | Add auth persistence |

## Rejected/bounded ideas

- Token lists expose metadata, not plaintext bearer values; describe APIs expose no existing token, SAML private key, or IAM credentials.
- Removing network access controls broadens reachability but leaves Grafana authentication intact; it is only a composition step.
- `UpdateWorkspaceConfiguration` changes supported Grafana settings but no independent cloud escalation was established.
- License association affects Enterprise licensing, not access. Destructive delete/revoke actions are ordinary DoS.
- Cross-account AWS data access uses the same-account workspace role and its permitted `sts:AssumeRole` into a target role; no direct cross-account workspace ownership path was found.
- SAML metadata URL fetching is expected outbound configuration; no useful private-network SSRF oracle or AWS credential exposure was demonstrated.

## Telemetry, cleanup, and future work

Control-plane calls are default management events. Managed Grafana also logs selected sign-in and state-changing workspace HTTP API calls, but documentation does not promise comprehensive reads. `iam:PassRole` has no standalone event; inspect `workspaceRoleArn` and downstream role calls.

Only the disposable IAM user/policy/key was created and all were removed. No paid infrastructure or private vulnerability report exists.

Future tests: sanctioned workspace token-response/CloudTrail redaction; read-versus-write HTTP API coverage across versions; active-session behavior after workspace-role swaps; and SAML XML signature/canonicalization, multi-value claim, and metadata-refresh edge cases.
