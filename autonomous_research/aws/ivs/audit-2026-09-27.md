# Amazon IVS security audit — 2026-09-27

## Scope and safety

- Services: Amazon IVS low-latency streaming and IVS real-time streaming. IVS Chat was excluded except for architectural awareness.
- Region: `us-east-1`.
- Authorized profile/role: `hacktricks-training` assuming `arn:aws:iam::228478051196:role/ChackBotAdministratorRole`.
- Minimum-permission behavior was tested with inline STS session policies. No IAM users, policies or access keys were created.
- Media tests used only generated 640x360 color bars and a tone, for at most 22 seconds.
- One server-side composition was started against disposable resources and immediately stopped by the cleanup trap. There were no long-running streams, reservations, paid commitments or network resources.
- Every test had a cleanup trap; final inventory is recorded below.

## Documentation baseline

The repository had no IVS enumeration, privilege-escalation, post-exploitation, persistence or unauthenticated-access page before this audit.

## Attack-surface inventory

### Low-latency streaming

- Channels expose public/private playback state, ingest and playback endpoints, SRT configuration, recording/restriction/ad configuration associations and tags.
- Stream keys are long-lived media-plane bearer credentials.
- Stream/session APIs expose active state and historical health/lifecycle/recording information.
- Imported playback key pairs establish trust for customer-signed private-playback JWTs.
- Recording configurations select S3 buckets through the `AWSServiceRoleForIVSRecordToS3` service-linked role.
- `PutMetadata`, `InsertAdBreak`, `StopStream` and viewer-session revocation alter live behavior.

### Real-time streaming

- Stages expose WHIP, event and RTMP(S) endpoints.
- Participant tokens provide PUBLISH/SUBSCRIBE capabilities for up to 20,160 minutes.
- RTMP(S) ingest configurations contain reusable stream keys and optional redundant credentials.
- Imported public keys trust customer-signed participant/connection JWTs and do not automatically expire.
- Stage sessions/participants/events disclose operational and application-provided metadata.
- Storage configurations modify S3 bucket policy for recording.
- Server-side compositions output a stage to low-latency channels or S3.

## Live results

### 1. Exact `GetStreamKey` returns a full publishing bearer — confirmed

A session whose only allow was `ivs:GetStreamKey` on one exact stream-key ARN recovered the same 56-character value returned during channel creation. RTMP(S) accepted that value without AWS credentials and brought a synthetic stream to `LIVE`.

Disposition: strong expected privilege-escalation/post-exploitation technique. The IAM access-level label `Read` understates the resulting media-plane authority.

### 2. `CreateStreamKey` does not require channel permission — confirmed

After an administrator deleted a disposable channel's initial key, a session with only:

```json
{
  "Effect": "Allow",
  "Action": "ivs:CreateStreamKey",
  "Resource": "arn:aws:ivs:us-east-1:228478051196:stream-key/*"
}
```

created a new key for the otherwise unauthorized channel and received a 56-character value. No channel ARN appeared in the session policy.

Important constraint: channels normally have an initial stream key and creation needs key quota available. Rotating a full channel requires permission to identify/delete the existing key.

Disposition: strong expected privilege escalation, consistent with the service authorization table where `Stream-Key*` is the required resource and channel is not listed for this action. Not a zero-day.

### 3. Private/public playback and live mutation behavior — confirmed

- A generated stream made a BASIC channel `LIVE`.
- Anonymous fetch of its playback URL returned HTTP 403 while the channel was authorized.
- An independently created public channel returned HTTP 200 for the same unsigned/no-token playlist request while live.
- `PutMetadata` on the exact live channel accepted a synthetic JSON marker.
- `UpdateChannel --no-authorized` is accepted while offline, but AWS returned `ConflictException` when attempted during a live stream.

Disposition: document public playback, persistent offline authorization downgrade and metadata manipulation. The opaque playback URL is not enumerable from only an account ID.

### 4. Exact `CreateParticipantToken` mints a 14-day bearer — confirmed

A session restricted to `ivs:CreateParticipantToken` on one exact stage minted a 652-character opaque token with `PUBLISH` and `SUBSCRIBE`, duration 20,160 minutes.

Disposition: strong expected delegation/privesc technique. Treat this permission as equivalent to issuing stage media access.

### 5. Real-time ingest-key disclosure and rebind authorization — confirmed

- Creating an RTMPS ingest configuration returned a 69-character stream key.
- `GetIngestConfiguration` on the exact ARN returned the complete matching key.
- A policy containing `CreateIngestConfiguration` only on `ingest-configuration/*` was denied on the referenced stage. Adding the exact stage allowed creation.
- `UpdateIngestConfiguration` only on the ingest ARN was denied when moving it to a second stage. Adding the destination stage allowed the rebind.
- The stream-key value remained unchanged after the authorized rebind.

Disposition: document secret disclosure and persistent key reuse. Record the stage authorization dependency so the book does not claim a destination-stage bypass. The observed create denial fills a nuance absent from a simplistic reading of the service authorization row.

### 6. Imported real-time public key is account/Region token trust — confirmed/authoritative

A session restricted to `ivs:ImportPublicKey` on prospective `public-key/*` imported an attacker-generated P-384 public key. AWS documents that the retained private key can sign participant and connection JWTs; participant JWTs name any stage in the account/Region and can last up to 14 days. Imported IVS public keys have no expiry.

Disposition: high-value expected privilege escalation and persistence. No live client join was necessary to restate the documented JWT trust workflow.

### 7. Imported playback key is private-playback trust — confirmed/authoritative

A session restricted to `ivs:ImportPlaybackKeyPair` on prospective `playback-key/*` imported the same controlled public key. AWS documents using its private counterpart to sign `ES384` playback JWTs naming private channel ARNs.

Disposition: high-value expected content-access escalation and persistence. It bypasses the application token-issuance decision, not IVS token verification.

### 8. `StartComposition` destination channel is not required in IAM policy — confirmed

Disposable stage, encoder and low-latency channel resources were created. A session allowed `ivs:StartComposition` only on the stage and encoder ARNs. The request named the otherwise unauthorized channel as destination and succeeded, returning a composition in `STARTING` state. CloudTrail captured the complete stage/encoder/channel mapping.

The attempted RTMP publisher did not become active during the short observation window, so this audit did not claim visual confirmation at the channel. AWS's server-side-composition documentation defines the accepted channel destination as the output, and the authorization result itself is conclusive for the control-plane boundary.

Disposition: strong expected privilege escalation: composition authority over a stage/encoder can originate stage media on a channel without that channel's stream key or channel permission. The current service authorization reference lists the channel resource as optional and stage/encoder as required. Not a zero-day.

### 9. Recording/storage attachment does not authorize the destination — confirmed

- An administrator created an ACTIVE low-latency recording configuration and S3 bucket. A session with only `ivs:UpdateChannel` on the exact channel attached that recording configuration without permission on the configuration or bucket.
- An administrator created a real-time storage configuration and bucket. A session with only `ivs:UpdateStage` on the exact stage enabled automatic participant recording to it without permission on the storage configuration or bucket.

Disposition: strong expected recording-redirection/persistence technique when the attacker can reference an existing destination they can read. Attachment alone does not grant S3 read.

### 10. Destination creation has external authorization dependencies — confirmed negatives

- Real-time `CreateStorageConfiguration` using only the documented IVS action was denied on the target bucket, even with the prospective storage-config ARN or wildcard resource. The operation modifies bucket policy and needs the documented S3 bucket-policy authority.
- Low-latency `CreateRecordingConfiguration` succeeded as administrator and automatically established `AWSServiceRoleForIVSRecordToS3`. Attempts under a session explicitly denying IAM/S3 failed validation, including after a bootstrap configuration existed. AWS documents the service-linked-role creation/update permissions.

Disposition: do not publish a false IVS-to-S3 write escalation based on only the named IVS create action.

## CloudTrail and detection results

Observed management events:

- `GetStreamKey` recorded the requested ARN with `responseElements: null`.
- `CreateParticipantToken` recorded stage, TTL, capabilities and user ID; the token was `***`.
- `ImportPublicKey` recorded the public PEM/fingerprint. `ImportPlaybackKeyPair` recorded the public material/fingerprint. These values are public, while private keys never reached AWS.
- `UpdateChannel` recorded authorization/recording changes and the updated channel; the SRT passphrase was `***`.
- `UpdateStage` recorded both the stage and storage-configuration resources when attaching storage.
- `StartComposition` recorded the source stage and the complete destination channel/encoder topology.
- `PutMetadata` and `GetStreamSession` appeared after normal Event History propagation.

Media-plane observations:

- RTMP(S) ingest and unsigned playlist requests did not create one CloudTrail event per packet/segment/request.
- Low-latency EventBridge supplies best-effort session/stream/takeover/recording events.
- Real-time EventBridge supplies participant, recording and composition changes.
- `AWS/IVS` CloudWatch metrics cover ingest bitrate/frame rate, views and other health/activity signals.

## Cross-account and unauthenticated conclusions

- IVS provides no channel/stage resource-policy management API. Cross-account AWS API operation normally requires assuming a role in the owning account.
- Stream keys, ingest keys, participant tokens and signed playback URLs/JWTs are intentional non-SigV4 bearer capabilities and can cross account/network boundaries.
- A public live playback URL is anonymously usable but contains opaque values; an account ID is insufficient to derive it.
- A private live playback URL without a token returned HTTP 403 in the live test.
- Recording S3 objects obey S3 authorization. Knowing the IVS configuration/bucket name is not an object-read bypass.

## Cleanup verification

Each run used a trap that stopped FFmpeg/compositions and deleted the exact channel, key/config parent, stage, ingest configuration, encoder, recording/storage configuration, bucket policy and S3 bucket as applicable. IVS briefly rejected deletion of two channels while their encoders were winding down; the final audit found those two exact ARNs, called `StopStream`, waited for the offline transition and deleted them explicitly.

Final `us-east-1` inventory for the test prefix:

```text
IVS channels ht-ivs-*                    []
IVS recording configurations ht-ivs-*   []
IVS playback key pairs ht-ivs-*          []
IVS stages ht-ivs-*                      []
IVS ingest configurations ht-ivs-*       []
IVS encoder configurations ht-ivs-*      []
IVS storage configurations ht-ivs-*      []
IVS public keys ht-ivs-*                  []
S3 buckets ht-ivs-*                       []
FFmpeg test processes                     []
Test composition                          STOPPED (StopComposition succeeded; ephemeral tombstone pending service cleanup)
```

Composition resources have no delete API separate from `StopComposition`. The test composition entered `STOPPED` at `2026-09-26T23:42:31Z`; AWS documents automatic cleanup of this ephemeral final-state record. The low-latency recording service-linked role disappeared after its final recording configuration was deleted. No active or billable fixture remained.

## Zero-day assessment

No unexpected AWS security vulnerability was confirmed. The strongest authorization edges (`CreateStreamKey` and destination-channel omission for `StartComposition`) match the published service authorization resource model. Secret-bearing reads, account/Region signing trust and recording association behavior are intended features. No private bug-bounty report was created.
