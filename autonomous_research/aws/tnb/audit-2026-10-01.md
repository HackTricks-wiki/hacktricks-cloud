# AWS Telco Network Builder retirement audit — 2026-10-01

## Decision

Do not add AWS Telco Network Builder (TNB) attack pages to HackTricks. The service is retired in practice: a September 23, 2026 signed control-plane sweep received the service-generated response `AWS Telco Network Builder is deprecated. All API operations are blocked.` for every tested write, and on October 1 the documented regional API hostnames no longer resolved. The current AWS documentation, CLI model, Service Authorization Reference and Service Quotas entries remain published, but they describe an inaccessible control plane.

This closes TNB as a current missing-service lead. No AWS vulnerability was found and no private report was created.

## Historical attack surface

The current CLI `tnb` model still exposes 33 operations over function packages, network packages, network instances and network lifecycle operations. The historically important chain was:

1. `CreateSolNetworkPackage` created an empty package container.
2. `PutSolNetworkPackageContent` uploaded a caller-controlled CSAR/NSD ZIP, including optional scripts.
3. `CreateSolNetworkInstance` associated the onboarded descriptor with a network instance.
4. `InstantiateSolNetworkInstance` provisioned the described infrastructure and ran lifecycle tasks.
5. `UpdateSolNetworkInstance` could move an existing deployment to a different network package, while `TerminateSolNetworkInstance` and `CancelSolNetworkOperation` could disrupt it.

The NSD schema made this a material delegated-code-execution surface. An `AWS.HookDefinition.Bash` node names a bundled `./hooks/<script>.sh` and a required `execution_role`; an `AWS.HookExecution` node runs it through CodeBuild during infrastructure/network instantiation. AWS's own IAM example creates a CodeBuild-trusted `TNBHookRole` with `AdministratorAccess`, while warning customers to scope the hook policy to the script's needs. If a live deployment exposed package/instance lifecycle writes and a passable privileged hook role, attacker-controlled package content could therefore have executed as that role. EKS managed/self-managed node `user_data`, Helm/function packages and the broad TNB provisioning role were additional code and delegation boundaries.

AWS's IAM troubleshooting guide says callers must receive `iam:PassRole` when a TNB action passes a role, but the Service Authorization Reference currently lists no dependent actions for TNB and the API requests do not carry the hook role directly—it is embedded in package content. Because all APIs are now blocked, the exact operation and resource on which hook-role `iam:PassRole` was enforced could not be established. Do not publish a minimum-permission escalation chain that guesses this boundary.

Other historical candidates included:

| Candidate | Historical impact | Current disposition |
| --- | --- | --- |
| `GetSolFunctionPackageContent` / `GetSolNetworkPackageContent` | Recover Helm charts, scripts, topology and deployment configuration | Inaccessible; do not publish |
| Replace or create package content, then instantiate/update | Code execution under hook/node roles and infrastructure creation under the TNB provisioning role | Strong historical expected-functionality lead, but unusable now and exact PassRole gate cannot be retested |
| `TerminateSolNetworkInstance` / `CancelSolNetworkOperation` | Tear down or interrupt managed telco infrastructure | Obvious destructive write with no current target API |
| `UpdateSolNetworkPackage` / `UpdateSolFunctionPackage` | Disable packages and block future lifecycle operations | Low incremental value and no current target API |
| Cross-account resource policy | TNB did not support resource-based policies | No path |
| Unauthenticated enumeration | API required SigV4 while available | No path |

## Retirement evidence

CloudTrail Event History in account `228478051196`, Region `us-east-1`, contained five September 23 requests from the earlier `ht-audit-sweep-tnb` research role:

```text
UpdateSolNetworkInstance
UpdateSolNetworkPackage
PutSolFunctionPackageContent
PutSolNetworkPackageContent
UpdateSolFunctionPackage
```

Every event had `eventSource=tnb.amazonaws.com`, `errorCode=AccessDenied`, and this service response in `responseElements.message`:

```text
AWS Telco Network Builder is deprecated. All API operations are blocked.
```

The package uploads additionally recorded `error: Request body is invalid.` in `requestParameters`, but the terminal service response was the same retirement block. On October 1, `tnb.us-east-1.amazonaws.com` returned no DNS answer; signed list calls also failed to connect in `us-east-1`, `us-west-2`, `eu-central-1` and `ap-southeast-2`. This is stronger evidence than the still-live documentation and SDK artifacts.

Stale public surfaces observed after retirement:

- the API Reference was republished on September 25, 2026;
- the User Guide still lists ten regional endpoints and describes instantiation;
- the machine-readable Service Authorization Reference still lists every IAM action/resource; and
- Service Quotas still returns four TNB quotas for the account.

These artifacts must not be treated as proof that the service is operational.

## Telemetry and stealth (historical)

TNB control-plane requests were CloudTrail management events under `tnb.amazonaws.com`. Package creation/upload, instance creation, instantiation, update, termination and cancellation would all have been low-stealth control-plane writes. Successful instantiation also produced correlated CloudFormation, CodeBuild, EKS, EC2, S3, EventBridge, SSM and IAM activity under the supplied service roles. Hook execution was therefore not meaningfully stealthy even though downstream calls were attributed to role sessions rather than directly to the initiating principal.

The retirement response itself is retained in the CloudTrail event's `responseElements.message`; `errorMessage` was null in the observed events.

## Revisit condition

Only reconsider TNB if AWS restores a resolvable endpoint and at least one signed read succeeds. If that happens, first use a disposable empty package and `ValidateSolNetworkPackageContent` / `InstantiateSolNetworkInstance --dry-run` to identify exactly where `iam:PassRole` is evaluated. Do not instantiate EKS, EC2, NAT gateways or CodeBuild infrastructure until the role and cleanup semantics are proven with the non-mutating paths.

## Cleanup

This pass made only IAM inventory, Service Quotas, CloudTrail-history, documentation, DNS and connection checks. It created no TNB package, function, instance or operation and no IAM role, CodeBuild project, CloudFormation stack, EKS/EC2/network, S3 object, EventBridge rule or SSM parameter. There was nothing to delete. The account contained no IAM role whose name included `TNB` or `tnb`.
