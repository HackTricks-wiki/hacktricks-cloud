## Service and trust model established

AWS documentation establishes these boundaries:

1. Applications are copied from S3 when `CreateApplication` runs. The source is not synchronized later.
2. Stream groups associate applications, stream classes, locations, capacity, and optional VPC transit configuration.
3. Stream-session objects return environment variables, launch arguments, signaling data, user IDs, role ARNs, and S3 output metadata.
4. `StartStreamSession` can pass a `GameLiftStreams-*` role. GameLift Streams assumes it and makes rotating credentials available through normal SDK providers inside the application.
5. `CreateStreamSessionAdminShell` grants terminal access with the same access as the application.
6. `CreateStreamUrl` creates an unauthenticated browser capability. Maximum documented URL lifetime is 1,440 minutes and maximum usage is 50 starts.
7. `ListStreamUrls` is `Resource: "*"` and returns the actual bearer URL.
8. GameLift Streams has no service resource policies and no normal cross-account API access.
9. Applications and stream groups are IAM resource types. Stream sessions and stream URLs are authorized through a parent stream group (and, for creation, application where documented), not standalone IAM resource types.
10. Application/group control-plane calls are CloudTrail management events. Session, export, admin-shell, and URL operations are data events, disabled by default. End-user URL activation is explicitly not a customer CloudTrail API call.

## Local tooling observation

The installed AWS CLI is `2.34.45`. Its bundled GameLift Streams model includes the original application/group/session APIs but not the newer:

- `CreateStreamSessionAdminShell`
- `CreateStreamUrl`, `GetStreamUrl`, `ListStreamUrls`, `RevokeStreamUrl`
- `ListApplicationShaderCaches`

The current official CLI `2.37.x` and service authorization/API references include these actions. Book syntax for them follows the current official model. The local model gap is a client-version issue, not a service security issue.

## Promoted expected techniques

| Technique | Why it is useful | Evidence basis |
| --- | --- | --- |
| `ListStreamUrls` / `GetStreamUrl` bearer recovery | Account-wide list returns live shareable URLs; get returns plaintext args/env, role and sessions | Current IAM, API and CLI references |
| `GetStreamSession` configuration disclosure | Returns plaintext args/env, WebRTC offer/answer, user, role and S3 metadata | `GetStreamSession` response schema |
| `CreateStreamSessionConnection` takeover | Reconnects `ACTIVE` or `PENDING_CLIENT_RECONNECTION` session while preserving state | API lifecycle documentation |
| `CreateStreamSessionAdminShell` runtime access | Full application-equivalent terminal, user/application data, VPC path, and session-role access | Admin-shell guide and API docs |
| `ExportStreamSessionFiles` collection | ZIP of modified application/profile/temp files and performance stats | API and developer guide |
| Admin shell to existing session role | Does not require attacker `iam:PassRole`; role is already attached to session | Admin-shell and session-credential guides |
| `StartStreamSession` + `iam:PassRole` | Controlled application uses the passed role's rotating credentials | Session-credential setup/use guides |
| Bearer stream URL persistence | Survives creator credential loss for up to 24 hours/50 starts | Stream URL guide and CLI constraints |
| Unauthenticated use of leaked URL | Browser starts sessions without AWS account/client integration | Stream URL API/developer guide |

All public techniques state exact impact, stealth, logs/detection, and the distinction between data events and default management-event coverage.

## Considered but not promoted

| Candidate | Decision | Reason |
| --- | --- | --- |
| Delete applications/groups or terminate sessions | Rejected | Straight availability impact; not a distinct high-value offensive primitive. |
| Raise always-on/target-idle/maximum capacity or add locations | Kept only as warning | Cost/availability abuse is real but generic and potentially expensive; never invoked. |
| Environment-variable or launch-argument RCE | Backlog | Variables reach the application, but reliable execution depends on its runtime/files/argument parser. Admin shell or controlled application is stronger and deterministic. |
| Change executable path with `UpdateApplication` | Rejected | Current application content/source and executable selection are effectively creation-time boundaries; no reliable arbitrary payload path was established. |
| Modify source S3 objects after import | Rejected | AWS explicitly states imported application files are copied once and not synchronized. |
| Shader-cache poisoning | Backlog | Public API exposes list metadata but no documented customer mutation primitive suitable for an attack. |
| Cross-account application API access | Rejected as expected unsupported | Service has no resource policies and documentation says API access is restricted to the owning account. |
| Application-log redirection to attacker account | Rejected | AWS documents strong same-account bucket ownership enforcement. Same-account log collection can matter but is weaker than session-file export/admin shell. |
| Blind application import as S3 exfiltration | Rejected | FAS uses caller S3 access, but GameLift Streams provides no direct download of imported content; useful recovery still needs valid executable/session capacity and stronger permissions. |
| Stream URL guessing/account-ID reconnaissance | Rejected | URL is a high-entropy bearer; end-user errors deliberately collapse failure causes and do not expose useful victim data from an account ID alone. |
| Service quota exhaustion | Rejected | Generic DoS/cost abuse rather than a novel security technique. |

## Defect / zero-day backlog

No item below is claimed as a vulnerability. They require an account without the SCP and controlled, low-cost fixtures.

1. **Parent/child authorization confusion:** use mismatched stream-group and session/URL identifiers, including same-account second groups and a second authorized account, across get, reconnect, admin-shell, export, terminate, and revoke.
2. **Role authorization matrix:** verify both `iam:PassRole` and `gameliftstreams:RoleArn` enforcement for `StartStreamSession` and `CreateStreamUrl`, including paths, wildcard roles, permission boundaries, session tags, and confused-deputy trust conditions.
3. **Existing-role shell boundary:** confirm admin shell never creates access to role credentials beyond the selected session/application and expires/revokes promptly on termination.
4. **Stream URL atomicity:** race parallel activation at usage limit one, expiration, `REVOKE_URL`, and `REVOKE_AND_TERMINATE_SESSIONS`; verify no extra session starts and revocation reaches every location.
5. **Bearer disclosure authorization:** test exact `ListStreamUrls`/`GetStreamUrl` behavior under tag policies, explicit resource denies, and application-only versus stream-group-only grants.
6. **Connection takeover isolation:** attempt replayed offers, duplicate client tokens, cross-session offers, and stale offers after state transitions.
7. **Export destination enforcement:** verify caller S3 authorization, same-account ownership, key overwrite behavior, KMS keys, bucket-owner-enforced mode, cross-account buckets, and URL-encoded/case-confused keys.
8. **Application import FAS:** test cross-account buckets, access points, aliases, KMS grants, requester-pays, version races, symlinks/path handling, and prefix/object boundary validation.
9. **VPC transit isolation:** attempt foreign/shared Transit Gateway and RAM configurations, overlapping CIDRs, route changes, stale shares, DNS confusion, and cross-account VPC identifiers.
10. **CloudTrail completeness/redaction:** verify every listed data API, correct `readOnly` classification, application+group resource attribution, and redaction of bearer URL, shell token, WebRTC offer/answer, environment variables, arguments, and role information.
11. **Admin-shell token handling:** test 60-second expiry, replay, simultaneous connections, use after session termination, and whether SSM customer-account permissions or logs incorrectly participate.
12. **Session-role credential containment:** confirm credentials are inaccessible from browser protocol or exported files unless application code writes them, and that refresh ends immediately with session termination.
13. **URL activation audit gap variants:** verify service metrics/session inventory always record successful starts even though no customer API event exists, and that failed starts cannot become a stealth capacity oracle.
14. **Tag TOCTOU:** race tag changes against stream URL, session, shell, and export authorization because child operations authorize against parent resources.

## Minimum-permission validation plan for a future account

Use two roles and two stream groups/applications where required:

1. Create one tiny application whose executable immediately exits and a stream group with minimum/target-idle zero and maximum one only after confirming price and deletion behavior.
2. Attach one minimally privileged `GameLiftStreams-*` role that can read a single canary object.
3. Test each action from a role containing exactly one GameLift Streams action plus dependencies; use explicit denies for neighboring actions.
4. Keep connection/session timeouts at the minimum and terminate immediately.
5. Enable application and stream-group CloudTrail data events before testing; record request/response redaction and resource attribution.
6. Trap cleanup: revoke URLs with session termination, terminate sessions, set capacity to zero, remove remote locations, delete stream group/application, delete test role/object/bucket, then inventory every supported Region until empty.

No such fixture was launched here because the account SCP prevents even read-only inventory and because a new stream group defaults can allocate billable capacity.
