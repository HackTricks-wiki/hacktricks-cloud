# AWS Network Security Manager audit (2026-09-30)

## Scope and current model

- Network Security Manager was absent from the public HackTricks Cloud corpus at the start of this pass.
- Reviewed the current Developer Guide, API reference, Service Authorization Reference, CloudTrail contract, pricing, and AWS-managed service-role policy.
- The service is regional and exposes rules, templates, policies, scopes, deployments, immutable snapshots, administrator accounts, association discovery, and synchronization diagnostics.
- The installed AWS CLI `2.34.45` predates the service. A temporary current AWS CLI `2.37.6` was used for signed calls and was kept outside the repository.

## Exact-rule update authorization test

Safety constraints:

- A synthetic Network Security Manager WAF configuration rule only; no policy, scope, deployment, WAF web ACL, protected application, traffic, Shield subscription, AWS Config recorder, or billable protected asset.
- Initial active rule configuration: `DefaultAction.Block`.
- A fresh STS session policy allowed only `network-security-manager:UpdateRule` on the exact synthetic rule ARN. It had no `GetRule`, WAF, Shield, Config, IAM, Organizations, or `iam:PassRole` action.
- The restricted session was given the already known current update token and changed the active configuration to `DefaultAction.Allow` with `isPublished=true`.

Result:

- The exact-resource write succeeded and changed the rule from version 1 to version 2.
- This confirms the authorization table's narrow boundary: the active rule mutation itself requires only exact-rule `UpdateRule` plus knowledge of the optimistic-concurrency token.
- `GetRule` is a practical additional permission when the attacker does not already know that token.
- The test did not claim downstream WAF impact because no policy/deployment existed. AWS's documented resource lifecycle states that a published live rule is enforced through referencing deployments and that a resource change triggers asynchronous recomputation/remediation. A version-qualified snapshot is immutable and is not changed by updating the live rule.

## High-value expected techniques

1. **Active live-rule weakening:** exact-rule `UpdateRule` can replace WAF inspection/configuration JSON without caller-side WAF access. Operational impact requires a mutable live reference, active deployment and remediation-enabled policy.
2. **Deployment deletion:** exact-deployment `DeleteDeployment` stops its monitoring/remediation. If the associated policy enables resource cleanup, removing the deployment also removes Network Security Manager-created firewall resources; otherwise they can remain unmanaged.
3. **Administrator removal:** wildcard-only `DeleteAdminAccount`, from the Organizations management account, disables one administrator's regional multi-account scopes/deployments and initiates protection cleanup.
4. **Delegated-admin persistence:** management-account `PutAdminAccount` can designate a controlled member account, assign priority 1 and delegate an organization/OU/account/firewall scope. This persists regional network-security administration beyond the original management session but does not grant general IAM access to member accounts.
5. **Cross-account security posture discovery:** synchronization results can expose account IDs, protected resource ARNs/types, expected-versus-actual configuration differences and remediation errors. This is useful enumeration but was kept in the service page rather than inflated into a separate low-impact technique.
6. **Potential financial/availability abuse:** Shield policies can cause the service role to create Shield Advanced subscriptions/protections. This was not tested because Shield subscription cost exceeds the authorized testing budget and the prerequisite already represents powerful protection-plane control.

## Telemetry

- AWS states that all service APIs are CloudTrail management events under `network-security-manager.amazonaws.com`.
- Read operations omit response elements; write operations retain request parameters and response elements. `GenerateRuleConfiguration.prompt` is specifically redacted.
- Event History later contained the exact live create/update/delete events. The restricted `UpdateRule` event was a default management write with the exact rule ARN in `resources`; its request retained the URL-encoded ARN, prior update token, complete `DefaultAction.Allow` configuration, publish flag and client token. Its response retained the new token, complete configuration, name/ID/ARN, `ACTIVE` status and version `2`.
- Empty `List*` calls were default management reads with `resources:null`; `GetRule` had the exact rule in `resources` but, consistently with the service contract, no response body in the event.
- Downstream enforcement also produces service-role activity and WAF/Shield/Config/resource telemetry.

## Potential unexpected-defect hypotheses

- Administrator-scope bypass: a delegated administrator targets an excluded account/OU or unauthorized firewall type through crafted scope expressions, explicit ARNs or snapshots.
- Administrator-priority bypass: a lower-priority admin or member policy overrides a higher-priority organization baseline through mixed live/snapshot references or sparse configuration merging.
- Cross-admin/account IDOR on `Get*`, snapshot, association or synchronization APIs using a known ARN from another administrator namespace.
- Cross-account visibility leakage when `enableCrossAccountVisibility=false`.
- WAF logging-configuration abuse causing the service-linked role to mutate an unrelated `aws-waf-logs-*` bucket policy or log delivery beyond the deployment/account boundary.
- Snapshot/draft confusion that changes an immutable pinned version or enforces an unpublished draft overlay.

These require an authorized Organizations management account and at least two controlled member accounts or a deployed protected-resource fixture. They remain hypotheses, not findings. No private AWS vulnerability report was created.
