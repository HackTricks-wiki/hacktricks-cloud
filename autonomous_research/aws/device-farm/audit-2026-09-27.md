## Authoritative behavior confirmed from current AWS models/documentation

The local AWS CLI was `aws-cli/2.34.45`. Its Device Farm service model exposed 68 operations and current request fields, including project/run `environmentVariables`, `executionRoleArn`, VPC configuration, remote-access endpoints, device proxies, and `UpdateUpload.editContent`.

Current AWS documentation confirms:

- Device Farm is available only in `us-west-2`.
- Custom test specifications execute ordered shell commands and gather chosen artifact paths.
- Project and run configuration can supply plaintext environment variables and an IAM execution role.
- Device Farm assumes an execution role inside the custom test runtime; the role must be in the caller's account and configuring it requires `iam:PassRole`.
- `UpdateUpload --edit-content` updates a custom test specification and returns an upload object containing a presigned S3 URL.
- `ListArtifacts` returns temporary download URLs for logs/files/screenshots; custom artifacts include the YAML, generated shell script, output, and customer-selected files.
- `GetRemoteAccessSession` returns interactive and Appium/WebDriver endpoint URLs; AWS demonstrates direct `curl` use of the Appium endpoint.
- `CreateTestGridUrl` issues a signed WebDriver URL for 60–86,400 seconds. AWS warns that anyone with the URL can create sessions on the caller's behalf until expiry.
- TestGrid browsers can access VPC-resolvable private applications when the project is VPC-attached.
- Private-device instance profiles control package cleanup, exclusion lists, and reboot. Package cleanup defaults to false for private devices. AWS documents retaining iOS apps/developer trust through exclusions.
- All Device Farm API calls are CloudTrail events. Subsequent HTTP use of a returned signed URL is not another SigV4 Device Farm API call.
- Device Farm does not expose a general resource-policy API. Execution roles are same-account.

## Strong techniques promoted to the book

### Privilege escalation

1. **Existing test-spec trojanization**: exact-upload `UpdateUpload` permission can replace a reused YAML test specification. A later legitimate run executes attacker commands and can expose an already configured execution role without the editor needing `iam:PassRole`.
2. **Execution-role pass and custom-spec execution**: `CreateProject`/`UpdateProject` or run-level role selection plus `iam:PassRole`, content upload, and `ScheduleRun` yields arbitrary shell execution with the passed role. Impact is bounded by role policy and network reach.

### Post-exploitation

1. **Plaintext configuration disclosure** via `GetProject`, `ListRuns`, and `GetRun`: environment values, role ARN, VPC/proxy topology, upload ARNs, and artifact paths.
2. **Test-spec and artifact theft** via `GetUpload`/`ListArtifacts`: YAML, generated scripts, logs, screenshots, video, crash data, and customer artifacts through temporary URLs.
3. **Remote-device session takeover** via `GetRemoteAccessSession` endpoint URLs.
4. **Private-web pivot** via `CreateTestGridUrl` on an existing VPC-attached TestGrid project.
5. **Traffic interception** by starting a run/session with a hostile `deviceProxy`, with an explicit caveat that a proxy alone cannot decrypt properly validated TLS.
6. **Anti-forensics/deletion** through exact delete APIs for runs, completed sessions/results, uploads, or projects.

### Persistence

1. **Stored test-spec commands** under a stable upload ARN, triggered by later CI runs. This is service/pipeline persistence and is time-limited by upload retention.
2. **Private physical device persistence** by disabling cleanup/reboot or excluding an attacker package, then installing it during a private-device session. This preserves app/data/trust state on that device.

### Unauthenticated capability use

1. Leaked presigned upload/edit URLs permit method-scoped content PUT without AWS credentials.
2. Leaked artifact/test-spec download URLs permit temporary GET without AWS credentials.
3. Leaked TestGrid signed URLs permit browser-session creation and associated cost/VPC reach until expiration.
4. Leaked remote interactive/Appium URLs permit control of the running physical device.

These are not public-by-ARN resources. An authenticated request first mints or retrieves the capability URL.

## Ideas investigated but not promoted

| Idea | Disposition | Reason |
| --- | --- | --- |
| Download every app/test-package through `GetUpload.url` | Narrowed | AWS explicitly documents GET download for test specs and PUT storage for generic uploads. General download behavior needs a live method test before claiming it. |
| Cross-account access through Device Farm resource policies | Rejected | No general Device Farm resource-policy API. Normal cross-account access requires assuming a role in the owner account. |
| Identifier-only/unsigned account enumeration | Rejected | Native APIs require SigV4; no useful public account-ID path found. |
| `CreateNetworkProfile`/`UpdateNetworkProfile` as an attack | Not promoted alone | It mainly degrades a test's bandwidth/latency/loss; weaker than proxy/VPC pivots and obvious in resource state. |
| Change radio/location/locale settings | Not promoted alone | Test disruption/spoofing with limited general security impact. |
| `StopJob`, `StopRun`, `StopRemoteAccessSession` | Not promoted alone | Straightforward availability impact and usually lower value than deletion/anti-forensics. |
| `PurchaseOffering`/`RenewOffering` cost abuse | Documented only as a dangerous permission | Potentially expensive, deliberately not invoked; ordinary billing abuse rather than a distinct exploit. |
| Project env-var injection (`HTTP_PROXY`, package registries, `BASH_ENV`, language hooks) | Backlog | The service allows custom variables except reserved `DEVICEFARM_` names, but reliable code execution depends on victim commands/files and was not live-tested. Direct test-spec replacement is stronger. |
| Legacy VPCE configuration cross-account/IDOR | Backlog | Likely constrained by endpoint-service acceptance and IAM; requires a second authorized account/service and was not testable behind the SCP. |
| TestGrid/VPC service-linked-role privilege escalation | Rejected as generic IAM privesc | The managed role is limited to ENI lifecycle. The useful attack is the browser's network path, not credential recovery from the service-linked role. |
| Public-device retained app persistence | Rejected | Public devices are shared and service-cleaned; the supported persistence primitive is explicitly for private fleets. |

## Logging conclusions

- AWS states all Device Farm API calls are logged as CloudTrail events and visible in Event history.
- Reads that return signed URLs are therefore detectable at issuance/retrieval time.
- Direct presigned S3, WebDriver, interactive, and Appium HTTP requests are not additional Device Farm API calls. Detection must use session/run inventory, TestGrid actions/artifacts, video/logs, VPC Flow Logs, DNS, application/IdP telemetry, egress/proxy logs, and cost/concurrency alarms.
- CloudTrail event fields/redaction could not be observed live because both Device Farm and `LookupEvents` are explicitly denied by the organization SCP.
