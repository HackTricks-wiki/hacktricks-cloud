# ElastiCache — open ideas

- [ ] **Enum page** — `DescribeCacheClusters` / `DescribeReplicationGroups` / `DescribeCacheSubnetGroups` recon: endpoints, node types, engine version, `AuthTokenEnabled`, `TransitEncryptionEnabled`, whether RBAC or legacy AUTH-token, publicly-resolvable endpoints.
- [x] **Privesc / lateral via RBAC** — live exact-user test confirmed that `elasticache:ModifyUser` alone can simultaneously replace a restricted user's password and ACL with `on ~* +@all`, without Describe, group/cache, secret/KMS, PassRole, or SLR-management permission. Published on the privesc page; see `modify-user-rbac-escalation-2026-10-01.md`.
- [x] **Post-exploitation / legacy AUTH takeover** — exact-group `ModifyReplicationGroup --auth-token ... --auth-token-update-strategy ROTATE` added a second attacker-known token while preserving the old token; both completed TLS `AUTH` + `PING`. Published; see `modify-replication-group-auth-rotation-2026-10-01.md`.
- [ ] **Other replication-group mutations** — test user-group removal (documented to disable access control), security-group replacement, log-delivery disablement and snapshot-retention changes. Keep `TestFailover` / pure disruption out unless it reveals a stronger boundary.
- [ ] **Snapshot export correction/test** — current public `CopySnapshot`/serverless-export text overclaims minimum S3 permissions and cross-account destination support. Correct against current docs and live-test caller/bucket ownership boundaries; do not retain the current cross-account claim without evidence.
- [ ] **Serverless caches** — check `CreateServerlessCacheSnapshot` / `ExportServerlessCacheSnapshot` for an exfil path analogous to the RDS snapshot-share technique.
- [ ] **Free invariant tests** — Redis no-password user to Valkey transition; IAM-mode user with mismatched ID/name; `ModifyUserGroup` secondary-resource authorization; exact-resource Describe isolation; failed-call AUTH-token redaction.
