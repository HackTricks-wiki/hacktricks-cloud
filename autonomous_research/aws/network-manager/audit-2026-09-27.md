## Attack hypotheses and dispositions

| Hypothesis | Result | Public-book disposition |
| --- | --- | --- |
| A core policy writer can bypass segmentation, redirect/blackhole routes, auto-admit attachments, or steer traffic through a network function | **Confirmed expected behavior** from exact-ARN auth probe and current policy schema; deployment requires `PutCoreNetworkPolicy` plus `ExecuteCoreNetworkChangeSet` | Added post-exploitation technique |
| Attachment tags can move an attachment between tag-selected segments | **Confirmed expected behavior** in current AWS policy docs; automatic movement occurs where acceptance is disabled | Added post-exploitation technique |
| A routing-policy label writer can add/remove attachment route filters without changing the segment | **Confirmed expected behavior**; exact core + attachment resource authorization reached `ResourceNotFound` rather than IAM denial | Added post-exploitation technique |
| Attachment acceptance can admit attacker-controlled cross-account infrastructure | **Confirmed expected behavior** from shared-attachment model and exact attachment auth probe | Added post-exploitation technique |
| VPC/DX attachment update can break or reshape network paths | **Confirmed expected behavior**; exact attachment auth probe reached resource lookup, and API exposes subnet/options or edge locations | Added post-exploitation technique |
| A RAM share can persist an external account's ability to create attachments | **Confirmed expected behavior**; a RAM-only least-privilege role created a share and attempted core association with no Network Manager identity permission | Added service-level persistence technique |
| `networkmanager:PutResourcePolicy` can directly install a useful handcrafted external policy | Exact core-ARN authorization was confirmed, but no live core existed and AWS does not document the accepted consumer-action policy shape independently of RAM | Retained as a research lead; not published as a technique |
| Network Manager exposes `iam:PassRole` or another direct IAM privilege-escalation path | **Negative**: no Network Manager API accepts an execution role; service-linked roles are service-owned dependencies, not caller-selected role execution | No privilege-escalation page |
| Unauthenticated list/get APIs disclose global networks or ID existence | **Negative**: all four unsigned probes returned `MissingAuthenticationTokenException` | No unauthenticated-access page |
| Legacy site/device/link metadata mutations provide meaningful access | Mutations can falsify monitoring/topology metadata but do not change the underlying AWS network path by themselves | Excluded as low-value/noise |
| Route Analyzer sends traffic and could probe endpoints stealthily | **Negative**: it evaluates configuration without sending packets. It is still useful topology/control recon and is logged as a write API | Included in enumeration, not a separate attack page |
| Delete operations merit standalone techniques | They provide straightforward availability impact but add little beyond obvious CRUD/destructive permissions | Mentioned only implicitly; no low-value standalone technique |

No unexpected AWS security defect was confirmed, so no file was created under `/home/tester/cloud_bb/aws` for this service.

## RAM cross-account persistence probe

The current live permission catalog returned:

| Managed permission | Version | Current actions |
| --- | --- | --- |
| `AWSRAMDefaultPermissionsNetworkManagerCoreNetwork` | 3 | `CreateVpcAttachment`, `UpdateVpcAttachment`, `CreateTransitGatewayPeering`, `CreateTransitGatewayRouteTableAttachment`, `CreateDirectConnectGatewayAttachment` |
| `AWSRAMTransitGatewayPermissionsNetworkManagerCoreNetwork` | 1 | `CreateTransitGatewayPeering`, `CreateTransitGatewayRouteTableAttachment` |
| `AWSRAMVPCPermissionsNetworkManagerCoreNetwork` | 1 | `CreateVpcAttachment`, `UpdateVpcAttachment` |

To determine the victim-side minimum permission safely:

1. Created disposable role `ht-networkmanager-ramprobe-20260927-2277247` with only `ram:CreateResourceShare` on `*`.
2. Called `CreateResourceShare` in `us-east-1` with the default Network Manager core permission, no principals, and a fake core-network ARN.
3. API returned success with an ACTIVE share. Its resource association became `FAILED` with `The specified resource could not be found in your AWS account.`
4. This proves RAM accepted the share and attempted to author/associate the resource policy without the caller holding `networkmanager:PutResourcePolicy`.
5. Deleted the exact share immediately, then deleted the inline policy and role.
6. Final query by exact share name returned no non-deleted share; final role-prefix query returned `[]`.

No external principal was used, so no invitation or cross-account notification was created.

## Logging results

AWS documents Network Manager API calls as CloudTrail management events with `eventSource=networkmanager.amazonaws.com`. Current EventBridge documentation also lists direct best-effort events for:

- Topology Change
- Routing Update
- Status Update
- Service Advisory
- Segment Update
- Network Function Group Update
- Policy Update

The audit generated the expected named API calls through signed probes. Direct lookup of `us-west-2` CloudTrail Event History could not be completed because the organization SCP explicitly denied `cloudtrail:LookupEvents`; `us-east-1` returned no Network Manager events because the tested service control-plane calls were signed to the `us-west-2` endpoint. This is an environment validation limitation, not evidence that the documented events are absent.

Expected logging/stealth classification used in the public pages:

| Activity | Evidence | Stealth |
| --- | --- | --- |
| Inventory/policy/route reads | Named CloudTrail management events | Medium |
| Route Analyzer | `StartRouteAnalysis`, `GetRouteAnalysis` | Medium |
| Policy deployment | Put + execute events and direct policy/routing/segment events | Low |
| Attachment mutations | Named CloudTrail events and direct topology/routing/status events | Low to medium depending change |
| RAM sharing | RAM CloudTrail events plus durable share/principal/resource inventory | Low |
| Data-plane use | Flow/firewall/application telemetry, if enabled | High when telemetry is absent |
