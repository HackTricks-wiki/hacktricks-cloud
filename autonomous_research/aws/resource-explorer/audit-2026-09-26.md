# AWS Resource Explorer security audit — 2026-09-26

## Scope and result

Reviewed the current Resource Explorer search/setup model, views, IAM action/resource scoping, CloudTrail behavior, multi-account sharing boundary, and low-cost least-privilege behavior in `us-east-1`.

Main results:

1. An exact-view `GetView` + `Search` grant is a strong cross-service metadata oracle and does not require any corresponding target-service enumeration permission.
2. `UpdateView` alone can clear a restrictive view filter. Existing users keep the same view ARN and search policy but immediately see the broader result set.
3. CloudTrail records both actions as management events but redacts the search query and view filter, and omits search results. Detection needs view snapshots plus behavioral monitoring.
4. Index deletion/update convergence is asynchronous and stale deleted resources can remain searchable.
5. View sharing is constrained to the same AWS Organization through multi-account search/AWS RAM; no public or arbitrary external-account sharing path was established.
6. No unexpected AWS malfunction or zero-day was found. Both published attacks are expected authorization/configuration behavior.

## Experiment A — exact-view search without target-service permissions

### Fixtures

- Tagged SSM parameter `/ht-rex-audit-20260926`
- Tagged empty S3 bucket `ht-rex-audit-228478051196-20260926`
- Local index `arn:aws:resource-explorer-2:us-east-1:228478051196:index/89a81f52-5dba-4d64-9bd1-f4214bbd2daa`
- View `ht-rex-restricted-20260926`, initially filtered to `service:ssm`, with `tags` included
- Role `HtRexSearchAudit-20260926`

The search role had only:

```json
{
  "Effect": "Allow",
  "Action": [
    "resource-explorer-2:GetView",
    "resource-explorer-2:Search"
  ],
  "Resource": "arn:aws:resource-explorer-2:us-east-1:228478051196:view/ht-rex-restricted-20260926/631aae10-df75-4713-9061-0ffdb2c19ebd"
}
```

### Results

- `ssm:DescribeParameters` failed with an identity-policy `AccessDeniedException`.
- `s3:ListAllMyBuckets` failed with an identity-policy `AccessDenied`.
- Search through the restricted view succeeded and returned the SSM parameter ARN, account, Region, `ssm:parameter` type, service, last-report time, and both tags.
- After view expansion, a free-form name search returned the SSM and S3 fixtures plus names/ARNs from IAM, Lambda, CloudWatch Logs, ECS, and Batch.
- Several results were stale names of recently deleted research resources, confirming that the index is not a real-time existence oracle.

Conclusion: Resource Explorer search authorization is independent of target-service read authorization. The returned metadata is operationally useful for discovering exact ARNs and naming conventions but does not grant permission on those resources.

## Experiment B — exact `UpdateView` filter widening

The view was reset to `FilterString=service:ssm` with tags included. A second role was granted only:

```json
{
  "Effect": "Allow",
  "Action": "resource-explorer-2:UpdateView",
  "Resource": "arn:aws:resource-explorer-2:us-east-1:228478051196:view/ht-rex-restricted-20260926/631aae10-df75-4713-9061-0ffdb2c19ebd"
}
```

The role successfully ran:

```bash
aws resource-explorer-2 update-view \
  --view-arn '<exact-view-arn>' \
  --filters 'FilterString=' \
  --included-properties Name=tags
```

`GetView` was independently denied for the same role. The response confirmed an empty filter and retained tags. Existing search authorization did not change, but its visible service set did.

An earlier update omitted `IncludedProperties`; the resulting view had an empty included-property list, and tag-filter search failed validation. `UpdateView` replaces these mutable structures rather than preserving an omitted tag setting. The published command explicitly retains tags.

## Experiment C — CloudTrail telemetry

Observed live events:

| Event | Type | Tested visibility |
| --- | --- | --- |
| `Search` | Read-only management | `ViewArn` visible; `QueryString` replaced by `"***"`; response absent |
| `UpdateView` | Write management | `ViewArn` and included properties visible; request and response `Filters` replaced by `"***"` |
| `CreateView` | Write management | View name/properties visible; filter redacted |
| `CreateIndex` | Write management | Index ARN/state visible |

Search is logged, but the event cannot answer what was queried or returned. `UpdateView` is high-signal but the event cannot show whether the filter narrowed or widened without an external configuration baseline.

## Candidate matrix

| Candidate | Required authority / prerequisite | Result and disposition |
| --- | --- | --- |
| Cross-service inventory through a view | Exact `GetView` + `Search` | Verified and published |
| Expand existing consumers by clearing view filter | Exact `UpdateView` on known ARN | Verified and published |
| Obtain target data/credentials through search | Search permission | Rejected; metadata only, no underlying data access |
| Public/outside-organization view sharing | Resource policy/RAM | Rejected; sharing is constrained to multi-account search in the same Organization |
| Organization-internal reconnaissance through a shared view | Existing RAM/resource policy plus consumer identity policy | Expected and documented as a boundary; no standalone attack added |
| Hide exact search/filter intent from CloudTrail | Normal `Search`/`UpdateView` | Verified redaction, incorporated into stealth/detection guidance |
| Rely on Resource Explorer as real-time asset state | Search | Rejected; asynchronous index can retain deleted resources |
| Automatic first-search setup as escalation | Read-only plus optional `iam:CreateServiceLinkedRole` | Expected setup behavior; no privilege escalation beyond metadata completeness |

## Follow-up ideas

- In an Organization lab, measure the exact CloudTrail/RAM/resource-policy event sequence for sharing a view and then widening it from the owner account.
- Test whether an SCP/permissions-boundary combination can reliably distinguish `Search` and `ListResources` through `resource-explorer-2:Operation` without breaking console search.
- Inventory which supported resource types expose unusually sensitive names, descriptions, or system tags and whether those properties differ between service-managed and user-owned views.
- Evaluate query throttling as a practical defender signal and measure pagination/no-keyword behavior on an account with more than 1,000 indexed resources.
