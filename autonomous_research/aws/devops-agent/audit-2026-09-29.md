# AWS DevOps Agent boundary audit — 2026-09-29

## Outcome

Published current service enumeration, sanitized registered-service reads, service-association poisoning, one-time webhook credential persistence, private-connection certificate tampering and the correct Operator App IdP replacement path. No AWS defect was confirmed and no private report was created.

Account `228478051196` was checked through `ht-admin` in `us-east-1` and `eu-west-1`. Both Regions ended with empty agent-space, registered-service and private-connection inventories. No space, service, association, role, VPC Lattice resource, ENI, paid integration or third-party request was created.

## Authorization and data boundaries

- CLI/service name: `devops-agent`; IAM prefix: `aidevops`; event source:
  `aidevops.amazonaws.com`.
- `ListServices` uses `Resource: "*"`; `GetService` supports the exact service ARN.
- Association reads/writes can require both the exact agent-space and child association ARNs. A policy containing only the child is insufficient for these dual-resource actions.
- Submitted AWS roles require exact-role `iam:PassRole` with `iam:PassedToService=aidevops.amazonaws.com`, service trust and normal role-policy/session-policy limits. APIs expose role ARNs, not STS credentials.
- `GetService` returns endpoints, auth types/header names, KMS/private-connection/resource/provider metadata but intentionally omits stored tokens, keys and OAuth/provider secrets.
- `ListWebhooks` returns URL, ID and type, not the one-time secret/API key.
- Unsigned `ListServices` required authentication in both Regions.

## Public expected techniques

1. **Service/association reconnaissance:** reveal internal endpoints, connected resources, role ARNs, auth schemes and provider/account identifiers without dumping stored credentials.
2. **Association poisoning:** overwrite or update a provider association to change resource/tool selection, monitoring/elevated roles or webhook configuration. Role-bearing variants retain the PassRole gate.
3. **Webhook persistence:** supported association responses can contain a newly issued one-time secret/API key. That bearer credential preserves external event injection after the AWS session ends, until defenders replace/disassociate/revoke it. Not every update regenerates a credential.
4. **Private trust-store tampering:** exact-connection `UpdatePrivateConnectionCertificate` replaces the trusted PEM chain. Alone this can cause outage; credential interception/tool-response poisoning also requires control of the routed destination.
5. **Operator App takeover correction:** `UpdateOperatorAppIdpConfig` accepts only a replacement secret. Issuer/client/provider/role replacement requires `DisableOperatorApp` followed by `EnableOperatorApp` and PassRole, making the operation disruptive and very noisy.

## Telemetry

All tested calls appeared as CloudTrail management events. Observed secret fields were redacted:

- `RegisterService` logged endpoint/token name and `tokenValue: "***"`.
- `UpdateOperatorAppIdpConfig` logged `idpClientSecret: "***"`.
- `UpdatePrivateConnectionCertificate` logged the submitted public PEM certificate in full.
- `ListWebhooks` logged agent-space/association IDs and was read-only.

Agent reasoning/actions are also retained in immutable journals. Webhook use and downstream agent actions produce integration/journal and assumed-role/service evidence even though the bearer user no longer needs an AWS identity.

## Rejected/deferred ideas

- **Stored credential dump through `GetService`:** rejected; sanitized output types omit secrets.
- **Webhook takeover from `ListWebhooks`:** rejected; the secret/key is one-time output and is not listed later.
- **Raw role credential theft:** rejected; expected service trust, PassRole and session guardrails.
- **Access-token persistence:** high-value future candidate. Agent-space-scoped create/rotate/get/list and revoke actions exist; enabled `operate` tokens can last up to 60 days. Access tokens are off by default and the current public CLI lacks a stable create-request schema, so no PoC was published.
- **New Relic/Grafana endpoint credential relay:** private fixture hypothesis only. Determine whether updating an association-selected endpoint sends the stored provider credential to that endpoint or enforces a provider allowlist/equality check.
- **Private-connection SSRF/credential relay:** private fixture hypothesis only. Test link-local, loopback/RFC1918, DNS-rebinding, SNI/Host and OAuth exchange boundaries before any claim.
- **Cross-account/wrong-parent known-ID combinations and current role enforcement:** require a controlled non-empty fixture.

The local AWS CLI's `UpdateOperatorAppIdpConfig` endpoint trait selected the wrong endpoint; the safe probe reached the control plane only with `https://cp.aidevops.us-east-1.api.aws`. This appears to be a stale SDK-model issue, not a security vulnerability.
