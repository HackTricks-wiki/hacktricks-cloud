# AWS CodeConnections / CodeStar Connections audit — 2026-09-26

## Scope and isolation

- Account: `228478051196`, region `us-east-1`.
- Administrator session: `hacktricks-training` assumed `arn:aws:iam::228478051196:role/ChackBotAdministratorRole`.
- Exact fixture namespace: `ht-codeconnections-20260926`.
- No third-party provider was authorized, no OAuth/app installation was started, no real repository was contacted and no paid workload ran.
- Initial state: zero connections, hosts and repository links in `us-east-1`.

Fixtures created:

- Pending GitHub connection `ht-codeconnections-20260926` with research marker tags.
- Pending GitHub Enterprise Server host `ht-codeconnections-20260926-host` using the deliberately non-resolving endpoint `https://git.invalid.example`.
- Least-privilege role `ht-codeconnections-20260926-low`, trusted only by the designated administrator role.

## High-value conclusions

1. Connection and host reads are useful metadata oracles. `GetConnection` disclosed name, ARN, provider, account and state with only that exact-resource permission; `ListTagsForResource` independently disclosed all tags. `ListHosts` exposed the self-managed provider endpoint.
2. `ListConnections` did not authorize when the IAM statement used the concrete connection ARN or `arn:aws:codeconnections:us-east-1:228478051196:*`. It authorized with `Resource: "*"`. A `codeconnections:ProviderTypeFilter = GitHub` condition required the caller to supply the matching provider filter; no filter and `GitLab` were denied.
3. `CreateRepositoryLink` has a real three-permission boundary. Main action only failed on `UseConnection`; adding that failed on `PassConnection`; adding unconditioned `PassConnection` advanced to the missing service-linked-role permission. A `PassedToService` value of `codepipeline.amazonaws.com` also advanced, while `proton.amazonaws.com`, `codeguru-reviewer` and `cloudformation.sync.codeconnections.amazonaws.com` did not.
4. `CreateSyncConfiguration` enforces both `iam:PassRole` and `PassRepository`. A mismatched `PassRepository` condition (`codepipeline.amazonaws.com`) was denied. With `PassRepository` and `iam:PassRole` restricted to `cloudformation.sync.codeconnections.amazonaws.com`, the request advanced to `Repository Link ... was not found`. No sync was created.
5. Public CodeConnections APIs do not return provider tokens. Sensitive handshake and token-related IAM actions are permission-only and are exercised by console/service workflows.
6. No resource-policy surface exists. A cross-account `GetConnection` using a foreign-account ARN returned `Account 228478051196 does not have access...`. Unsigned list/get returned `MissingAuthenticationTokenException`.
7. No unexpected authorization bypass or AWS security defect was found.

## CloudTrail observations

- New namespace endpoint event source: `codeconnections.amazonaws.com`; legacy activity can use `codestar-connections.amazonaws.com`.
- Successful `ListConnections`, `ListHosts`, `GetConnection` and `ListTagsForResource` were management read events. Request filters/ARNs were logged; `responseElements` was `null`.
- Successful `CreateConnection` and `CreateHost` logged names, provider, endpoint and all supplied tags in both request and response fields.
- Authorization failures frequently had `requestParameters: null` but included the missing action and target ARN in `errorMessage`.
- Once repository-link authorization passed, `CreateRepositoryLink` logged the connection ARN, owner ID and repository name, even though creation stopped at missing SLR permission.
- `CreateSyncConfiguration` failures were management writes. The service redacted/omitted request fields (`requestParameters: null`) in the tested authorization failures.

## Service-linked role behavior

The first successful authorization phase of `CreateRepositoryLink` tried to create `AWSServiceRoleForGitSync` and failed because the low role lacked `iam:CreateServiceLinkedRole`. This is expected per AWS documentation. The permission was deliberately not added, so no persistent SLR or repository link was created.

## Notification visibility

AWS CodeStar Notifications does not provide connection-specific notification rules. Its supported resource types are CodeBuild projects, CodeDeploy applications, CodePipeline pipelines and CodeCommit repositories. Connection abuse is instead visible through CodeConnections CloudTrail events, related CodePipeline/CloudFormation events, Git-sync EventBridge events and the external Git provider's audit logs.

## UpdateConnectionInstallation / handshake assessment

- `UpdateConnectionInstallation`, `GetIndividualAccessToken`, `GetInstallationUrl`, `ListInstallationTargets` and `StartOAuthHandshake` are documented permission-only actions; the public AWS CLI/service model has no directly invocable API operations for them.
- `UpdateConnectionInstallation` supports exact connection-resource scoping, resource tags and `codeconnections:InstallationId`.
- Security impact: a principal that can complete provider authorization may bind a third-party installation to a connection and thereby establish/alter the trust used by downstream services.
- This was not live-completed because doing so would require interacting with and authorizing an external third-party account, explicitly outside this audit's test design.
- Recommended controls: exact connection ARNs, protected ABAC tags, allowlisted Installation IDs and provider types; alert on connection status/installation changes.

## Repository-link and sync mutation assessment

Documented `UpdateRepositoryLink` mutable fields:

- Connection ARN (replacement provider type must match)
- Encryption key ARN

Documented `UpdateSyncConfiguration` mutable fields:

- Branch
- Config file
- Repository link ID
- Resource/stack name
- Git-sync role ARN
- Trigger behavior and pull-request/deployment-status options

These are source-integrity and privilege-escalation surfaces. A malicious source plus a passable Git-sync role can cause CloudFormation to execute attacker-controlled templates. The public API explicitly states that the selected role lets AWS update the target resource on the caller's behalf.

## Ideas retained for future authorized testing

1. With a disposable Git provider organization, verify whether `UpdateConnectionInstallation` can rebind an already `AVAILABLE` connection or only complete a `PENDING` connection, and whether downstream pipelines retain a stable connection ARN after rebind.
2. With a disposable private repository, test every `UseConnection` condition key (`FullRepositoryId`, `OwnerId`, `RepositoryName`, `BranchName`, `ProviderAction`, `ProviderPermissionsRequired`) against CodePipeline, CodeBuild and CloudFormation Git sync. Confirm which services provide each context key and fail closed when absent.
3. Test legacy `codestar-connections` action prefixes against new `codeconnections` ARNs and vice versa. AWS documents compatibility, but mixed-prefix resource matching has caused operational mistakes.
4. Create a disposable repository link after explicitly authorizing and later deleting the SLR. Verify `UpdateRepositoryLink` requires both `UseConnection` and `PassConnection`, and confirm the `PassedToService` context on update as well as create.
5. Create a no-op CloudFormation Git sync with a least-privilege role and test `UpdateSyncConfiguration` branch/config/repository/role swaps one field at a time. Record exact EventBridge and CloudTrail telemetry.
6. Investigate permission-only/console-only `codeconnections:CreateForcedTargetSync` and `codeconnections:CreatePullRequestForResource`, which the CloudFormation guide says may be required even though IAM can warn the actions do not exist. These could force deployment or write to a provider repository, but were not callable through the current public CLI model.
7. Test tag-poisoning chains: grant only `TagResource` plus an action conditioned on `aws:ResourceTag`, add the authorization tag, then exercise `UseConnection`, `PassConnection`, `UpdateConnectionInstallation` or `PassRepository` through their consumer APIs.
8. Check KMS-key replacement on repository links for confused-deputy, cross-account key-policy and denial-of-service edge cases.
9. Validate deletion behavior and recoverability of connections consumed by pipelines, build projects, Proton and Git-sync configurations.
10. Compare CloudTrail coverage of browser-only OAuth actions with external-provider installation audit events. Determine whether installation IDs are visible in AWS logs.

## Low-value / rejected ideas

- Treating `UseConnection` as a direct token-download API: the action is permission-only and public CodeConnections has no generic token-returning operation. Abuse needs a consumer service; CodeBuild-specific provider token exposure is already documented elsewhere.
- Calling arbitrary provider endpoints through a pending host: no public operation was found that turns `GetHost`/`UpdateHost` into an unauthenticated SSRF primitive, and setup requires provider registration flows.
- CodeStar Notifications as a direct connection metadata oracle: connection resources are not a supported notification-rule resource type.
- Reporting `ListConnections` resource-scoping behavior as a zero-day: this is an IAM/documentation mismatch and operational gotcha, not a demonstrated security-boundary failure.
