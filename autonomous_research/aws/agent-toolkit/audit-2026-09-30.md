# Agent Toolkit for AWS public catalog audit — 2026-09-30

## Result

Reviewed the new AWS CLI `agent-toolkit` catalog API and local skill-management commands. No HackTricks technique or private AWS report was warranted: the API intentionally distributes the same AWS-maintained skills published in the open-source `aws/agent-toolkit-for-aws` repository, exposes no victim/account state, and requires existing local filesystem access to install a skill into an agent.

## Observed model and behavior

- API model date: `2026-04-22`; endpoint: `https://agent-toolkit.us-east-1.api.aws`.
- Every catalog operation (`ListSkills`, `SearchSkills`, `GetSkill`, `GetLatestSkillVersion`, `GetSkillFile`, `GetSkillFileChecksum`) is explicitly `noAuth`.
- Live unsigned listing returned the public curated catalog. Metadata enumerates name, description, version, categories and exact file paths.
- An unsigned `GetSkillFile` returned the published `signing-in-to-aws` `SKILL.md` without credentials. CloudTrail Event history contained no account event, as expected for a public non-account-scoped request.
- The file's checksum endpoint returned SHA-256 `9fecdf124113b2f6e8e4729c7722578783d05c3d5677d380d6950e96ea7d6100`, which matched the downloaded body.
- `add-skill` supports explicit `--skill-version` pinning; `update-skill` is an explicit local operation. No install/update/remove command was executed during this audit.

## Boundary probes

Against the harmless known `signing-in-to-aws/v1/SKILL.md` path:

- listed file: HTTP 200;
- unlisted `README.md`: HTTP 404;
- raw `../`, percent-encoded `..`, encoded slash, double-encoded traversal and a cross-skill escape attempt: HTTP 403 before content retrieval.

The greedy path field therefore did not escape the advertised skill/version boundary in the tested canonicalization set.

## Disposition

The security-relevant concept is ordinary local AI-agent supply-chain risk: installed Markdown/scripts are authoritative instructions and should be version-pinned/reviewed where appropriate. An attacker would still need to compromise AWS's public catalog/repository/TLS path or already control the local agent configuration. Public catalog discovery alone provides no foothold, cloud reconnaissance, IAM permission, victim identifier or persistence boundary, so it is intentionally excluded from the book.

No AWS resources, credentials, local skills or agent configuration were created or modified.
