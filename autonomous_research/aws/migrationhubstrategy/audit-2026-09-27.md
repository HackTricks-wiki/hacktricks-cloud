## Managed-role boundaries

`AWSMigrationHubStrategyCollector` version 6 currently grants:

- S3 read/write and bucket-management actions on `arn:aws:s3:::migrationhub-strategy-*`, restricted by `aws:ResourceAccount` to the collector principal's account;
- `secretsmanager:GetSecretValue` on same-account `migrationhub-strategy-*` secrets;
- collector messaging/config/logging actions;
- application-transformation assessment actions;
- patterned API Gateway log/metric calls.

`AWSMigrationHubStrategyServiceRolePolicy` version 1 grants:

- `discovery:ListConfigurations`, `discovery:DescribeConfigurations`, and `mgh:GetHomeRegion` on wildcard resource;
- S3 list/read/write/ACL actions for `migrationhub-strategy-*` buckets.

The account did not contain `AWSServiceRoleForMigrationHubStrategy`. The console full-access policy permits `iam:CreateServiceLinkedRole` only when `iam:AWSServiceName` equals `migrationhub-strategy.amazonaws.com`. The native APIs do not accept a role ARN.

| `GetLatestAssessmentId` / `GetRecommendationReportDetails` | `readOnly: true`, `ResourceNotFoundException` |

This unusual read-only classification is not a vulnerability, but detections that filter only `readOnly=true` can miss the two inventory list calls. S3 object reads/writes require separate S3 data-event logging, which is disabled by default. Direct reads from collector-local configuration create host telemetry rather than CloudTrail events.

## Strong expected attacks accepted

1. Read collector/server/component topology, source/database metadata, migration strategies, import locations and report coordinates through narrow service read actions.
2. Generate a fresh JSON/Excel recommendation export when authorized, or use returned S3 bucket/key coordinates, then combine them with independent `s3:GetObject` and optional `kms:Decrypt` access to steal anti-pattern, recommendation and import-status reports.
3. Harvest locally stored AWS, vCenter, fleet OS, SSH/WinRM, source-control and remote analysis credentials after compromising a collector host/container.
4. Abuse a captured collector IAM key to fetch same-account `migrationhub-strategy-*` secrets and read/write same-account prefixed S3 buckets.
5. Poison the durable migration inventory with `StartImportFileTask`; full cleanup may require AWS Support because no public delete-data API exists.
6. Tamper with portfolio goals, preferred server/component strategies or inclusion status using `PutPortfolioPreferences`, `UpdateServerConfig` and `UpdateApplicationComponentConfig`.
7. Stop a known running assessment with `StopAssessment` to delay or stale recommendations.

## Rejected, narrowed or deferred ideas

- **Unauthenticated native API:** rejected; unsigned calls return `MissingAuthenticationTokenException`.
- **Bearer report URL:** rejected; public responses contain S3 bucket/key values, not pre-signed URLs.
- **Arbitrary role pass or account privilege escalation:** rejected; no request accepts a role ARN and the service supports only its fixed service-linked role. No privilege-escalation page was created.
- **Recommendations execute code or migrations:** rejected; they are advisory. Analysis can run through a configured collector, but the service does not deploy the recommended architecture.
- **Native cross-account resource sharing:** rejected; Strategy Recommendations has no resource policies. Cross-account API access requires an identity in the owner account.
- **Foreign-account import/report bucket accepted merely because the request accepts a bucket name:** unverified. The model does not include an account constraint and the service-linked policy lacks `aws:ResourceAccount`, but actual acceptance needs two authorized accounts, bucket policy, object-ownership and KMS tests. It was not presented as a proven attack.
- **`UpdateApplicationComponentConfig` leaks the selected Secrets Manager value:** rejected; the request supplies a secret reference for database analysis, and no public response returns the plaintext value.
- **Recommendation tampering as access persistence:** rejected. It creates durable integrity damage, not a durable authentication/authorization path, so no persistence page was created.
- **Successful import/assessment fixture:** excluded because imported data lacks self-service deletion, assessment may create background work/SLR/S3 state, and the empty account was sufficient for safe boundary tests.
- **CloudTrail `readOnly` misclassification as a security defect:** not reportable by itself. It is documented as a detection caveat only.

## Candidate future defect tests

Use an existing authorized customer account with a disposable collector, two researcher-controlled AWS accounts and Support-approved deletion:

1. Test foreign-account input, analysis and report buckets, including bucket-owner-enforced ownership, `PutObjectAcl`, KMS keys, redirects and stale bucket-name reuse.
2. Build the complete authorization matrix for every action under wildcard, global-condition and region constraints, including mismatched/foreign IDs.
3. Validate whether service-linked-role creation is consistently authorized before every API that needs it and whether deletion/recreation races cross assessment boundaries.
4. Inspect the current collector's on-disk encryption, file modes, Docker mounts, backup/snapshot exposure, credential rotation behavior and removal after reconfiguration.
5. Test collector registration and message protocols for stale registration, ID substitution, replay, cross-account routing and authorization after credential rotation.
6. Test `secretsManagerKey` substitution with researcher-owned secrets and databases for cross-account Secret ARN validation, stale access, version-stage selection, KMS context and confused-deputy controls.
7. Validate source repository/project/branch binding, path traversal, malicious archive handling and whether attacker-controlled repository content can escape the analysis sandbox.
8. Exercise import parser boundaries (duplicate IDs, Unicode, oversized/nested input, number coercion, ZIP/archive cases if supported, task replay and conflicting imports) without persistent customer data.
9. Capture successful CloudTrail shapes for every write and verify whether bucket names, source-code locations, secret ARNs and strategy changes are logged or redacted.
10. Test assessment start/stop and recommendation-report generation races, idempotency and stale output access after stopping or deleting the service-linked role.
11. Validate isolation among Application Discovery Service, manual-import and collector data sources when identifiers collide.
12. Test VPC endpoint policies and private-DNS behavior for collector-only/internal operations, including whether public and private endpoints enforce identical authorization.
