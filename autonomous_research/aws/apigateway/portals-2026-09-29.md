# API Gateway Portals boundary audit — 2026-09-29

## Scope and inventory

- Read-only inventory covered `us-east-1` and `eu-west-1`, including the service's continuation-token pagination behavior.
- The account contained no portals or portal products in either allowed Region.
- Signed synthetic getters reached API Gateway and returned `NotFoundException`; unsigned management requests returned `MissingAuthenticationTokenException`.
- No API Gateway, Cognito, RAM, IAM, or test application resources were created or modified.

## Publishable expected-functionality techniques

| Surface | Boundary | Impact / limits |
| --- | --- | --- |
| `UpdatePortal` authorization to `None`, then `PublishPortal` | Exact-portal `apigateway:UpdatePortal` and `apigateway:PublishPortal`, plus dependent `GetPortalProduct` on included products | Makes the published documentation/catalog public. Does not weaken the documented APIs' own authorization. |
| Public portal browsing and **Try it** | Known published public/custom domain; **Try it** enabled for a supported public REST endpoint | Unauthenticated API-documentation recon. **Try it** retains endpoint authorization and does not support private, mTLS, or private/self-signed-certificate APIs. |
| Cognito portal self-registration | Portal uses a user pool whose chosen settings permit external self-service sign-up | Conditional authenticated portal foothold; not an IAM identity and not API authorization bypass. |
| PortalProduct AWS RAM share | Owner can manage the share and `PutPortalProductSharingPolicy`; external recipient normally accepts | Read-only documentation exfiltration into a recipient portal. No source API mutation, invocation grant, or re-sharing. |

The live default RAM permission was inspected and contained only the five documented product/page read actions. The Service Authorization Reference lists exact Portal and PortalProduct resource types. Portal mutation additionally depends on `GetPortalProduct` for included products; it does not depend on Cognito administration or `iam:PassRole`.

## Telemetry

- Signed synthetic portal reads generated default management events from `apigateway.amazonaws.com`.
- Authorization update and publication are expected management writes and leave a durable externally visible state change.
- RAM share lifecycle is represented by RAM management events and durable resource/principal associations. External acceptance is normally a separate recipient-side event; same-organization sharing may auto-accept.
- Portal browsing is web/data-plane activity rather than an API Gateway control-plane event. Optional RUM, edge/web, WAF, API stage, backend, and Cognito telemetry cover different parts of the flow.
