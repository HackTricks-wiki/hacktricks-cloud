# Amazon CodeGuru Profiler security audit — 2026-09-27

## Scope and constraints

- Service: `codeguruprofiler` (Amazon CodeGuru Profiler).
- Focus: lifecycle/availability, enumeration, profile confidentiality/integrity, agent APIs, resource policies, notifications, cross-account behavior, unauthenticated access, IAM resource scoping, and CloudTrail stealth.
- Authorized live account: assumed `arn:aws:iam::228478051196:role/ChackBotAdministratorRole` from the `hacktricks-training` profile.
- No cluster, compute workload, long-running agent, SNS topic, trail, or other chargeable infrastructure was provisioned.
- Temporary profiling groups were short-lived and empty except for one accepted synthetic profile. Temporary IAM roles had no identity policy and were deleted in the same guarded test scripts.
- No `SUMMARY.md`, status file, stable PR worktree, commit, push, or PR was touched.

## Existing coverage and lifecycle

- Repository search found no pre-existing CodeGuru Profiler enum, post-exploitation, persistence, privilege-escalation, or unauthenticated page.
- The service remains available. Current AWS product, pricing, API, CLI, IAM Service Authorization Reference, User Guide and CloudTrail documentation are live as of the audit date.
- Pricing is based on agent sampling hours. Tests used either disabled groups or enabled groups for seconds with no running workload. One one-minute synthetic profile was accepted, after which the group was immediately deleted.

## Current API and IAM surface

AWS CLI 2.34.45 exposes:

- groups/configuration: `CreateProfilingGroup`, `DeleteProfilingGroup`, `DescribeProfilingGroup`, `ListProfilingGroups`, `UpdateProfilingGroup`;
- profiles/data: `GetProfile`, `ListProfileTimes`, `BatchGetFrameMetricData`, `GetRecommendations`, `ListFindingsReports`, `GetFindingsReportAccountSummary`, `SubmitFeedback`;
- agent plane: `ConfigureAgent`, `PostAgentProfile`;
- resource policy: `GetPolicy`, `PutPermission`, `RemovePermission`;
- notifications: `AddNotificationChannels`, `GetNotificationConfiguration`, `RemoveNotificationChannel`;
- tags: `ListTagsForResource`, `TagResource`, `UntagResource`.

Current SAR resource model:

```text
arn:aws:codeguru-profiler:<region>:<account>:profilingGroup/<name>
```

- `ListProfilingGroups` and `GetFindingsReportAccountSummary` have no resource type in the current SAR and require `Resource: "*"`.
- All other service actions support/require the profiling-group resource.
- Resource tag conditions apply to group actions; request-tag/tag-key conditions apply to create.
- The current SAR omits a resource type for `CreateProfilingGroup`, but a role holding only `CreateProfilingGroup` on the exact future group ARN successfully created that group. This agrees with the AWS-managed agent policy and older Profiler permissions-reference page. Public documentation records the verified exact-ARN behavior and the SAR documentation drift.

## Sensitive data model

- `GetProfile` returns aggregated JSON or Amazon Ion profile data.
- Captured stack traces contain function/method names and their callers. Official data-protection documentation explicitly says the agent does not access parameter names/values, variable values or application data.
- Practical disclosure: private package/class/function names, call relationships, hot paths, and agent-dependent file/line details. Not a raw memory/secret dump.
- Retention: five-minute profiles 15 days, hourly profiles 60 days, daily profiles three years. `GetProfile` request window is at most seven days.
- Minimum known-group read: `codeguru-profiler:GetProfile` on the exact group ARN. `ListProfileTimes` and `ListProfilingGroups` are optional discovery only.

## Hypotheses and outcomes

| Hypothesis | Result | Publication decision |
| --- | --- | --- |
| `GetProfile` leaks internal code structure and execution paths | High-confidence from API/data-protection docs; exact ARN scoping confirmed by SAR | Published as post-exploitation with explicit no-arguments/no-values limitation |
| `PostAgentProfile` accepts attacker-chosen stack names/sample counts and can poison profiles | Verified: an uncompressed official-schema JSON body returned HTTP 204 on an enabled disposable group | Published as profile-integrity post-exploitation |
| `ConfigureAgent` leaks agent orchestration settings | Verified: returned `shouldProfile`, period, sampling/reporting intervals, max stack depth and memory-use limit | Kept in enum; too low impact for a standalone attack |
| `PutPermission` can authorize a role that has no identity policy | Verified: the role was denied before the grant and `ConfigureAgent` succeeded after `agentPermissions` was added | Published as narrow profiling-group persistence |
| `PutPermission` grants profile read/admin privileges | Rejected: the only action group expands solely to `ConfigureAgent` and `PostAgentProfile` | Not published as privesc |
| Direct cross-account resource-policy persistence | Existing cross-account IAM user ARN was rejected with `ValidationException: Invalid PrincipalArns`; source-account call before any grant also resolved a group ARN in the source account. Cross-account role was not tested because no safe existing source-account role was available | Not claimed. Public persistence page explicitly limits the verified result to same-account principals |
| Wildcard/public principal grants | Rejected by documented/API principal validation; explicit role/user ARNs only | No unauthenticated technique |
| Unsigned enumeration or group probing | `ListProfilingGroups --no-sign-request` returned `MissingAuthenticationTokenException` | No unauthenticated page |
| Notification-channel takeover/exfiltration | API can add up to two SNS anomaly channels; first configuration can create `AWSServiceRoleForCodeGuruProfiler`. It carries anomaly notifications, not raw profile data, and delivery depends on an existing usable SNS topic/role boundary | Excluded as a standalone attack: limited impact and would require an SNS/SLR fixture that was not justified |
| `UpdateProfilingGroup` as persistence | Only toggles profiling enablement | Excluded; sabotage/availability, not persistence |
| `DeleteProfilingGroup` as useful technique | Destructive denial of visibility/data | Excluded as obvious deletion, not a distinct high-value technique |
| Managed agent policy creates groups | `AmazonCodeGuruProfilerAgentAccess` includes broad `CreateProfilingGroup` plus agent actions | Published as an enum least-privilege warning, not privesc |
| `CreateProfilingGroup` must use `Resource: "*"` as implied by current SAR | Rejected: exact future profiling-group ARN succeeded under a role with no other permissions | Published as exact scoping guidance; tracked as beneficial documentation drift, not a vulnerability |
| Compressed JSON agent profile | Two gzip-body attempts returned service HTTP 500. Source review then showed the actual SDK reporter instantiates `ProfileEncoder(..., gzip=False)` despite the encoder class supporting gzip | Negative format result; no vulnerability report |

## Live evidence

### Inventory and unauthenticated boundary

- Source identity: `arn:aws:iam::418720621023:user/chack-bot`.
- Assumed target identity: `arn:aws:sts::228478051196:assumed-role/ChackBotAdministratorRole/...`.
- Initial `us-east-1` and `eu-west-1` inventories were empty.
- Unsigned listing failed with `MissingAuthenticationTokenException`.

### Resource-policy authorization

Disposable group `ht-cgp-audit-20260927b` was created with profiling disabled. Disposable role `arn:aws:iam::228478051196:role/ht-cgp-audit-agent-20260927` had only a trust policy and no identity permissions.

1. Before the group policy, `ConfigureAgent` was denied because no identity policy allowed it.
2. `PutPermission --action-group agentPermissions` returned a policy granting exactly:
   - `codeguru-profiler:ConfigureAgent`
   - `codeguru-profiler:PostAgentProfile`
3. After the grant, the no-policy role's `ConfigureAgent` succeeded and returned `shouldProfile: false`.
4. After `RemovePermission`, the same call was denied again.
5. The group and role were deleted.

A second enabled group returned:

```json
{
  "shouldProfile": true,
  "periodInSeconds": 300,
  "agentParameters": {
    "SamplingIntervalInMilliseconds": "1000",
    "ReportingIntervalInMilliseconds": "300000",
    "MinimumTimeForReportingInMilliseconds": "60000",
    "MemoryUsageLimitPercent": "10",
    "MaxStackDepth": "1000"
  }
}
```

IAM-to-CodeGuru principal propagation took two failed `PutPermission` attempts before the new role ARN was accepted. This is expected eventual consistency, not a defect.

### Cross-account negative result

On disabled group `ht-cgp-audit-20260927`, adding the existing principal `arn:aws:iam::418720621023:user/chack-bot` failed with `ValidationException: Invalid PrincipalArns in the request`. The pre-grant source-account `ConfigureAgent` failure referenced a source-account profiling-group ARN, confirming that the name-only API resolved in the caller's account before a valid policy relationship existed.

This is enough to reject a cross-account-user claim, but not to assert that every cross-account role form is impossible. No source-account IAM resource was created because the authorized administrative scope was the target account.

### Telemetry poisoning

- Disabled group + gzip JSON: HTTP 500.
- Enabled group + gzip JSON: HTTP 500.
- Enabled group `ht-cgp-audit-20260927f` + uncompressed JSON matching the official Python agent schema: `PostAgentProfile` returned success with an empty HTTP 204 response.
- The accepted call graph contained synthetic `PaymentController:handleSecretRequest` and `TokenProcessor:validateToken` frames, file paths, line numbers and an attacker-selected `WALL_TIME` count.
- The immediate `ListProfileTimes` follow-up used the wrong local CLI enum (`Timestamp` instead of `TimestampAscending`/`TimestampDescending`) and was rejected before any meaningful aggregation observation. This does not affect verification that the service accepted the profile for aggregation; the PostAgentProfile API definition states accepted data is aggregated.
- The group was deleted by the cleanup trap immediately after that validation error.

### Create resource scoping

- Temporary role `ht-cgp-create-scope-20260927` had only `codeguru-profiler:CreateProfilingGroup` on `arn:aws:codeguru-profiler:us-east-1:228478051196:profilingGroup/ht-cgp-scope-20260927`.
- Its session successfully created that exact disabled group without `Resource: "*"` and without any other permission.
- The administrator deleted the group; the inline policy and role were deleted immediately afterward.
- This is least-privilege-positive behavior, not a security vulnerability, but it contradicts the current SAR resource-type table.

### CloudTrail

- No account trails existed, so no CodeGuru Profiler data-event selector was active.
- Event History showed management events for `CreateProfilingGroup`, `DeleteProfilingGroup`, `DescribeProfilingGroup`, `ListProfilingGroups`, `GetPolicy`, `PutPermission`, and `RemovePermission`.
- `PutPermission` request parameters recorded `principals`, `actionGroup` and group name; the response recorded the resulting policy and revision.
- `ConfigureAgent` and `PostAgentProfile` were absent, matching official documentation: they are data events and are not logged by default.
- Required selector resource type: `AWS::CodeGuruProfiler::ProfilingGroup`.

## Notification and role-vending review

- `AddNotificationChannels` supports one or two existing SNS topic ARNs and only the `AnomalyDetection` publisher.
- The first notification configuration can cause CodeGuru Profiler to create its service-linked role automatically. This is expected service behavior; no caller-supplied execution role or `iam:PassRole` path exists.
- Because the channel carries anomaly notifications rather than raw profiles, and a working SNS/SLR setup was not needed to validate higher-value techniques, no live notification mutation was performed.
- `ConfigureAgent` returns configuration only; it does not vend AWS credentials or a role session.
- No credential-vending, confused-deputy or IAM privilege-escalation path was identified.
