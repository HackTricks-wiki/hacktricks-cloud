# AWS Free Tier API audit — 2026-10-01

## Result

Published the missing `freetier` service inventory and a conditional but high-impact expected attack: wildcard-only `freetier:UpgradeAccountPlan` can irreversibly convert a new Free-plan account to Paid, removing the plan's no-charge/service-access boundary and allowing usage beyond credits to become billable.

The API does not grant IAM permissions or launch a workload. The financial impact requires existing or later target-service activity, and a direct manual/API upgrade normally preserves eligible remaining credits until their separate expiration. This is documented functionality, not an AWS vulnerability; no private report was created.

## Service surface

- API/IAM/signing prefix: `freetier`.
- Operations: `GetAccountPlanState`, `ListAccountActivities`, `GetAccountActivity`, `GetFreeTierUsage`, and `UpgradeAccountPlan`.
- All actions require `Resource: "*"`; there are no Free Tier resource ARNs or service-specific condition keys.
- `GetAccountPlanState` returns account ID, `FREE`/`PAID`, plan status, remaining USD credits and expiration.
- Activity APIs expose credit-earning task status, reward, deadlines, completion time, instructions and URL.
- `GetFreeTierUsage` exposes qualifying service, operation, Region, usage type, actual/forecast usage, allowance and unit.
- `GetFreeTierAlertPreference` and `PutFreeTierAlertPreference` are permission-only console actions. Their backing console request remains a separate follow-up; no unsupported public API was invented.

## Authorization checks

A disposable IAM user with only these current read actions successfully listed activities and called the usage API:

```text
freetier:GetAccountPlanState
freetier:GetAccountActivity
freetier:ListAccountActivities
freetier:GetFreeTierUsage
```

The plan getter passed IAM and returned service-level `ResourceNotFoundException`; the activity and usage calls returned empty successful lists. `GetFreeTierUsage` succeeded without `aws-portal:ViewBilling`, despite the legacy action's adjacent row in the current Service Authorization Reference. Adding it did not change the result.

A separate disposable user with only:

```text
freetier:UpgradeAccountPlan on Resource "*"
```

called `UpgradeAccountPlan(PAID)` and reached `ResourceNotFoundException`, proving it passed IAM without Billing, Organizations, Account, IAM or target-service permissions. The training account predates the enhanced account-plan system, so this was a safe non-mutating state check rather than a successful irreversible conversion. A no-policy attempt immediately after key creation returned `UnrecognizedClientException` because the new key had not propagated; it is inconclusive and not treated as an authorization result.

## Documented impact and boundaries

AWS documentation establishes that:

- the Free plan incurs no charges while active, restricts selected services/features, and closes when six months pass or credits are exhausted;
- the Paid plan allows all services, continues beyond credit exhaustion and bills eligible usage beyond credits;
- a customer can upgrade at any time;
- the Paid plan cannot be downgraded to Free; and
- unused credits normally continue to apply after a direct upgrade until their own expiration.

The exception is an automatic upgrade caused by joining Organizations or setting up Control Tower, which AWS documents as immediately expiring Free Tier credits. The direct `UpgradeAccountPlan` API is not described as that path and should not be claimed to erase credits.

The attack is therefore post-exploitation/financial defense impairment, not privilege escalation: it can unlock services for permissions already held and remove the no-charge cap, but it does not create IAM authority.

## Telemetry

Live Event History showed `freetier.amazonaws.com` management events in `us-east-1`. Calls made with both `us-east-1` and `eu-west-1` CLI Regions were centralized there.

| Event | Observed behavior |
| --- | --- |
| `UpgradeAccountPlan` | `readOnly:false`; recorded the restricted IAM user and `accountPlanType:"PAID"`; failed response preserved the `ResourceNotFoundException` |
| `GetAccountPlanState` | `readOnly:true`; failed state and message recorded |
| `ListAccountActivities` | Successful management read; input recorded and `responseElements:null` |
| `GetFreeTierUsage` | Successful management read; input recorded and `responseElements:null` |

The write is Low stealth because the account plan visibly changes and the default management event contains the intended target. Subsequent resource use and charges retain independent evidence.

## Negative and deferred candidates

| Candidate | Result | Disposition |
| --- | --- | --- |
| Downgrade Paid to Free for rollback | AWS states that Paid cannot be downgraded | Secure/irreversible boundary |
| Upgrade grants service permissions | It changes eligibility/charging, not IAM | Not privilege escalation |
| Direct upgrade immediately destroys remaining credits | AWS says remaining credits normally continue after direct upgrade | Negative; do not overstate impact |
| Read another account by ID | APIs have no account-ID selector or resource policy | Negative |
| `aws-portal:ViewBilling` required for usage API | Current Free Tier action alone succeeded | Legacy action not required in live test |
| Redirect/suppress Free Tier alert preference | Permission-only console actions exist, but no public API was tested | Deferred console-workflow research |
| Activity-ID cross-account access | No enrolled activity fixture existed | Deferred; low expected value because calls use caller account context |

## Cleanup

Both disposable IAM access keys, inline policies and users were deleted. Final IAM inventory returned no `ht-freetier-*` users. `GetAccountPlanState` still returned the original `ResourceNotFoundException`; the test did not create or change an account plan. No workload, organization membership, credit activity, billing preference or paid resource was created.
