# SageMaker Amazon Augmented AI Runtime audit — 2026-09-30

## Result

Added the missing Amazon Augmented AI (A2I) human-review inventory and a scoped post-exploitation path for resolving and reading a completed loop's sensitive S3 output. Exact-loop authorization and management-event telemetry were verified live. The current account is not an existing A2I customer, so no flow, loop, workforce, task UI, role, bucket or paid human task was created.

## API and data model

- Runtime service/API: `sagemaker-a2i-runtime` / `2019-11-07`; endpoint prefix `a2i-runtime.sagemaker`; SigV4 signing and IAM namespace `sagemaker`.
- Runtime operations: `StartHumanLoop`, `ListHumanLoops`, `DescribeHumanLoop`, `StopHumanLoop`, and `DeleteHumanLoop`.
- Control-plane resources live in the ordinary SageMaker API: flow definitions, human task UIs, workforces and workteams.
- `StartHumanLoop` accepts up to 3 MiB of JSON input and a flow-definition ARN. A custom task starts a human review on every accepted invocation.
- `ListHumanLoops` is wildcard-only and requires a known flow-definition ARN. It returns loop name, status, creation time, flow ARN and failure reason.
- `DescribeHumanLoop` supports `arn:aws:sagemaker:<region>:<account>:human-loop/<name>` resource scoping. A completed loop exposes `HumanLoopOutput.OutputS3Uri`.
- The output object can include original input, upstream AI service request/response, activation-condition results, human answers, submission details and private-workforce metadata. S3/KMS authorization remains independent.

## Live inventory and customer boundary

Read-only inventory in both `us-east-1` and `eu-west-1` returned zero flow definitions, human task UIs and workteams.

A reversible eligibility probe attempted to create only a harmless standalone task UI in `us-east-1`. The first local CLI-shorthand attempt never reached AWS. The correctly encoded request reached SageMaker and failed with `ValidationException: Amazon Augmented AI is no longer accepting new customers.` Exact describe and final list checks found no task UI. No workforce, review flow or human loop was attempted.

## Exact-resource authorization

Three temporary STS sessions/calls used synthetic names only:

1. A session policy allowing only `sagemaker:DescribeHumanLoop` on exact synthetic loop A reached the service and returned `ResourceNotFoundException`.
2. The same session was denied synthetic loop B and the denial named B's exact human-loop ARN.
3. A control session without `DescribeHumanLoop` was denied loop A.

This verifies exact-loop minimum authorization without creating a loop. It does not prove the content of a successful response, which follows the public API/output contract.

## Attack matrix

| Idea | Result / boundary | Disposition |
| --- | --- | --- |
| Resolve and read completed review output | `DescribeHumanLoop` provides the exact timestamped object URI; `s3:GetObject` and optional `kms:Decrypt` remain separately required. Output contains sensitive inputs and answers. | Published as post-exploitation data access |
| Enumerate loop names | `ListHumanLoops` is wildcard-only but needs each flow ARN; it exposes names/status/failure reasons, not output bodies. | Foundational enumeration |
| Spam/cost abuse through `StartHumanLoop` | Can create reviewer work for attacker-supplied data on an existing flow, but mainly cost/queue DoS and not a new data boundary. | Excluded as low-value/DoS |
| Inject secrets from another AWS resource into a loop | `StartHumanLoop` accepts only caller-supplied input; it does not fetch arbitrary AWS data for the caller. Any source read is a separate permission. | Rejected |
| Stop/delete active loops | Can disrupt review or remove loop metadata but does not delete the independent output S3 object or erase CloudTrail. | Excluded as DoS/anti-forensics too weak |
| Worker-UI script/template injection through loop input | Depends on the customer-authored task template and escaping context. No existing flow/customer fixture was available. | Retain as fixture-dependent private hypothesis; do not publish |
| Cross-account loop access | No A2I resource policy/share mechanism was found; exact account ARN scope applies. | Secure boundary |

## Telemetry

CloudTrail Event History indexed all exact-resource controls within minutes as default read-only `sagemaker.amazonaws.com` `DescribeHumanLoop` management events.

- `requestParameters` contained the full synthetic `HumanLoopName`.
- `userIdentity.arn`, Region, source IP and user agent identified the caller.
- `responseElements` was null for not-found and denied calls.
- `errorCode` distinguished `ResourceNotFoundException` and `AccessDenied`; `errorMessage` was null.
- No `resources` array was populated in these failed events.

The later `GetObject` is an S3 data event and absent from default trails unless the bucket/prefix is selected. A customer-managed KMS decrypt creates the ordinary KMS cryptographic event.

## Cleanup

The valid task-UI request failed before creation, and the deletion trap was still executed. Exact task-UI describe returned `ResourceNotFound`; filtered final task-UI inventory was empty. Both Regions retained zero flow definitions, task UIs and workteams. Synthetic loop describes cannot create state. All test identities were temporary STS sessions. No S3, KMS, Cognito, IAM, workforce, Mechanical Turk, EventBridge or logging resource was created, and no private AWS vulnerability report was opened.
