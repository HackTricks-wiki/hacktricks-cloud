## Live minimum-permission results

### Unsigned baseline

An unsigned `SearchAgreements` request returned `AccessDeniedException`. No victim-specific identifier-only anonymous API was found.

### Search-only agreement session

Allowed:

```json
{"Effect":"Allow","Action":"aws-marketplace:SearchAgreements","Resource":"*"}
```

Explicitly denied `aws-marketplace:ViewSubscriptions`, `DescribeAgreement`, and `GetAgreementTerms`.

- `PartyType=Acceptor` plus `AgreementType=PurchaseAgreement`: success, zero results.
- `PartyType=Proposer` plus `AgreementType=PurchaseAgreement`: success, zero results.
- A PartyType-only request failed `ValidationException`; that unsupported filter combination was retained as a negative control.

This proves the direct Agreement API read is independent from the broader console-oriented `ViewSubscriptions` action.

### Catalog list-only session

Allowed `aws-marketplace:ListEntities` and `ListChangeSets`; explicitly denied `DescribeEntity` and `StartChangeSet`.

`ListEntities` with `OwnershipType=SELF` succeeded and returned zero for:

- `AmiProduct`
- `ContainerProduct`
- `SaaSProduct`
- `DataProduct`
- `Offer`
- `ResaleAuthorization`

`ListChangeSets` returned a validation error in the non-seller/empty context and was not used as live evidence beyond endpoint/auth reachability.

### Procurement dashboard session

Allowed only `aws-marketplace:GetBuyerDashboard` on:

```text
arn:aws:aws-marketplace::228478051196:AWSMarketplace/ReportingData/*
```

Both documented dashboard identifiers were tested with a synthetic HTTPS embedding domain:

- `Agreement_V1/Dashboard/AgreementSummary_V1`
- `BillingEvent_V1/Dashboard/CostAnalysis_V1`

Both returned `UnauthorizedException`, consistent with the account not being an organization management account/delegated administrator registered for procurement insights. No URL was returned or redeemed. The technique remains official, useful functionality for qualifying accounts.

## High-value expected techniques promoted

1. Agreement/terms/entitlement/charge/invoice reads, including the documented 30-minute SaaS registration token.
2. `GetBuyerDashboard` creating a five-minute one-time bearer URL and one-hour anonymous procurement-insights session.
3. Seller `GetEntitlements` mapping customer identifiers, license/dimension/capacity and expiration/renewal state.
4. Commerce Analytics dataset/support-contact materialization to an existing authorized S3 destination.
5. `StartChangeSet` seller product/delivery/offer supply-chain changes and private-marketplace procurement/audience manipulation.
6. Direct Catalog `PutResourcePolicy` sharing read/write entity control cross-account immediately without consumer acceptance or discoverability.
7. Durable paid subscription/agreement and renewal abuse with explicit warning against live testing.

## Ideas investigated but not promoted

| Idea | Result |
|---|---|
| Public product ID as victim agreement access | Rejected; victim agreement/reporting APIs require authenticated authorization |
| Marketplace write as general AWS-admin privesc | Rejected; impact is service/commercial/supply-chain scoped unless a separately deployed product or role adds another path |
| `GetEntitlements` without product code | Rejected; product code is required and seller access is necessary |
| Commerce export directly to any attacker bucket with only API permission | Not claimed; delivery is bounded by seller enrollment and the supplied role/bucket/KMS/topic policies |
| Dashboard URL as indefinitely reusable secret | Rejected; token is one-time, redeemable for five minutes, with a one-hour session and embedding-domain constraint |
| Catalog direct share discoverable in consumer inventory | Rejected; official docs explicitly say direct policy shares do not appear under `OwnershipType=SHARED` |
| Product subscription automatically executes code | Rejected; subscription/agreement and deployment/launch are distinct steps |

## Detection notes

- Live `SearchAgreements` events appeared under `agreement-marketplace.amazonaws.com` with `readOnly=true`, `managementEvent=true`, the complete catalog/filter/max-results request, and no response body.
- Live successful `ListEntities` events appeared under `marketplacecatalog.amazonaws.com` with `readOnly=true`, `managementEvent=true`, entity type, ownership type, filters/sort and max results, and no response body.
- Live denied `GetBuyerDashboard` events appeared under `reporting-marketplace.amazonaws.com` with `readOnly=true`, `managementEvent=true`, dashboard ARN and embedding domains, and `UnauthorizedException` or throttling error. No bearer URL response existed in this account, so successful response redaction remains backlog.
- Agreement API purchase, cancellation and read operations integrate with CloudTrail; AWS specifically documents `AcceptAgreementRequest`, `CancelAgreement`, `DescribeAgreement`, `GetAgreementTerms`, and `SearchAgreements` events.
- Catalog documentation states all Catalog API calls, including Management Portal calls, are CloudTrail events.
- Commerce Analytics exports create an API request, service-role activity, S3 CSV/metadata objects and an SNS notification.
- Private Marketplace emits EventBridge events for user requests and approval/decline workflow.
- The audit's read-only calls arrived after a short Event history delay; exact observed fields above supplement the official integration documentation.
