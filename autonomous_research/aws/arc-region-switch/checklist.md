# arc-region-switch — checklist (potential, not yet done)
- [x] UpdatePlan step-injection: RESOLVED -> executionRole is REQUIRED so PassRole IS enforced every call (verified two-sided). NOT PassRole-free. Documented on wiki.
- [x] crossAccountRole + externalId: mapped from current official docs. ARC first assumes the plan's executionRole; the executionRole must have `sts:AssumeRole` on the target crossAccountRole. The target role trusts the execution-role account/principal and requires the configured external ID — it does not directly trust `arc-region-switch.amazonaws.com`. ARC validates role assumption, target permissions, and the external ID before execution. No second-account live fire was needed to resolve the contract.
- [ ] StartPlanExecution authorization: any resource-policy / tag condition, or is action-only enough on any plan in the account?
- [x] associatedAlarms/triggers: yes, documentation-grounded. CreatePlan and UpdatePlan accept associated alarms plus triggers; a trigger automatically starts plan execution when its alarm conditions transition to the configured red/green state. A condition already satisfied when attached does not immediately execute, so an attacker needs a later transition (and any separate ability required to cause it). This provides delayed/autonomous execution without a later attacker `StartPlanExecution` call, but creating/updating the plan still requires PassRole on its required executionRole. Not live-fired because a real plan execution is intentionally disruptive.
