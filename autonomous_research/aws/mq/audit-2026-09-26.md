## Least-privilege probe record

A disposable IAM user was used to probe fake known identifiers with policies scoped to the documented resource formats. Calls to `CreateUser`, `UpdateUser`, `UpdateConfiguration`, `UpdateBroker`, and `RebootBroker` returned `AccessDenied` rather than reaching a not-found validation boundary. This does **not** falsify the documented resource-level permissions: Amazon MQ could not resolve the invented resource identifiers, and the initial configuration policy also used an incorrect name-bearing ARN before the Service Authorization Reference format (`configuration:<configuration-id>`) was confirmed. The probes are therefore recorded as inconclusive and are not represented in the book as live verification.

Exact documented resource formats retained for future testing:

- Broker: `arn:aws:mq:<region>:<account>:broker:<broker-name>:<broker-id>`
- Configuration: `arn:aws:mq:<region>:<account>:configuration:<configuration-id>`

## Telemetry conclusions

- Amazon MQ control-plane calls (`CreateUser`, `UpdateUser`, `UpdateConfiguration`, `UpdateBroker`, and `RebootBroker`) are CloudTrail management writes.
- ActiveMQ Web Console and messaging-protocol actions are not Amazon MQ control-plane CloudTrail events; use broker and network logging for data-plane visibility.
- RabbitMQ's native management HTTP API does not call the Amazon MQ AWS API and therefore produces no Amazon MQ CloudTrail event. RabbitMQ inventory and optional broker/management/network logs are the relevant evidence.
- `mq:UpdateBrokerAccessConfiguration` is a permission-only gate evaluated during an auth-changing `UpdateBroker`; it has no independent API event. External IdP token minting and token-backed RabbitMQ traffic are also outside Amazon MQ CloudTrail.
