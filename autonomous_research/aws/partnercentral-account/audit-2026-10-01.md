# Partner Central Account API audit — 2026-10-01

## Result

Added the missing `partnercentral-account` inventory and two expected post-exploitation read paths:

1. wildcard-resource `partnercentral:GetVerification` can recover verification state, business registration details and a time-limited completion URL from an existing business or registrant workflow;
2. exact Partner/connection/invitation reads recover alliance contact PII, verified training domains, related AWS account IDs, invitation content and qualification association topology.

## Control plane

- Current client/API model: `partnercentral-account` / `2025-04-04`.
- IAM prefix: `partnercentral`.
- CloudTrail source: `partnercentral-account.amazonaws.com`.
- Live endpoint: `partnercentral-account.us-east-1.api.aws`; `eu-west-1` had no reachable endpoint.
- Unsigned requests fail with `MissingAuthenticationTokenException`.
- Cataloged resources use `AWS` and `Sandbox`; verification takes `BUSINESS_VERIFICATION` or `REGISTRANT_VERIFICATION` instead of a catalog parameter.

The API exposes 34 operations covering Partner creation/profile/contact, training-domain association, connections/invitations/preferences, qualification association/disassociation, and verification.

## Live inventory and IAM results

Both catalogs returned empty Partner, connection, and invitation lists. `GetConnectionPreferences` returned the default `ALLOW_ALL` state and revision for both catalogs; it was not mutated. Both verification types returned `ResourceNotFoundException`, confirming that the account has no active workflow.

A disposable restricted IAM principal established:

- `GetVerification` requires `Resource: "*"`; an exact synthetic Partner ARN failed IAM.
- `partnercentral:VerificationType=BUSINESS_VERIFICATION` reached the service for business verification and denied registrant verification.
- the successful authorization stage needs no Partner list/get or other Partner Central action.

The response model/documentation establishes that a real workflow can return business legal name, registration ID, country/jurisdiction, status/reason, timestamps, and a completion URL. No active workflow or URL was created to test downstream provider authentication.

## Deferred write hypotheses

These remain queued rather than padded into the book:

- `PutAllianceLeadContact`: email-verification code is optional in the model, but whether changing the email without a code is accepted needs an enrolled disposable Partner.
- `StartProfileUpdateTask`: could poison public name/description/website/logo for phishing, but asynchronous review/approval behavior needs a reversible enrolled fixture.
- `StartQualificationsAssociationTask` / `StartQualificationsDisassociationTask`: could move qualification ownership across Partner profiles/accounts, but business approval, reversibility and delete/undo behavior are not yet proven.
- `CreateConnectionInvitation`: can send an AWS-branded custom invitation to a supplied email, but testing requires a consenting second Partner and recipient; low-value spam alone does not meet the public-book threshold.
- `UpdateConnectionPreferences`, invitation acceptance/rejection/cancellation and `CancelConnection`: expected relationship disruption, but no disposable Partner relationship existed and the empty-account default was not mutated.
- `StartVerification`, `CreatePartner`, training-domain association and email-code delivery were not invoked because they create onboarding/external-message state that cannot be guaranteed clean in this account.

## Telemetry

Live `GetVerification` calls appeared as default `us-east-1` management reads with `eventSource: partnercentral-account.amazonaws.com`, `readOnly:true`, caller identity and `requestParameters.verificationType`. IAM-denied events used `requestParameters:null`; calls that passed IAM and reached the missing-workflow check retained the requested type.

## Cleanup

All disposable IAM users, inline policies and access keys were deleted. Final `ht-pca-*` IAM user/role inventories were empty. No Partner Central resource, verification, email, invitation, relationship, task, tag, profile, domain association or preference was created or changed.
