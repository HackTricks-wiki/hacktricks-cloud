## Current API surface

AWS CLI `2.34.45` exposed 29 operations from service model `supplychain-2024-01-01`:

- Instance: create, update, get, list, delete, tags.
- Data lake: create/update/get/list/delete namespaces and datasets.
- Data integration: create/update/get/list/delete flows; get/list executions; send/get/list integration events.
- Bill of materials: create and get import jobs (no list operation).

The current service authorization reference additionally exposed console-only actions absent from the public CLI model:

- `AssignAdminPermissionsToUser`
- `RemoveAdminPermissionsForUser`
- `ListAdminUsers`
- `CreateSSOApplication`
- `DeleteSSOApplication`
- `DescribeInstance`

The federated browser application has a separate, much larger internal action surface that is absent from the public SDK/CLI and Service Authorization Reference. Official pages list user/role/chat operations (`AssociateUser`, `AssignGalaxyRoleToUser`, `ListChatMessages`), data-lake operations (`CreatePresignedUrl`, connection/dataflow management), full Demand Planning exports, numerous Supply Planning reads/updates/exports, and Amazon Q message operations. These are authorized by Supply Chain application roles rather than IAM policies.

The service has no general resource-policy API. Cross-account SCN administration therefore uses a role in the owner account. S3/KMS policies and organization IAM Identity Center remain downstream/cross-account trust boundaries.

The `SendDataIntegrationEvent` probe did **not** appear in Event History while the adjacent management probes did. The account had no trail or event data store. This matches AWS documentation that Supply Chain instance data activity uses CloudTrail data events (`AWS::SCN::Instance`), which are disabled by default and absent from Event History.

AWS's legacy documentation conflicts on web application logging. The monitoring page says web APIs are data events, but the web-application API overview says those internal actions are not visible in CloudTrail. The current CloudTrail catalog does expose `AWS::SCN::Instance`, plus newer SCN business-rule/metric/outcome resource types. Successful tenant testing is required before claiming complete coverage. Console-only control-plane APIs are documented as captured under `scn.amazonaws.com`.

## Strong expected attacks accepted

1. Read instance, KMS, web-domain, schema, S3/prefix, SQL, execution/diagnostic and event metadata through exact resource-scoped read APIs.
2. Create or replace a dataset-to-S3 SQL flow as a durable export primitive, bounded by the existing instance role's S3 access.
3. Poison or delete dataset records through exact-instance `SendDataIntegrationEvent` using `APPEND`, `UPSERT` or `DELETE` without dataset-definition write permission.
4. Persistently redirect/corrupt future integration by replacing an existing flow's source, SQL, target, load or dedupe configuration.
5. Poison `product_bom` through a BOM import job when a crafted CSV is already readable by the instance role.
6. Delete exact flows/datasets/namespaces or an entire instance; custom KMS key disable/delete is a separate high-impact dependency attack.
7. Escalate/persist as a Supply Chain application administrator through `scn:AssignAdminPermissionsToUser` on one instance. This is explicitly service-level, not AWS-account/IAM escalation.
8. Use a permitted web-app export to retrieve complete demand/supply planning data. Demand-plan CSV export ignores active UI filters by design.
9. Read Insights chat messages as any associated instance user even without permission to the corresponding Insight, as explicitly documented by AWS.
10. Treat `CreatePresignedUrl` results from the internal data-lake workflow as bearer capabilities and capture/revoke them appropriately.
11. Conditionally retarget an ERP/SAP connection so the instance role uses an otherwise unreadable Secrets Manager credential against a controlled endpoint. This is expected delegated-role behavior only when every endpoint/secret/role prerequisite is satisfied; it was not promoted as an authorization bypass.

## Rejected, narrowed or deferred ideas

- **Unauthenticated account-ID/instance enumeration:** unsigned API calls require SigV4. The public web subdomain is only an Identity Center authentication entry point. No unauthenticated page was created.
- **Bearer URL theft:** the public service model returns no presigned/bearer data URL. Diagnostic output is an S3 URI and requires separate S3 authorization.
- **Native cross-account resource policy:** unsupported. Use an assumable role in the owner account. A data-flow target can still cross an S3 account boundary only if the target bucket accepts the instance role; this was documented as conditional, not claimed as universally accepted.
- **Data rows returned by `GetDataIntegrationEvent`:** false. The response returns event metadata and target/load details, not the submitted JSON payload.
- **Instance role equals service-linked role:** AWS IAM documentation says Supply Chain supports service roles but not IAM service-linked roles. The per-instance role is `service-role/scn-instance-role-<instance-id>` and should not be described as an AWS-managed SLR.
- **Create instance + custom KMS as a cheap live fixture:** excluded because it provisions a full application, may incur ongoing cost, and this account had no Identity Center instance. Authorization and documented behavior were sufficient.
- **Application-admin live test:** excluded because it requires a real Identity Center user/application and sends an invitation email.
- **KMS key swap on an active instance:** unsupported. The customer-managed key selection is immutable; replacement requires a new instance. Key disable/revocation may take up to 15 minutes to affect cached data keys.
- **`CreateSSOApplication` alone as a privilege escalation:** it establishes integration but does not itself prove attacker user assignment/admin access. The stronger `AssignAdminPermissionsToUser` action was documented.
- **Internal web API IAM policies:** rejected. AWS says these calls are authorized by the application's federated role model and are absent from the Service Authorization Reference. Writing an IAM policy with their documented names is not a substitute for an application-role test.
- **UI filters as export authorization:** false. AWS explicitly says Demand Planning CSV exports contain the whole demand plan regardless of filters.

## Candidate future defect tests

Use a disposable, already-funded instance and controlled identity directory:

1. Validate cross-account S3 targets for dataset-to-S3 flows, including bucket-owner-enforced object ownership, foreign-region buckets, KMS keys, and confused-deputy restrictions.
2. Test whether `CreateDataIntegrationFlow`/`UpdateDataIntegrationFlow` re-authorizes every S3 source/target at configuration time and execution time, including stale policy and DNS/bucket-name reuse races.
3. Build a full resource-level authorization matrix for dataset source/target ARNs, flow ARNs, namespace ARNs, and mismatched instance path parameters.
4. Verify whether `SendDataIntegrationEvent` authorizes only the instance or also validates the dataset ARN's account/instance before enqueue, and test foreign/mismatched dataset identifiers.
5. Measure event ordering, idempotency-token replay (8-hour lifetime), `eventGroupId` serialization, and delete/upsert races for cross-tenant or stale-write behavior.
6. Validate console-only admin/SSO actions with exact instance tags, identities from account versus organization Identity Center instances, deleted/recreated users, invitation revocation, and stale web sessions.
7. Compare removal of application admin/user access with already-issued browser sessions and cached KMS data keys.
8. Capture successful CloudTrail event shapes for every flow/event/import operation and verify whether SQL, S3 URIs, event data, identity attributes or invitation fields are safely redacted.
9. Enable a disposable SCN data-event selector and verify `SendDataIntegrationEvent`/web API resource ARNs, `readOnly` classification, and payload redaction.
10. Test web-domain uniqueness/reuse only between authorized disposable instances after complete deletion.
11. Characterize `CreatePresignedUrl` method, scope, lifetime, replay, revocation after user removal, and cross-user/instance isolation without exposing the URL outside the research account.
12. Reconcile the contradictory AWS documentation by exercising internal user, chat, data-lake, export and Q actions with an SCN data-event selector enabled.
13. Test ERP connector endpoint/Secret ARN binding with researcher-owned credentials: public HTTPS, controlled PrivateLink, redirects, DNS changes, TLS enforcement, credential transmission timing, and whether update/reconnect reuses stored credentials without reauthorization.
