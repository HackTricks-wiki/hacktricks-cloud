## Scope and outcome

- Account: `228478051196`, Region: `us-east-1`.
- Identity: `hacktricks-training` assumed `ChackBotAdministratorRole`; each capability test used an additional STS inline session policy to reduce the effective permissions.
- One unassociated feed and one unreferenced dictionary were used. No MediaLive channel, association, media, inference processing, role, S3 object, or other paid fixture was created.

## Service model

1. Feeds have exact-resource IAM authorization, a unique data endpoint, named outputs, a source association, optional access role configuration, and one-way lifecycle states.
2. Metadata can include subtitles/transcripts, contextual classification/summary, smart-crop coordinates, and event-clipping output and is retained for seven days.
3. Dictionaries contain a sensitive JSON vocabulary; `GetDictionary` returns metadata while `ExportDictionaryEntries` returns the entries.
4. A feed resource policy can grant only `GetMetadata` to another AWS account/service. `PutFeedPolicy` replaces the complete document.
5. `PutMedia` and `GetMetadata` use the feed data endpoint and have explicit CloudWatch request-count metrics.
6. Control-plane calls are CloudTrail management events under `elemental-inference.amazonaws.com`.

## Live tests

### Feed creation baseline

- Created `ht-ei-audit-*` with one enabled cropping output.
- Waited for `AVAILABLE`; never associated it and never called `PutMedia`.
- `GetFeed` returned the exact ID, ARN, output, and feed-specific data endpoint.

### Exact `GetFeed`

The constrained session allowed only:

```json
{"Effect":"Allow","Action":"elemental-inference:GetFeed","Resource":"<exact-feed-arn>"}
```

and explicitly denied `ListFeeds` and `UpdateFeed`. Exact `GetFeed` succeeded; listing failed `AccessDeniedException`.

### Blind `UpdateFeed`

The constrained session allowed only `UpdateFeed` on the exact ARN and explicitly denied `GetFeed`, `ListFeeds`, and `iam:PassRole`.

- Replaced the enabled cropping output with the same output set to `DISABLED` and changed its description.
- The update succeeded and admin verification observed the replacement.
- The same session's follow-up `GetFeed` failed `AccessDeniedException`.
- A preliminary request that attempted to supply immutable association state failed `ValidationException` and was recorded as a negative control.

### Blind `PutFeedPolicy`

The constrained session allowed only `PutFeedPolicy` on the exact feed ARN and explicitly denied `GetFeed`, `GetFeedPolicy`, and `ListFeeds`.

- Attached a policy granting `elemental-inference:GetMetadata` to a controlled external-account root principal, without conditions.
- Admin `GetFeedPolicy` verified the stored document and principal.
- The writer's own `GetFeedPolicy` failed `AccessDeniedException`.
- The policy was removed before feed deletion.
- No metadata existed and no external-account request was made, so only the authorization persistence primitive—not content exfiltration—was exercised.

### Exact dictionary export

- Created one `eng` dictionary with two synthetic entries, including one `sounds_like` alias.
- An inline session allowed only `ExportDictionaryEntries` on the exact dictionary ARN and explicitly denied `GetDictionary`, `ListDictionaries`, and `UpdateDictionary`.
- Export returned a JSON payload equal to the original entries; a SHA-256 comparison was used during the run.
- Both denied control calls returned `AccessDeniedException`.

### Blind dictionary replacement

- A second session allowed only `UpdateDictionary` on the exact ARN and explicitly denied `GetDictionary`, `ListDictionaries`, and `ExportDictionaryEntries`.
- It replaced the vocabulary with one synthetic entry.
- Its export control failed `AccessDeniedException`; admin export confirmed the replacement exactly.

## CloudTrail observations

| Action | `readOnly` | `managementEvent` | Important observed fields |
|---|---:|---:|---|
| `CreateFeed` | false | true | request `name`, `outputs`, `tags`; response includes ARN, endpoint, outputs and status |
| `GetFeed` | true | true | request `id`; successful response omitted from the event |
| `UpdateFeed` | false | true | request `id`, `name`, `outputs`; success has the feed resource ARN |
| `PutFeedPolicy` | false | true | request contains `id` and the complete `policy`; feed resource present |
| `GetFeedPolicy` | true | true | request `id`; successful response omitted |
| `CreateDictionary` | false | true | request includes `entries`, language/name/tags; dictionary ARN present on success |
| `ExportDictionaryEntries` | true | true | request `id`; exported response omitted |
| `UpdateDictionary` | false | true | request includes `id` and `entries`; dictionary ARN and configuration in response |
| Delete operations | false | true | requested ID, status/ARN as applicable |

Access-denied and validation failures also appeared with caller/source/error details. Resource type spelling was inconsistent across observed feed event families (`AWS::Elemental-Inference::Feed` vs `AWS::ElementalInference::Feed`); this is recorded as a detection-engine normalization pitfall, not a demonstrated security defect.

`GetMetadata` and `PutMedia` were not exercised. AWS documents per-feed `GetMetadataRequestCount`, `PutMediaRequestCount`, processing latency, and processing fault metrics. Public pages avoid claiming unverified CloudTrail data-path behavior.

## Ideas considered but not promoted

| Idea | Result |
|---|---|
| Unsigned control-plane enumeration | Rejected: missing authentication token |
| Identifier-only data endpoint access | Rejected as a native unauth technique: requests require SigV4 or a feed policy-authorized AWS principal/service |
| `UpdateFeed` as AWS-account privilege escalation | Rejected: confirmed integrity/availability impact; role-backed changes can require `iam:PassRole` |
| External principal with unrestricted policy actions | Rejected: feed-policy delegation is limited to `GetMetadata` |
| Wildcard anonymous principal | Not promoted; policy security requirements prohibit broad unsafe principals and this was not needed to prove cross-account persistence |
| Media injection live proof | Deferred: processing was unnecessary, billable, and the authorization/functionality is explicit in official documentation |
| MediaLive confused deputy through association | Backlog: requires a bounded MediaLive fixture and exact role/source-condition testing |
