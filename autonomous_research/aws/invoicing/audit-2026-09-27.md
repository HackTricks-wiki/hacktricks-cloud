### Resource model

```text
arn:aws:invoicing::<account>:invoice-unit/<identifier>
arn:aws:invoicing::<account>:procurement-portal-preference/<identifier>
arn:aws:billing::<account>:billingview/<resource-id>
```

- `GetInvoiceUnit`, `UpdateInvoiceUnit`, and `DeleteInvoiceUnit` support an exact invoice-unit ARN.
- Invoicing tag operations support applicable exact Invoicing ARNs.
- Invoice profiles, invoice summaries, invoice PDFs, invoice-unit listing/creation, procurement preference operations, correction/email permission-only actions, and portal metadata require `Resource: "*"` in the current authorization reference.
- Billing view metadata, update/delete, source association, tags, and resource-policy actions nominally support the exact Billing view ARN.
- Global Billing preferences, credit/support/contract/IAM reads and writes, notifications, seller of record, `UseSourceView`, and list actions require `Resource: "*"`. Permission-only `GetBillingData` and `GetBillingDetails` support a view ARN; `GetBillingViewData` requires one.
- `CreateBillingView` and `AssociateSourceViews` depend on `billing:UseSourceView`; tagged creation also depends on `billing:TagResource`.

## Strong attack paths and constraints

### Financial and identity data disclosure

- `BatchGetInvoiceProfile` returns legal entity, receiver address, contacts and account-level invoice identity data.
- `ListInvoiceSummaries` returns invoice IDs, account IDs, billing periods, currencies, totals, tax/discount/fee breakdowns, seller and payment metadata.
- `GetInvoicePDF` returns expiring pre-signed URLs for invoice and supplemental documents. The later HTTP download does not require the original caller's AWS credentials.

### Procurement secret disclosure and routing

- A full procurement preference can return production/test endpoints, buyer/supplier identifiers, contacts, selectors, status/reasons and `ProcurementPortalSharedSecret`.
- AWS CLI documentation explicitly warns that billing read-only policies expose all procurement connection details.
- The shared secret belongs to the external procurement integration, not IAM. Actual use depends on portal/protocol configuration.
- Preference creation is not silent activation. The documented setup includes AWS/customer verification, contacts and testing; this was not invoked.

### Invoice-unit manipulation

- Creation selects the receiver, rule and tax-inheritance behavior. Update can change the rule and tax setting, but not the immutable name or receiver; receiver replacement requires delete and recreate.
- Both payer and receiver can download unit invoices. This can confer durable service-level document access to an eligible member account.
- Account membership is mutually exclusive; arbitrary unrelated accounts are not valid receivers. External bill-source accounts require an already authorized Billing Transfer.
- Deletion disrupts custom grouping but does not remove charge liability.

### Billing-view cross-account persistence

- Custom views can expose filtered or combined cost data and are shareable inside or outside the organization through AWS RAM.
- External sharing requires RAM permissions and recipient acceptance. Primary, billing-group and billing-transfer views are not shareable.
- View source/filter changes take effect immediately for recipients.
- Cross-account derived views can create `AWSServiceRoleForBilling`, whose managed policy contains only `billing:GetBillingViewData` on Billing view ARNs and whose trust is limited to `billing.amazonaws.com`.

### Billing business-integrity changes

- `UpdateBillingPreferences` can alter credit, RI and Savings Plans sharing and thus affect bills.
- `RedeemCredits` consumes a promo code.
- `PutContractInformation` changes contract/end-user/public-sector/PO metadata.
- `UpdateIAMAccessPreference` can activate existing legacy IAM Billing entitlements, but grants no Billing action by itself.

None of these public APIs accepts a caller-selected role or provides general AWS credentials. No direct IAM privilege escalation primitive was found.

## Rejected or constrained ideas

- **Invoice IDOR:** no invoice identifier from another tenant was available or used, and arbitrary synthetic IDs reached not-found only in the caller's authorized context. No cross-account bypass was found.
- **Procurement preference IDOR:** a synthetic external-account ARN was denied before resource disclosure.
- **Billing-view ARN IDOR:** an arbitrary unshared external ARN was denied. Supported cross-account access uses RAM/resource policy.
- **Service-linked role escalation:** the Billing role has one narrow read action and service-only trust; it is not a general role-assumption path.
- **Invoice receiver as arbitrary external persistence:** receiver eligibility and the billing family constrain it; external bill-source accounts require Billing Transfer.
- **Create resources to force proof:** creating invoice units or changing preferences could alter real invoices. Procurement setup could trigger external contact/workflows. Those tests were intentionally not performed.
