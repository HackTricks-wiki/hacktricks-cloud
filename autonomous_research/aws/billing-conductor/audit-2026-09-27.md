- Reviewed current AWS CLI `2.34.45`: 32 modeled APIs. Current service-authorization feed has 34 actions, adding billing-transfer preference read/update.
- Resource types: billing group, pricing plan, pricing rule, custom line item. Conditions: request/resource tags and `billingconductor:PricingPlanArn`.
- Reviewed payer/Organizations boundary, pro forma cost reports, account associations, pricing manipulation, custom line items, resource associations, billing-transfer preferences, CloudTrail and supported downstream integrations.
- No prior dedicated HackTricks Billing Conductor coverage found.

## Live boundary

Authorized admin access was in member account `228478051196`, not the payer. `ListBillingGroups` returned `AccessDeniedException: Only payer account is authorized`. Further list calls were not attempted because the same server-side payer boundary applies. No mutation was made and no asset existed to clean.

This boundary means member-account AdministratorAccess cannot enumerate or manipulate ABC. It is not an IAM bypass target: testing requires explicit payer-account authorization, which was outside the supplied account.

## Exclusions

- No privilege escalation: ABC does not execute arbitrary code or accept a caller-passed role. Its service-linked role is not a PassRole primitive.
- No unauthenticated/cross-account endpoint: caller must be authenticated in the payer account; member admin was denied.
- No live pricing/group/line-item tests: these would alter real payer chargeback configuration and the authorized account was not the payer.
- Deletes and tag abuse are obvious and add no distinct technique.
- Billing transfer preference is a newer Organizations boundary. Its auto-group/pricing-plan effect
  is documented from the current official API; no live mutation was attempted because no safe
  authorized payer/transfer fixture existed.
- No unexpected defect was found; no private report created.
