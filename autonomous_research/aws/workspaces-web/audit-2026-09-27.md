## Authentication boundary

An unsigned `ListPortals` call returned `MissingAuthenticationTokenException`. The portal URL is
internet-reachable by design, but AWS documents that a user cannot start a session without valid
portal identity credentials. Read/control-plane APIs do not expose a public resource policy, bearer
stream URL, browser cookies, rendered pages, clipboard contents or downloaded-file contents.

## Retained techniques

### Forced extension/browser policy

AWS permits any supported Chrome Enterprise policy for Linux and explicitly documents
`ExtensionSettings` with `installation_mode=force_installed`. The browser-settings policy applies
to all sessions using the portal. This is a strong post-exploitation and portal-level persistence
primitive because an appropriately permissioned extension can observe or modify reachable pages
after the original AWS session is gone.

### Transfer controls

`UpdateUserSettings` independently controls copy, paste, upload, download, print, deep links,
toolbar presentation, WebAuthn and cookie synchronization. Re-enabling transfer controls is a
direct data-exfiltration path only after an authenticated portal user can reach sensitive content.

### Redaction and IP restrictions

`UpdateDataProtectionSettings` can replace the inline redaction patterns with an empty set.
`UpdateIpAccessSettings` can broaden the source CIDRs. The latter does not bypass SSO; it is useful
with separately obtained identity/session material.

### Logging redirect and blinding

Session Logger stores usernames, client/portal IPs, session IDs, full URL paths, website
interactions, printing, clipboard direction and file-transfer metadata in S3. AWS explicitly omits
clipboard and file contents. Its S3 configuration includes `bucketOwner`, and the destination must
accept the WorkSpaces Web service/caller writes. User Access logging sends a smaller start/end/URL
event set to Kinesis. Updates can redirect future metadata; disassociation can blind both paths.

### Identity-provider persistence

`CreateIdentityProvider` and `UpdateIdentityProvider` can establish an attacker-operated
SAML/OIDC trust path on a standard-federation portal. The attacker still needs protocol-valid
assertions and correct portal service-provider metadata. IAM Identity Center portals have different
same-account/Region and Organizations-management-account prerequisites and are not represented as
vulnerable to this standard-provider path.

## Rejected or bounded ideas

| Idea | Result |
| --- | --- |
| Direct unauthenticated API enumeration | Rejected: unsigned list call denied. |
| Portal URL alone creates a foothold | Rejected: public reachability is not portal authentication. |
| Direct cross-account Secure Browser resource policy | Rejected: no customer resource-policy API; use an assumed IAM role in the owning account. |
| General AWS IAM privilege escalation | Rejected: settings affect portal sessions and reachable applications, not arbitrary IAM roles or credentials. |
| Read APIs leak browser content or cookies | Rejected by API output contract; session APIs expose identity/lifecycle metadata. |
| Logger captures clipboard/file contents | Rejected: AWS explicitly says those contents are not recorded. |
| `UpdateNetworkSettings` alone bypasses application authentication | Rejected: changing VPC/subnets/security groups may alter reachability or availability but does not mint portal/app credentials. |
| `ExpireSession` as a book technique | Excluded as availability/response functionality rather than access, persistence or sensitive-data gain. |

## Telemetry

- All WorkSpaces Secure Browser control-plane calls are documented CloudTrail management events.
- The live inventory events were `readOnly:true`; the tested mutation attempts were
  `readOnly:false`.
- Browser-extension execution and normal web traffic are not WorkSpaces Web API calls. Detection
  needs browser-policy reconciliation plus network telemetry.
- Session Logger sends files approximately every 15 minutes or when the session ends and publishes
  delivery/error metrics. User Access logging has a smaller event set and can miss incognito or
  deleted-history URLs.
- An unexpected telemetry behavior observed during the probes is intentionally excluded from this
  public ledger and retained only in the restricted AWS disclosure directory.
