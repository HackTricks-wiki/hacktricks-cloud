# Partner Central Selling API audit — 2026-10-01

## Result

Published the missing `partnercentral-selling` inventory and three material expected attack groups:

1. Exact Opportunity, AWS-summary, invitation and snapshot reads recover customer PII/account IDs, sales pipeline, expected spend, private-offer/solution links, AWS/Partner contacts, scores/recommendations and software commitment/discount terms.
2. Exact writes can full-replace Opportunity content (omitted fields become null), reassign its owner, alter commercial associations, submit/lock it for AWS review or reject a referral and lose its data.
3. An external connected Partner can be added as an Engagement member and retain permanent access to shared immutable snapshot revisions; a passed snapshot-job role plus a running job can continue publishing later Opportunity changes after the installer loses access.

These are expected Partner collaboration and CRM-control capabilities. No AWS defect or private report was created.

## Current control plane

- CLI/SDK client: `partnercentral-selling`; model version `2022-07-26`.
- IAM prefix/ARN service: `partnercentral`.
- Endpoint: `partnercentral-selling.us-east-1.api.aws`; `eu-west-1` was unreachable, matching AWS's current Region table.
- CloudTrail source: `partnercentral-selling.amazonaws.com` in `us-east-1`.
- 45 operations cover Opportunities, solutions/associations, AWS referrals, Engagements/contexts/members, immutable snapshots, snapshot jobs/settings and four task families.
- Service events use EventBridge source `aws.partnercentral-selling` for Opportunity, invitation, member, Engagement and snapshot changes.

## Live enrollment and authorization results

Unsigned `ListOpportunities` returned `MissingAuthenticationTokenException`. With a confirmed administrator session, every tested AWS/Sandbox list/get call reached the endpoint but returned:

```text
INCOMPATIBLE_BENEFIT_AWS_PARTNER_STATE
```

The gate covered Opportunities, Engagements, sender/receiver invitations, snapshot jobs, solutions, system settings and all four task inventories. No Selling record existed or was created.

A disposable principal was allowed `GetOpportunity` only on:

```text
arn:aws:partnercentral:us-east-1:228478051196:catalog/AWS/opportunity/O1234567890
```

That ID passed IAM and reached the Partner gate. A different Opportunity ID and the same ID under `Sandbox` were denied with the exact evaluated ARN, proving exact-resource and `partnercentral:Catalog` separation.

## Snapshot-job role boundary

`PutSellingSystemSettings` requires both the wildcard Partner Central action and `iam:PassRole` on the selected role. Without PassRole, the live call was denied specifically on the role ARN. With exact PassRole it reached the Partner gate. After IAM propagation, this documented condition also passed authorization:

```json
{
  "StringEquals": {
    "iam:PassedToService": "resource-snapshot-job.partnercentral-selling.amazonaws.com"
  }
}
```

No real role was passed and no setting changed. The fake role did not exist, but the enrollment gate ran after IAM authorization.

The current AWS-managed `AWSPartnerCentralSellingResourceSnapshotJobExecutionRolePolicy` default version is v3 and grants only:

- `partnercentral:GetOpportunity` on AWS/Sandbox Opportunity families; and
- `partnercentral:CreateResourceSnapshot` on AWS/Sandbox Engagement families.

Direct `CreateResourceSnapshot` and `CreateResourceSnapshotJob` have caller-side dependent `GetOpportunity` permissions, so they are not standalone read bypasses. An existing job fixes the target Opportunity/Engagement/template; `StartResourceSnapshotJob` can resume continuous publication but cannot choose an arbitrary target.

## Persistence boundary

Current AWS documentation establishes:

- a maximum of ten Engagement members (the owner plus up to nine invited connected Partners);
- accepted invitees receive their own Opportunity in the same Engagement;
- shared snapshots are immutable and remain permanently accessible to Engagement members;
- running snapshot jobs automatically publish a new revision when the underlying Opportunity changes; and
- no current API operation removes a member, deletes an Engagement or deletes a snapshot revision.

The book therefore classifies an accepted attacker-controlled external member as Partner Central Selling service-level persistence, not AWS-account/IAM persistence. The connected/eligible external Partner, receiver acceptance and template-limited data boundaries are explicit. Future publication can be stopped by stopping/deleting the job and restoring the role; past snapshot access requires Engagement/membership recovery outside the current API.

## Telemetry

All enrollment-gate and IAM-denied probes were default CloudTrail management events. Reads had `readOnly:true`; `PutSellingSystemSettings` had `readOnly:false`. Every failed event stored `requestParameters:null`, `responseElements:null` and no resources, including exact-ARN denials and the allowed-but-unenrolled branches. Error text distinguished IAM resource/PassRole denials from Partner enrollment.

Successful production workflows additionally emit EventBridge events for Opportunity created/updated, invitation created/accepted/rejected/expired, member added, Engagement created/updated and snapshot created. Snapshot jobs publish CloudWatch `Invocations`, `Errors` and `Faults` metrics only when active.

## Deferred validation

Retest in two connected, reversible Partner sandbox accounts when available:

- successful Opportunity/AWS-summary/invitation/snapshot responses and exact field redaction;
- all list-family resource patterns, tags and Catalog conditions;
- complete update/assign/associate/submit/reject lifecycle behavior and notification recipients;
- member addition, whether AWS Support can remove a member/Engagement, and exact post-removal access to old snapshots;
- role replacement, job start/stop/delete, initial versus change-triggered revisions and restoration order; and
- successful CloudTrail request/response fields plus which account records foreign-member snapshot reads.

Do not create an Opportunity, Engagement or invitation solely for testing in this account: these APIs have no corresponding delete operations and can initiate AWS/third-party business workflows.

The three disposable IAM users, inline policies and access keys were deleted. Final matching `ht-pcs-*` user/role inventories were empty. No real IAM role, Opportunity, Engagement, invitation, member, context, snapshot, job, task, setting, solution/offer association, EventBridge rule, notification or Partner Central record was created or changed.
