## Exact-resource update test

The disposable role `ht-appint-update3-20260927` trusted only the authorized administrator role and
held:

```json
{
  "Effect": "Allow",
  "Action": [
    "app-integrations:GetApplication",
    "app-integrations:UpdateApplication"
  ],
  "Resource": "arn:aws:app-integrations:us-east-1:228478051196:application/<canary-id>"
}
```

The role successfully persisted:

```json
{
  "AccessUrl": "https://example.org",
  "ApprovedOrigins": ["https://example.net"],
  "Permissions": ["*"],
  "ApplicationType": "STANDARD"
}
```

The same session's update against
`application/00000000-0000-0000-0000-000000000000` was denied by IAM before resource lookup. The
role had no Connect, IAM mutation, AppFlow, EventBridge or data-integration permission.

An earlier isolated canary also verified that arbitrary permission strings and the URL/origins are
stored, but only current documented permissions should be treated as effective in the workspace.

## Application execution implications

Official current behavior:

- Standard apps render as an iframe for allowed agents when opened; apps may be pinned or opened by
  workflow/screen-pop behavior.
- Service apps start when the workspace loads, remain for the session and run without a visible app
  interface.
- Apps use the Connect SDK to request agent/contact data and subscribe to events; the stored
  AppIntegrations permission list gates those operations.
- `*` grants every supported request/event. Named permissions include customer phone/contact
  attributes and contact accept/clear/transfer/add-participant/outbound-call operations.

The web origin does not automatically receive AWS console cookies or credentials. The high-value
boundary is the Connect SDK channel, agent interaction and the trusted placement inside the contact
center workspace.

## CloudTrail

Observed `app-integrations.amazonaws.com` management events included create, update, get, delete and
list calls. `UpdateApplication.requestParameters` recorded the full replacement URL, approved
origins, permissions, requested type/timeout and URL-encoded application ARN. The failed
standard-to-service request was also present with its full requested configuration and error.

CloudTrail delivery to Event History was delayed by several minutes. Do not use an immediate empty
lookup as evidence that the action is unlogged.
