# AWS Interconnect audit — 2026-09-29

## Inventory and model

- Both allowed Regions (`us-east-1`, `eu-west-1`) returned zero customer connections.
- `us-east-1` exposed four AWS-managed environments: Azure (`eastus`), OCI (`us-ashburn-1`), GCP (`us-east4`), and a Lumen last-mile New York environment. Environment responses contain the partner activation-page URL where applicable and the required remote account identifier type.
- `ListConnections` returns `ConnectionSummary` objects and does **not** expose the key. `GetConnection`, `CreateConnection`, and proposal acceptance return the full `Connection` object; its current documented/modelled required fields include the sensitive `activationKey`.

## Published expected technique

`interconnect:GetConnection` is a credential-bearing read. The activation key is the shared token used to authorize and complete the provider side of a new Interconnect. Usefulness is conditional on:

1. a known `mcc-xxxxxxxx` or `lmcc-xxxxxxxx` connection ID;
2. a connection still awaiting partner acceptance;
3. access to the matching provider portal/account; and
4. any provider-side remote-account binding and validation.

The key can complete or interfere with a private-connectivity provisioning flow; it is not an AWS IAM credential and does not itself change VPC/TGW/Cloud WAN routes or security controls.

## Minimum-permission probes

- A disposable role with only `interconnect:GetConnection` on `arn:aws:interconnect:us-east-1:228478051196:connection/mcc-00000000` reached the service and returned `ResourceNotFoundException`. The same role's request for `mcc-11111111` was IAM-denied.
- A separate disposable role with only `interconnect:ListConnections` on `*` successfully returned the empty list and was denied `GetConnection`.
- Both roles and inline policies were removed; final `ht-interconnect-*` role inventory was `[]`.
- Unsigned getters and environment lists returned `MissingAuthenticationTokenException`.

## Telemetry

- Observed `GetConnection` calls were read-only default management events from `interconnect.amazonaws.com`; the authorized not-found event recorded `identifier` and had `responseElements:null`. Curiously, the service rendered its not-found as CloudTrail `errorCode:UnknownError`; this is a telemetry-quality quirk, not a security issue.
- `ListConnections` was also a read-only management event; the successful empty response was omitted.
- AWS's official `CreateConnection` CloudTrail example logs topology, remote account, attach point, tags and client token, but replaces the activation key in the response with `HIDDEN_DUE_TO_SECURITY_REASONS`.
- Partner-portal redemption is outside AWS CloudTrail. Connection-state transitions and network/ routing/traffic telemetry are the AWS-side follow-on signals.

## Deferred/rejected ideas

| Candidate | Disposition |
| --- | --- |
| `CreateConnection` from scratch as a network backdoor | High potential but begins a provider provisioning/billing workflow and needs a real Direct Connect gateway/remote account. Track for an engagement fixture; do not test in this empty account. |
| Replay key after acceptance/deletion | No fixture; state machine likely rejects it. Do not claim persistence beyond the pending workflow. |
| Cross-account guessed-ID read | Exact-resource IAM authorization was confirmed; no resource policies or evidence of foreign-owner access. Keep a two-account known-resource test in the private backlog. |
| Public environment or connection discovery | Rejected: unsigned calls require SigV4. |

No unexpected AWS vulnerability was demonstrated and no private report was created.

## Cleanup

- No connection, Direct Connect gateway, partner proposal, route, or network resource was created.
- Both disposable IAM roles/policies were deleted and independently verified absent.
- The temporary local probe scripts were deleted.
