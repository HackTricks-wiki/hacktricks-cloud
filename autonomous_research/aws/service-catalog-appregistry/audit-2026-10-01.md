# AWS Service Catalog AppRegistry audit — 2026-10-01

## Result

Expanded the previously minimal Service Catalog enumeration page with the complete AppRegistry model and added two expected existing-customer post-exploitation techniques:

1. exact-attribute-group metadata recovery; and
2. exact-attribute-group metadata poisoning that affects every associated application and downstream metadata consumer.

The training account is not an established AppRegistry customer and AWS denied fixture creation at the July 30, 2026 maintenance-mode gate. The attack semantics are directly documented by the current API/administrator guides, but no successful write was represented as a live account result. No AWS defect or private report was produced.

## Service and data model

- CLI client: `servicecatalog-appregistry`.
- IAM prefix: `servicecatalog`, shared with the main Service Catalog API.
- CloudTrail source: `servicecatalog-appregistry.amazonaws.com`.
- Regional resources: applications and attribute groups.
- Applications group CloudFormation stacks or tag-value resource groups and associated attribute groups.
- Application ARN: `arn:aws:servicecatalog:REGION:ACCOUNT:/applications/ID`.
- Attribute-group ARN: `arn:aws:servicecatalog:REGION:ACCOUNT:/attribute-groups/ID`.
- Attribute groups contain an arbitrary JSON string up to 8,000 characters. AWS examples include ownership, email/phone, department, runtime, SLA, compliance and data-sensitivity fields.
- Updating a group applies the new definition to every associated application.
- The `awsApplication` user tag integrates membership with cost, security, monitoring, Systems Manager, Resilience Hub, Resource Groups and third-party/ServiceNow views. AWS says existing values persist indefinitely during maintenance mode.
- AWS RAM shares support read-only and allow-associations permissions for accounts/OUs/organizations. Recipients cannot re-share a resource they do not own.

## IAM boundaries

- List/create and account-configuration actions use `Resource: "*"`.
- Get/update/delete actions support exact application or attribute-group ARNs.
- Association of an attribute group authorizes both the application and group.
- Resource-association actions support `servicecatalog:Resource` and `servicecatalog:ResourceType` conditions.
- Application/attribute resource actions support `aws:ResourceTag`; create/tag actions additionally support request-tag keys.
- Applying `awsApplication` to a target is not an AppRegistry-only tagging bypass. The documented path also checks Resource Groups Tagging API, Resource Groups, CloudFormation and target-service tagging permissions as applicable.

## Published techniques

### Exact-group metadata read

`GetAttributeGroup` returns full arbitrary JSON plus its description, tags, creator and timestamps. `ListAttributeGroups` is only optional discovery. The impact is operational/business intelligence and conditional accidental secret disclosure; attribute groups are not described as a credential store.

The read is High stealth: one ordinary management read. Existing AppRegistry list/config reads had null response elements, so returned content was not present in those observed events. Public text does not overclaim that every getter uses identical response logging.

### Exact-group metadata poisoning

`UpdateAttributeGroup` accepts replacement JSON/description on the exact group ARN. AWS explicitly states that the update affects every application associated with that group and highlights automated/third-party metadata consumers. This can falsify owners, escalation/runbook URLs, compliance or data classifications and poison consumers, but does not directly mutate associated resources or IAM.

This remains post-exploitation rather than persistence or privilege escalation. The changed metadata persists until restored, but it does not preserve attacker access. Public coverage recommends immutable/versioned source plus schema validation and baseline hashes.

## Live safe probes and telemetry

Initial inventory in `us-east-1` returned:

```json
{
  "applications": [],
  "attributeGroups": [],
  "configuration": {"tagQueryConfiguration": {}}
}
```

`CreateApplication` with a disposable name/description was denied:

```text
AccessDeniedException: AWS Service Catalog AppRegistry is in maintenance mode
and is no longer available to new customers as of July 30, 2026
```

CloudTrail recorded:

- successful `ListApplications`, `ListAttributeGroups` and `GetConfiguration` as default read-only management events with `responseElements:null`;
- denied `CreateApplication` as `readOnly:false`, including name, description, generated client token and the maintenance-mode response message; and
- all events under `servicecatalog-appregistry.amazonaws.com` in `us-east-1`.

The account gate occurred before any application, resource group, attribute group or IAM fixture was created.

## Negative/deferred candidates

| Candidate | Result | Disposition |
| --- | --- | --- |
| New-customer application creation | Explicit maintenance-mode access denial | Expected lifecycle gate |
| `AssociateResource` as arbitrary target tag bypass | Docs require dependent tagging/resource-group/CloudFormation authorization | Not a general bypass |
| Delete application to cascade-remove topology | Delete requires all resource/attribute associations removed first | Multiple noisy permissions/events required |
| Cross-account public sharing | Sharing is AWS RAM/Organizations based; incoming resources cannot be re-shared | No public/anonymous path |
| Foreign ARN/name IDOR | No owned/shared fixture could be created | Deferred for an existing customer account |
| Attribute JSON stored XSS | No existing-customer UI fixture | Deferred; do not publish without a rendered sink |
| `PutConfiguration` tag-key poisoning | Account configuration was empty but no applications existed and the account is gated | Deferred; insufficient demonstrated impact |
| Application membership/tag tampering | Documented but overlaps Resource Groups/tag controls and downstream impact is environment-specific | Kept out of public attack page for now |

## Cleanup

The create request produced no resource. Final application and attribute-group inventories for `ht-appreg-*` were empty, and no `ht-appreg-*` IAM user existed. No CloudFormation stack, Resource Group, RAM share, tag, service-linked role or paid resource was created. Account configuration remained unchanged and empty.
