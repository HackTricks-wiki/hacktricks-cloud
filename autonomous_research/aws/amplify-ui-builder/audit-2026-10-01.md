# AWS Amplify UI Builder audit — 2026-10-01

## Result

Published the previously missing `amplifyuibuilder` inventory and one expected post-exploitation technique: exact-job `GetCodegenJob` can recover the job's complete generic data schema plus presigned generated React source artifacts without any component, form or theme read permission.

The audit also confirmed a current unexpected code-generation security issue. Its technical details and sanitized PoC are intentionally withheld from the public repository pending AWS review and are maintained only in the restricted local AWS report directory.

## Service surface

- SDK/CLI service and signing name: `amplifyuibuilder`.
- Primary resources: components, forms, themes and codegen jobs, all nested under an Amplify app and environment.
- Exact resource ARNs exist for components, forms, themes and codegen jobs.
- Create/list/export/start operations are generally wildcard-authorized; exact getters, updates and deletes support their corresponding resource ARN.
- Codegen jobs accept a React render configuration, feature flags and a complete generic DataStore schema. Completed jobs return a presigned asset URL.
- The first asset URL returns a JSON manifest, not a ZIP. Each manifest entry contains a file name, schema name and second presigned URL.
- `ExchangeCodeForToken` and `RefreshToken` are documented as internal Figma OAuth helpers and return access/refresh tokens. Unsigned calls returned `MissingAuthenticationTokenException`; signed invalid values reached Figma/OAuth validation and returned `invalid_grant`. No real OAuth code or token was used.

## Published exact-job source recovery

A disposable Amplify app contained one benign DataStore form and a codegen job whose schema had an `Inventory` model with `id` and `internalLabel` fields. After the job reached `succeeded`, a disposable IAM user received only:

```text
amplifyuibuilder:GetCodegenJob on the exact codegen-job ARN
amplify:GetApp                 on the exact parent app ARN
```

The user recovered:

- job status;
- the full `genericDataSchema` and its model/field names; and
- a non-null presigned manifest URL.

It had no UI Builder list, component/form/theme read, write, IAM, build or deployment permission. Removing `amplify:GetApp` caused the same exact-job call to return the service-level `Invalid app ID`; adding exact-app `GetApp` made it succeed. The current UI Builder Service Authorization Reference shows the codegen-job resource type but no dependency column, so the public page records the empirically required pair.

The technique is materially useful because it crosses from a narrow exact-job read into generated application source and the complete job schema. It is not described as credential theft: Studio schemas should not contain secrets, and none existed in the fixture.

## Known code-generation security history

The official advisory for CVE-2025-4318 covers `amplify-codegen-ui <=2.20.2`: an authenticated principal able to create or modify a component schema could inject JavaScript into generated components. AWS identifies 2.20.4 as patched and provides no workaround.

The upstream repository subsequently added more identifier validation in February, June and August 2026. Current release 2.20.7 centralizes several allowlists and has regression tests across component, view, form and theme sinks. Its dedicated 31-test identifier-injection suite passed locally, which shows that the current private finding is outside that corpus rather than a failure of a checked-in test. Public documentation therefore advises using the newest release, reviewing generated diffs and treating lower-trust Studio editors as source-code contributors. It does not include details of the current private finding.

## Negative and bounded findings

| Candidate | Result | Disposition |
| --- | --- | --- |
| Anonymous Figma OAuth token exchange/refresh | Both endpoints require authenticated AWS requests | No unauthenticated token broker |
| Top-level component/form/view/theme name injection in 2.20.7 | Normal renderers validate top-level names with alphanumeric/PascalCase schemas | Negative |
| Child component name injection | Identifier-producing paths sanitize names; simple malformed names remained quoted in override metadata | No executable result in tested fixtures |
| Custom-form `dataTypeName` injection | Custom forms did not emit the test marker | Negative for that branch |
| `GetCodegenJob` without parent `amplify:GetApp` | Exact UI Builder permission reached `Invalid app ID`; adding exact-app `GetApp` succeeded | Documented prerequisite, not a bypass |
| OAuth token calls with fake values | Signed calls returned OAuth `invalid_grant`; no token issued | No finding |

## Telemetry

UI Builder control-plane calls were default CloudTrail management events under `amplifyuibuilder.amazonaws.com`:

- component/form/job mutations were `readOnly:false` and retained their supplied schema fields;
- `GetCodegenJob` was `readOnly:true`, retained app/environment/job IDs, and had `responseElements:null` on success;
- presigned manifest and per-file URLs did not enter CloudTrail response elements; and
- subsequent downloads did not create another UI Builder API event.

The separate parent `GetApp` read is recorded under `amplify.amazonaws.com`. Correlate it with `GetCodegenJob` in the same role session.

## Cleanup

All disposable Amplify apps, forms and jobs were deleted by deleting their parent apps. All disposable IAM access keys, inline policies and users were deleted. Final `ListApps` filters for every `ht-uibuilder-*` prefix returned zero, and exact IAM-user checks returned absent.

No branch, backend environment, repository, build, deployment, service role, secret, data record, Figma session or paid compute workload was created.

Temporary upstream source clones, dependency trees, downloaded manifests, presigned URLs and generated artifacts were deleted after the audit and private report were completed.
