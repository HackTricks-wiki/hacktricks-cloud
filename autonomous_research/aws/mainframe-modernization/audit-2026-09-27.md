## Account-eligibility boundary

`CreateDataSetExportTask`, `CreateDataSetImportTask` and `CreateDeployment` returned:

```text
AccessDeniedException: Unable to determine service/operation name to be authorized
```

This occurred:

1. with only the documented M2 application permission;
2. after adding exact S3 read/write and both application/environment resources; and
3. under the administrator control session.

The stable admin result, empty inventory and AWS closure of managed runtime to new customers make
account eligibility the likely gate. It cannot be used to infer missing IAM permissions. Public
minimums therefore follow the current official dependent-permissions table, and techniques state
the existing-customer/application prerequisites.

The second disposable role `ht-m2-deps-1790478467-2310145` and its policy were also deleted and
confirmed absent.

## IAM/model findings

- Application ARN: `arn:aws:m2:REGION:ACCOUNT:app/ID`.
- Environment ARN: `arn:aws:m2:REGION:ACCOUNT:env/ID`.
- `CreateDeployment` evaluates both even though some summarized tables appear application-centric.
- `CreateApplication` accepts `roleArn`; constrain PassRole with
  `iam:PassedToService=m2.amazonaws.com`.
- M2 uses forward access sessions. Dataset export/import and application definition operations
  require the caller's documented S3/KMS permissions.
- `StartBatchJob` accepts `s3BatchJobIdentifier` with caller-chosen bucket, prefix and
  file/script, and the authorization table lists no caller-side S3 dependent action.
- `authSecretsManagerArn` supplies application-operation credentials where that optional M2
  authorization feature is enabled. It does not return the secret to the caller.
