## Important authorization details

- `SearchContacts` maps to `connect:SearchContacts`, `connect:DescribeContact` and `connect:GetContactAttributes`, not only the nominal search action.
- Contact reads support `connect:Channel`, `connect:ContactAssociationId` and `connect:UserArn` conditions.
- `ListRealtimeContactAnalysisSegmentsV2` supports raw/redacted output and segment-type IAM conditions.
- `MonitorContact` evaluates Contact, Instance and User and supports `connect:MonitorCapabilities`.
- `StartContactStreaming` is scoped to the Instance in the current SAR, not the target Contact, despite taking a ContactId.
- `CreateUser` evaluates User, SecurityProfile, RoutingProfile and optional HierarchyGroup resources.
- `UpdateUserSecurityProfiles` evaluates both User and supplied SecurityProfile resources.
- Instance storage writes support `connect:StorageResourceType`; flow writes support `connect:FlowType`.
- Core Connect has no general native resource-policy CRUD API. Cross-account paths are mediated through Lambda/SNS resource policies and RAM/Lake Formation sharing.
- The local current model marks Connect federation `Credentials` as sensitive and includes access and refresh tokens; the successful CloudTrail event omitted them with `responseElements: null`.
- Live authorization used `Resource: "*"` plus exact `connect:InstanceId`. Plain Instance and actual `/agent/<id>` ARNs failed. AWS also documents a special virtual `/user/${aws:userid}` SAML policy pattern, which was not the agent ARN tested here.

## Ideas reviewed but not promoted as standalone techniques

| Idea | Result / reason |
| --- | --- |
| Anonymous Connect control-plane enumeration from account ID | Rejected. SigV4 is required and unsigned `ListInstances` returned `MissingAuthenticationTokenException` |
| Public chat widget, phone or email entry point | Expected application data plane. Valuable only when a deployed frontend has broken auth/rate-limit/tenant binding; not account-ID-only enumeration |
| `AssociateApprovedOrigin` alone | Does not grant a Connect session or automatically expose data. Requires a user to authenticate/use the integrated site; retain as phishing/session-integration review item |
| `AssociateSecurityKey` alone | Adds a public encryption key; no private key or plaintext is exposed without a corresponding malicious flow/data path |
| Lex association alone | Can alter bot behavior only after a flow uses it and the bot policy permits Connect. Lambda flow implant is clearer and more general |
| `CreateRule` with EventBridge action | Emits into the victim default bus; needs a separately attacker-readable target/archive or EventBridge control. Not standalone exfiltration |
| Outbound call/email/task initiation | Can cause cost, spam or workflow disruption but is primarily noisy abuse. The flow capability pivot was retained only where it yields new privileged behavior/data |
| Tag mutation plus tag-conditioned actions | Generic ABAC escalation is possible on many Connect resource types. Not promoted separately until a Connect-specific surprising multi-resource bypass is demonstrated |
| Prompt presigned URLs | `GetPromptFile` is a valid read but prompt audio is usually low-value compared with customer recordings/transcripts; kept in enumeration |
| Authentication-profile weakening | Useful adjunct to a planted user, but preview/allowlisted and does not grant access by itself |
