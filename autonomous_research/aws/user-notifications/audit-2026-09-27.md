## Key findings

### Regions and data topology

* User Notifications control-plane calls and the console are in `us-east-1`.
* Contacts has only a `us-east-1` endpoint.
* `GetNotificationEvent` and `ListNotificationEvents` are regional and return only UCN content stored in the called Region.
* UCNs are stored in registered notification hubs and the source event rule Region. New hubs are not backfilled.
* Removing a hub stops new replication but does not delete existing notifications; they expire after 90 days.
* Managed-notification APIs are part of the `us-east-1` control plane.

### Current API drift

The online documentation/service-authorization catalog is newer than the installed AWS CLI 2.34.45 model:

* Online API docs now include `isSensitiveEventsSubscribed` on managed account-contact/additional-channel association requests and responses.
* `ListManagedNotificationEvents` now documents `includeSensitiveEvents`.
* `UpdateManagedNotificationChannelAssociation` exists in current API docs/current online CLI listings and changes the sensitive-event subscription on an association.
* `notifications:AccessSensitiveEvents` and `notifications:SubscribeSensitiveEvents` are layered IAM gates.
* Installed CLI 2.34.45 lacked the update command and the new sensitive-event fields/flag. Public content therefore warns readers to upgrade rather than treating field absence as service behavior.

### Sensitive enumeration

Full UCN event content can include:

* headline, paragraph and complete descriptions;
* arbitrary named dimensions and localized text parts;
* related account and OU IDs;
* resource ARNs/IDs/tags and detail URLs;
* source-event ID/type/time/origin Region;
* media URLs and aggregation sample values.

Managed content additionally supports markup descriptions, attachments/download URLs, aggregation across accounts/OUs/Regions, and sensitive-event classification. Current managed sources include Health, Marketplace buyer, Partner Central and Billing/Cost Management, so messages can reveal incidents, security/billing/account status, purchases and entitlements.

Contacts enumeration returns contact name, email address, status, ARN and timestamps. These values must be redacted from shared logs.

### Persistence and impairment

* UCN channels persist through `AssociateChannel` until disassociated/config deleted/contact deleted.
* Managed notification category channels persist through `AssociateManagedNotificationAdditionalChannel`; account primary/alternate contacts use a separate association API.
* Sensitive managed-event delivery requires the extra subscription gate.
* Principal credential revocation does not remove a stored association.
* Creating a contact triggers verification email; resending activation sends mail. No email mutation was live-tested.
* `UpdateEventRule` changes only `eventPattern` and `regions`. It can narrow/suppress or broaden/noise/exfiltrate matching events.
* `UpdateNotificationConfiguration` can set `LONG` (12 hours), `SHORT` (5 minutes), or `NONE`; `LONG` can delay defensive notification delivery.
* User Notifications' EventBridge managed rule contains only base source/detail-type. The additional advanced filter is enforced by User Notifications and is absent from the managed rule, so EventBridge-only audits miss it.
* Hub, rule/config deletion, region removal, OU disassociation, and organization trust changes can impair visibility.
* Non-adjustable quotas (50 configurations/account, 10 rules/configuration, 50 channels/configuration, 500 email contacts, three hubs, and one source event/second/account) allow configuration-slot exhaustion and broad-rule contention/noise.

### IAM exact minimums

Confirmed from the 2026-09-27 Service Authorization Reference/programmatic catalog:

* Resource-scoped: configuration get/update/delete, list/associate/disassociate channels, organization member/OU listing and OU mutation; exact configuration ARN and tag conditions.
* Resource-scoped: event-rule get/update/delete on exact rule ARN.
* Resource-scoped: event get operations on exact event/managed-event/child-event ARN.
* Resource-scoped: managed configuration get/channel association list and mutations on exact managed configuration; no tag conditions.
* Resource-scoped: contact get/delete/activate/resend/tag operations on exact contact ARN with tag conditions where documented.
* Unscoped (`*`): list notification configs/rules/events/hubs/managed configs/managed events/children, list tags, create config, create rule, hub registration/removal, org access state/mutation, list contacts and contact creation.
* Tagged creation requires the corresponding `TagResource` action.
* Sensitive managed reads add `AccessSensitiveEvents` on `*`; sensitive association adds `SubscribeSensitiveEvents` on exact managed configuration.
* Permission-only: `GetFeatureOptInStatus`, `PutFeatureOptInStatus`; sensitive read/subscription actions are special gates rather than stand-alone APIs.

### Cross-account and unauthenticated

* No resource-policy API is documented for notification configurations, events or contacts. External principals normally assume a role in the resource-owning account.
* Deliberate cross-account scope is through Organizations trusted access: management/delegated-admin configurations receive matching member events; member copies are read-only; OU membership changes are followed automatically; events can remain visible for 90 days after departure.
* Channel ARN input grammar includes an account ID but does not establish that an arbitrary cross-account channel is accepted. The public page intentionally does not assert acceptance or rejection without credentials for an authorized test.

## CloudTrail conclusions

* AWS documents all User Notifications API calls as CloudTrail events, including console and programmatic calls.
* Event sources are `notifications.amazonaws.com` and `notifications-contacts.amazonaws.com`.
* Contacts events are also matchable in EventBridge as CloudTrail-originated events on a best-effort basis.
* AWS states contact names and activation codes are always redacted. Email addresses are redacted except upon creation; `CreateEmailContact` can therefore leave the address in trail data.
* Most control writes are in `us-east-1`, while UCN event reads occur in hub/source Regions. Detection needs a multi-Region trail.
* High-priority detections: all association changes, sensitive-subscription toggles, contact create/activate/resend/delete, rule/config updates/deletes, hub changes, OU association changes, and organization-access changes.
* Rule/filter drift must be compared against `GetEventRule`; EventBridge's managed rule does not reveal the advanced filter.
