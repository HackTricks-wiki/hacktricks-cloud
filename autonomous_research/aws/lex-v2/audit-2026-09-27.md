## Verified useful techniques and boundaries

### Exact-bot `CreateExport` starts a full model export

- A temporary IAM user had only `lex:CreateExport` and `lex:DescribeExport` on `arn:aws:lex:us-east-1:228478051196:bot/ROW41MP049`.
- `CreateExport` succeeded and returned export ID `FWG46NVVDL`.
- An administrator-created export was downloaded from the `DescribeExport` pre-signed URL. The ZIP contained `Manifest.json`, bot/locale JSON and both intent JSON files.
- Both synthetic training markers were present in the archive.
- The service-side exports and local ZIP were deleted.

Decision: document full-model export as high-value post-exploitation.

### `DescribeExport` has additional read dependencies

- A second temporary IAM user had only `lex:DescribeExport` on the exact bot ARN.
- After IAM propagation, `DescribeExport` returned `AccessDeniedException`.
- This agrees with AWS's export documentation: downloading a bot export also needs the relevant bot, locale/custom-vocabulary, intent, slot and slot-type describe/list permissions.
- The temporary export, access keys, inline policy and user were deleted.

Decision: show `CreateExport` as the creation primitive but do not claim `DescribeExport` alone can recover the archive.

### Session-state poisoning is possible for any known session ID

- `PutSession` set synthetic session attributes `authorizationTier=administrator` and `workflowToken=HTLEX-POISON`.
- `GetSession` returned both values unchanged.
- The API authorizes against the bot-alias ARN and does not expose a separate end-user/session-owner IAM boundary.
- The test session was deleted with both `DeleteSession` and `DeleteUtterances`; its local audio-output placeholder was deleted.

Decision: document predictable/leaked-session-ID takeover as an application post-exploitation technique. This is expected Lex behavior; the security failure is an application that exposes session IDs or trusts attributes as authorization.

### Runtime sessions can expose state but not necessarily the last raw text

- A text request created a synthetic session and `GetSession` returned the current interpretation/state.
- The response did not reproduce the exact submitted phrase as an `inputTranscript` field in this simple flow.
- The session and stored utterance were deleted; a later `GetSession` returned `ResourceNotFoundException`.

Decision: describe session-state/slots/contexts/attributes accurately, without claiming every raw transcript is returned by `GetSession`.

### Analytics APIs are eventually populated and have surprising IAM mapping

- Immediate `ListAggregatedUtterances`, `ListUtteranceAnalyticsData` and `ListSessionAnalyticsData` calls returned no records for the newly created bot.
- AWS documentation states that analytics are eventually populated and retained up to 15/30 days depending on the API and privacy settings.
- `ListUtteranceAnalyticsData` and `ListUtteranceMetrics` are both authorized by `lex:ListAggregatedUtterances`; AWS's example grants this on `Resource: "*"`.

Decision: document analytics as sensitive post-exploitation, but do not present the immediate empty result as a negative security boundary.

### Resource policies accept principals that cannot necessarily route native calls

- A resource-policy statement granting `lex:RecognizeText` to `arn:aws:iam::418720621023:user/chack-bot` was accepted on the target alias.
- The external principal's `RecognizeText` call failed. The authorization error named `arn:aws:lex:us-east-1:418720621023:bot-alias/ROW41MP049/B2HL04NB25`: Lex resolved the identifiers in the **caller's** account, not account `228478051196`.
- The policy statement was deleted immediately and `DescribeResourcePolicy` then returned `ResourceNotFoundException`.
- CloudTrail confirmed both creation and deletion, including principal, action, resource ARN and revision.

Decision: document resource policies as same-account/AWS-service delegation and persistence, but explicitly reject a generic native cross-account runtime claim. Future tests must use a documented service integration or another request shape that identifies the resource owner.

### Unsigned runtime is rejected before useful enumeration

- `RecognizeText --no-sign-request` returned `MissingAuthenticationTokenException`.
- A bot/alias identifier therefore is not a public credential or useful existence oracle by itself.

Decision: add an unauthenticated-access page focused on the negative boundary and the realistic public path: unauthenticated Cognito identities or public application/channel proxies.

### CloudTrail behavior

Live Event-history records showed:

| API | Category | Useful request/response behavior |
| --- | --- | --- |
| `CreateExport` | Management/write | Full resource specification, returned export ID and status |
| `DescribeExport` | Management/read | Export ID; `responseElements: null`, so no download URL |
| `CreateResourcePolicyStatement` | Management/write | Principal, effect, actions, encoded resource ARN and revision |
| `DeleteResourcePolicyStatement` | Management/write | Statement ID, expected revision and resource ARN |
| `CreateBotAlias` | Management/write | Alias ID/name, version, locale settings and tags |
| `RecognizeText`, `GetSession`, `PutSession`, `DeleteSession` | Lex bot data events | Not present in ordinary Event history; require `AWS::Lex::Bot` data-event configuration |

CloudWatch `AWS/Lex` metrics remain available for aggregate runtime operation/error detection even when data events are disabled.
