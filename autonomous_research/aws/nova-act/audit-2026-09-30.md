# Amazon Nova Act audit — 2026-09-30

## Scope and result

Audited the new `nova-act` API model, IAM authorization reference, deployment architecture, trajectory export, telemetry and live empty-account behavior. Added foundational enumeration coverage to the book. No standalone post-exploitation, persistence, privilege-escalation or unauthenticated technique met the publication threshold.

## Control-plane model

- Region observed/documented: `us-east-1`; the `eu-west-1` endpoint was unavailable.
- IAM/endpoint prefix: `nova-act`; CloudTrail source: `nova-act.amazonaws.com`.
- Resources:
  - `arn:aws:nova-act:<region>:<account>:workflow-definition/<name>`
  - `arn:aws:nova-act:<region>:<account>:workflow-definition/<name>/workflow-run/<uuid>`
- No resource policies, ACLs, ABAC, tags or service-specific condition keys.
- Nova Act has a metrics-only service-linked role and no customer service-role feature.
- The deployed browser workload is separate: Nova Act tooling packages code into Bedrock AgentCore Runtime and creates ECR, S3 and IAM resources.
- The agent loop is client mediated. `InvokeActStep` consumes caller-supplied tool results and returns browser/tool calls; the caller or AgentCore runtime executes them.

## Live observations

- `ListWorkflowDefinitions` returned an empty inventory in `us-east-1` and created no workflow resource.
- `ListModels --client-compatibility-version 1` returned:
  - active `nova-act-v1.0`, alias `nova-act-latest`;
  - preview `nova-act-v1.1_2026-02-09`, alias `nova-act-preview`.
- CloudTrail recorded `ListWorkflowDefinitions` as a read-only default management event with source `nova-act.amazonaws.com`, Region, principal, IP, user agent and `maxResults`; `responseElements` was null.
- AWS documents definition/run/list/model calls as management events. `CreateSession`, `CreateAct`, `UpdateAct` and `InvokeActStep` are optional data events and are off by default.
- No workflow, run, session, act, export bucket, log group, AgentCore runtime, ECR repository or execution role was created.

## Data and authorization boundaries

- `exportConfig` can direct Agent Trajectory Data (prompt, screenshots, agent response) only to a same-account S3 bucket. The definition creator independently needs `s3:PutObject` on the prefix.
- Trace locations appear in run/act summaries, but location disclosure does not grant underlying S3 read permission.
- `ListWorkflowDefinitions` and `ListModels` are wildcard-only. Most child actions support definition/run scoping, and several require both parent and child resources.
- Browser-entered secrets may appear in screenshots even when code avoids placing them in `act()` prompt text.

## Attack brainstorming and disposition

| Idea | Assessment | Disposition |
| --- | --- | --- |
| Create a malicious act in an existing session | The API creates task state, but a victim client/runtime must continue the loop and execute returned calls. No automatic browser handoff or direct execution was established. | Keep private/fixture-dependent; do not publish |
| Inject forged `callResults` through `InvokeActStep` | Can influence model state when a caller owns the loop, but still requires a client to execute returned calls. At most state corruption/DoS without a victim handoff. | Reject as weak standalone technique |
| Falsify act/run status with `UpdateAct` or `UpdateWorkflowRun` | May impair monitoring or terminate state, but is noisy write access and does not erase CloudTrail or obtain data/credentials. | Reject as low-value/DoS |
| Create a definition exporting trajectories to an attacker-readable bucket | Requires same-account S3 write authorization and only affects runs deliberately started against that new definition. No update/overwrite API exists. | Too conditional; document export review only |
| Read trace/artifact location from list/get | Reveals metadata, not object content; separate S3 authorization remains required. | Enumeration only |
| Cross-account workflow access | Nova Act has no resource policies or ACLs. | Secure boundary / no technique |
| Reuse Nova Act service-linked role for browser or S3 access | Managed policy is limited to `cloudwatch:PutMetricData` in `AWS/NovaAct`; no service-role support. | Secure boundary / no technique |

## Cleanup

An unused `AWSServiceRoleForNovaAct`, created during the prior audit pass, had only `arn:aws:iam::aws:policy/aws-service-role/NovaActServiceRolePolicy`. Supported deletion task `task/aws-service-role/nova-act.amazonaws.com/AWSServiceRoleForNovaAct/3fcf4031-62b9-499a-8852-c2b36916bc72` reached `SUCCEEDED`; an exact `GetRole` then returned `NoSuchEntity`. Final Nova Act workflow inventory was empty and no Nova Act execution resource was created.

A later SageMaker telemetry preflight found that the separate audit trail `ht-nova-audit-20260929` and its dedicated bucket `ht-nova-ct-228478051196-20260929` had continued running after this audit. The trail was stopped and deleted, all generated log objects were removed, the dedicated bucket was deleted, and exact trail/bucket checks returned not found. No private AWS vulnerability report was opened.
