# Route 53 Profiles security audit — 2026-09-27

## Scope and disposition

- Service: Route 53 Profiles (`route53profiles`).
- Region/account: `us-east-1`, authorized account `228478051196`.
- Public outcome: dedicated enumeration, post-exploitation and persistence pages.
- Private outcome: no unexpected security-impacting behavior. Surprising IAM dependencies are restrictive validation checks, not authorization bypasses.
- Privilege escalation: no role-bearing API, credential vending or IAM privilege grant was found.
- Unauthenticated access: unsigned `ListProfiles` returned `MissingAuthenticationTokenException`.

## High-value attack model

Profiles amplify one DNS-resource relationship across every associated VPC. Supported resources are private hosted zones, Resolver rules, DNS Firewall groups, Resolver query-logging configurations and interface VPC endpoints. Profile-level DNSSEC, reverse-DNS and DNS-Firewall failure-mode settings also apply immediately when enabled.

The two useful attacker positions are:

1. `AssociateResourceToProfile` on a victim/shared Profile: inject or reprioritize an attacker- controlled DNS resource across the Profile's existing/future VPC associations.
2. `AssociateProfile` in a victim account: attach an attacker-owned RAM-shared Profile to a victim VPC, after which external owner mutations propagate without another victim-side write.

Disassociation is also a defense-evasion/availability action because removing one Profile resource can remove a centralized DNS control from every attached VPC.

## Current IAM model

Association operations require `Resource: "*"`; Profiles added fine-grained condition keys in 2026:

- `ResourceIds` for VPCs;
- `ResourceTypes` for HostedZone, FirewallRuleGroup, ResolverRule, ResolverQueryLoggingConfig and VPCEndpoint;
- `ResourceArns`, `HostedZoneDomains`, `ResolverRuleDomains`; and
- `FirewallRuleGroupPriority`.

Only tagging operations currently expose Profile/Profile-association IAM resource types. RAM also enforces its managed permission. The default consumer permission allows read and VPC association; consumer resource attachment needs a custom RAM permission.

## Live tests

### Exact-VPC association

Created an empty Profile and a role with only `route53profiles:AssociateProfile`. The call reached a service `ValidationException` requiring `ec2:DescribeVpcs`. Adding only `ec2:DescribeVpcs` plus an exact `route53profiles:ResourceIds` condition for `vpc-027af22d687e33781` allowed association `rpassoc-fa6c4298628f441e` to reach `COMPLETE`.

The empty association was immediately disassociated. It spent roughly five minutes converging through `CREATING` and `DELETING`. Route 53 Profiles charges $0.75 per owner account-hour for the first 100 Profile/VPC associations, so the test stayed below the authorized cost ceiling.

### Private-hosted-zone association

Created a unique private `.invalid` zone, an empty Profile and a role with only `AssociateResourceToProfile` conditioned to `ResourceTypes=HostedZone`. The request passed that action gate but failed with an internal service error naming the missing exact `route53:GetHostedZone` permission. Adding only `route53:GetHostedZone` on the test-zone ARN allowed association `rpr-0042d9199492ce543e6` to reach `COMPLETE`; no broader Route 53 permission was granted.

A stricter preliminary policy combining type, domain and ARN conditions was denied at the Profile action gate. Because this is restrictive and the condition interaction was not isolated further, it is retained here as a retest item rather than reported as a security issue or generalized publicly.

The Profile was never associated to a VPC during the hosted-zone test, so the zone never propagated through Profiles and no test DNS answer was served through it.

### Logging

All Profile operations appeared as default CloudTrail management events under `route53profiles.amazonaws.com`. Repeated `GetProfileAssociation` and `GetProfileResourceAssociation` reads recorded identifiers and `responseElements: null`. Create, associate, disassociate and delete writes recorded request parameters; delete responses exposed the resource state/identifier. Underlying Route 53, EC2 and RAM operations retain their own event sources.

## Cleanup proof

Final checks returned:

- `ProfileSummaries[starts_with(Name, 'ht-r53p-')] = []`;
- no hosted zone containing `ht-type`;
- no IAM role starting `ht-r53p-`; and
- no Profile/VPC or Profile/resource association from either test.

No RAM share, Resolver endpoint/rule, DNS Firewall resource, query-log destination, interface endpoint or compute fixture was created.

## Attack idea matrix

| Idea | Result | Disposition |
| --- | --- | --- |
| Attach malicious private zone | Supported and minimum Profile + exact Route 53 read verified | Post-exploitation |
| Attach forwarding rule | Supported; requires an existing usable rule/endpoint | Post-exploitation with prerequisite |
| Attach/reprioritize Firewall group | Supported; priority condition key now available | Post-exploitation/defense evasion |
| Attach query logging | Supported; value depends on destination access/ownership | Post-exploitation |
| Attach interface endpoint | Supported; inspect owner, service and endpoint policy | Post-exploitation |
| Attach attacker-owned Profile cross-account | Default RAM consumer can associate to its VPCs | Post-exploitation + persistence |
| Replace an existing VPC Profile silently | Rejected; one Profile per VPC and conflict fails | Limitation documented |
| Native IAM privilege escalation | No role or credential-bearing API | Rejected |
| Unauthenticated inventory | Missing authentication token | Rejected |
