# AWS Artifact expected-functionality audit — 2026-09-29

## Inventory and model coverage

- `ListReports` returned 397 available AWS/third-party reports; 63 used explicit terms acceptance.
- Commercial report ARNs returned through both allowed endpoints used `us-east-1` in the ARN. Policies
  and direct calls should preserve the service-returned ARN rather than synthesize it from the endpoint.
- The installed AWS CLI 2.34.45 exposes the older report/account-settings/customer-agreement listing
  surface. Current official APIs additionally expose agreement workflows and Assurance Assistant
  inquiry operations. Read-only direct SigV4 requests confirmed the newer service endpoints exist.
- The account had ten available account-scoped agreements, no accepted customer agreements, and no
  compliance inquiries. No agreement write or report/inquiry document download was performed.

## Published expected techniques

| Surface | Minimum useful boundary | Impact / constraints |
| --- | --- | --- |
| Artifact report retrieval | Exact-report `GetTermForReport` + `GetReport`; known ID/version | Generates a short-lived AWS-owned S3 URL for a confidential, uniquely watermarked report. No customer S3 permission. |
| Agreement acceptance | List on `*`, then the exact agreement workflow actions/ARN and returned tokens/revision | Durable legal/compliance state, potentially organization-wide only with the documented management-account prerequisites. Not IAM escalation. |
| Agreement termination | List on `*`, then exact customer-agreement `GetCustomerAgreement` + `TerminateAgreement` and returned token | Legal/compliance disruption. No active agreement existed, so the write was not attempted. |
| Assurance Assistant inquiry reads/export | List on `*`, then exact-inquiry metadata/query/export actions | Questionnaire, generated-answer, citation, review, revision, metadata/tag, and exported-document disclosure. No inquiry existed for runtime response validation. |

## Telemetry and safe runtime observations

- Report terms and report-URL generation are read-only Artifact management events. The presigned URL
  points at the AWS-owned `artifact-assets-prod-us-east-1` bucket and was approximately 15 minutes in
  the observed run. No URL was redeemed.
- Report list/version operations record their request identifiers/pagination and omit response bodies.
- Agreement reads were performed only where they could not change legal state. `GetNdaForAgreement`
  respected an exact agreement ARN; another agreement was denied to the restricted session.
- Acceptance and termination were deliberately not executed. Their documented write events and
  durable service state make them very noisy.
- New Assurance Assistant CloudTrail event fields remain open for a future account with an inquiry;
  public coverage states the expected management-event boundary without inventing response logging.

## Rejected or bounded ideas

- There is no generic Artifact “portal token.” Current bearer-like values belong to report terms,
  agreement/NDA workflow steps, and presigned document URLs.
- Artifact report presigned URLs do not imply customer-bucket `s3:GetObject`; they target AWS-owned
  storage. Treat URL possession as the download authorization.
- Agreement writes are serious legal/compliance changes, not AWS privilege escalation or persistence.

## Cleanup

- All disposable IAM roles and inline policies used for minimum-permission checking were deleted.
- Independent IAM inventory contained no roles beginning with `ht-artifact-`.
- No report, NDA, agreement, or inquiry document was downloaded; no persistent Artifact resource was
  created or changed.
