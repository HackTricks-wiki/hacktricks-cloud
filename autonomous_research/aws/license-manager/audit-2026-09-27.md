| Create external license grant | Expected durable cross-account entitlement distribution with caller-selected allowed operations | Added as post-exploitation; explicitly not IAM/account persistence |
| Tamper self-managed configuration/association | Exact config-scoped actions can impose hard limits or change supported-resource associations | Added as availability/compliance post-exploitation |
| Start/stop user subscriptions and associate/disassociate users | Exact identity-provider-scoped actions create billing and software-access effects | Added as post-exploitation; no OS/IAM privilege claim |
| Asset-group and organization discovery | Broad software/instance/license estate metadata, no credentials | Added to enumeration |
| Linux provider `SecretArn` and user identity-provider `SecretId` disclosure | APIs return secret references, not values | Added to enumeration as pivots for a separate Secrets Manager/KMS review |
| Custom ruleset script to SSM RCE | Disproved: script statements are rejected for customer rulesets and SendCommand is restricted to Amazon-owned License Manager documents | Excluded |
| `CreateToken` plus License Manager OIDC | Real bearer-token feature but requires a seller license and a separately weak compatible role trust; standard consumption role is not broad privilege escalation | Kept only in the prior reasoned exclusion |
| Linux provider as arbitrary secret-exfiltration deputy | Service role reads only same-account secrets and KMS keys with an exact enablement tag; destination/consumer is the fixed provider workflow and no caller-readable secret output exists | Excluded pending evidence of an observable exfiltration channel |
| Self-managed AD registration as secret relay | Service role can read `license-manager-user-*` secrets and self-managed AD setup accepts domain/IP/network settings. ## Important IAM boundaries

- `CheckoutBorrowLicense` and `CreateGrant` support the exact seller-license ARN; `CheckoutLicense`
  requires `Resource: "*"`.
- `UpdateLicenseConfiguration` and `UpdateLicenseSpecificationsForResource` authorize against the
  exact license-configuration ARN and support resource-tag conditions.
- User-subscription `StartProductSubscription` and `AssociateUser` authorize against the exact
  identity-provider ARN. Starting a paid subscription is not a safe validation call.
- Linux `RegisterSubscriptionProvider` requires `Resource: "*"`; read/delete/tag operations on an
  existing provider support its exact ARN.
- The Linux service-linked role can call `secretsmanager:GetSecretValue` only for same-account
  secrets tagged `LicenseManagerLinuxSubscriptions=enabled`, and `kms:Decrypt` only for similarly
  tagged same-account keys via Secrets Manager.
- The user-subscription service-linked role can read Secrets Manager resources whose names begin
  `license-manager-user-`; customer-managed KMS use additionally depends on a key policy allowing
  that service-linked role.

## Logging

Core License Manager documentation states that all License Manager actions are captured by
CloudTrail. Live failures appeared as management events under:

- `license-manager.amazonaws.com`
- `license-manager-linux-subscriptions.amazonaws.com`

User-subscription operations use
`license-manager-user-subscriptions.amazonaws.com`. State-changing checkout, grants, configuration
updates, subscriptions and user associations should be treated as low-stealth because they also
leave service, usage or billing state.
