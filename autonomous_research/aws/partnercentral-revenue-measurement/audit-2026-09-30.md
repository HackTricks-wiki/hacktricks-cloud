# AWS Partner Central Revenue Measurement audit — 2026-09-30

## Result

The September 2026 `partnercentral-revenue-measurement` client adds a material partner-commercial data plane:

- Revenue Attribution reads expose customer AWS account IDs, Marketplace offer or Partner Central opportunity identifiers/names, product metadata, percentages and effective windows.
- `StartRevenueAttributionAllocationsTask` can create/update as many as 250 deal allocations under one exact attribution resource.
- Marketplace Revenue Share allocation writes change the partner-declared product percentage AWS uses when correlating Marketplace revenue against other revenue signals.

Added the missing enumeration page and two expected-functionality post-exploitation techniques: commercial intelligence recovery and attribution/reporting poisoning. No AWS vulnerability candidate was found.

## New-service provenance and endpoint

The installed AWS CLI 2.34.45 does not include this client. AWS CLI 2.37.6 includes 18 operations across Revenue Attribution and Marketplace Revenue Share resources. The IAM action prefix is `partnercentral`, while the CloudTrail/API source is `partnercentral-prm.amazonaws.com`.

Every commercial Region input resolves to `partnercentral-prm.global.api.aws` and uses SigV4a. Live calls made with both `us-east-1` and `eu-west-1` were recorded centrally in the `us-east-1` Event History.

## Impact boundary

The similar names are easy to overstate:

- Marketplace Revenue Share is documented as a partner-supplied measurement input declaring the portion of product revenue collected through Marketplace. It feeds revenue correlation/calculation; it is not an AWS Marketplace seller disbursement split.
- Revenue Attribution maps already measured product revenue to offer/opportunity deals and monthly percentages.
- The resulting measurements inform Partner Central dashboards and are described by AWS as inputs to partner recognition, programs, benefits and investment decisions.

Accordingly, the public technique claims commercial intelligence loss and corruption of attribution/partner metrics. It explicitly does not claim customer billing changes, Marketplace payout redirection, modification of the underlying offer/opportunity, or AWS IAM escalation.

## Inventory and authentication

Administrator inventory returned empty arrays for all four combinations of `AWS`/`Sandbox` catalog and `us-east-1`/`eu-west-1` Region input. An unsigned list failed with `MissingAuthenticationTokenException`.

The empty reads succeeded even though this lab is not an AWS Partner. A safely targeted allocation-task request against a nonexistent attribution reached a separate service-side denial: the account is not registered as an AWS Partner. No task or allocation was created.

## Least-privilege authorization

AWS-managed policy inspection and restricted session-policy probes established:

| Probe | Result | Conclusion |
| --- | --- | --- |
| `ListRevenueAttributions`, `Resource: "*"`, `Catalog=AWS` | Empty success | List is wildcard-resource and production catalog can be condition-limited |
| Same session, `Catalog=Sandbox` | Access denied on the Sandbox catalog ARN | `partnercentral:Catalog` is enforced |
| Exact-attribution `GetRevenueAttribution` | IAM passed, then `ResourceNotFoundException` | Getter binds to the exact requested parent ARN |
| Different attribution ARN in policy | Access denied on requested ARN | Cross-resource A/B control held |
| Exact-attribution `UpdateRevenueAttribution` | IAM passed, then `ResourceNotFoundException` | Update binds to the exact parent ARN |
| Exact-attribution `StartRevenueAttributionAllocationsTask` | IAM passed, then partner-registration denial | Batch write binds to exact parent and has a business-onboarding gate |
| Different attribution ARN for task | IAM access denied | Exact-resource A/B control held |
| Exact-share Get/GetAllocation/UpdateAllocation | IAM passed, then parent `ResourceNotFoundException` | Child access/update authorizes against the exact parent share ARN |
| Different share ARN | IAM access denied | Exact-resource A/B control held |

Creation and list actions in `AWSPartnerCentralRevenueAttributionManagement` use `Resource: "*"`. Targeted attribution operations use `catalog/*/revenue-attribution/*`; targeted Marketplace-share operations use `catalog/*/marketplace-revenue-share/*`. Every Revenue Measurement statement in that policy also uses the `partnercentral:Catalog` condition.

No create call was tested: revenue attributions and shares have no delete operation in the current API, so even a Sandbox fixture could leave permanent account state. This irreversible-lifecycle boundary is the reason to use nonexistent-resource authorization probes.

## Telemetry

CloudTrail indexed the calls in `us-east-1` under `partnercentral-prm.amazonaws.com`:

- successful and failed list/get calls were default management reads;
- `UpdateRevenueAttribution` was a management write;
- the write request retained catalog, identifier, generated client token, description and revision;
- the allocation-task request retained its entity type/identifier, percentage, dates, revision and description but replaced `customerAwsAccountId` with `HIDDEN_DUE_TO_SECURITY_REASONS`;
- exact-resource access denials omitted request parameters, while post-IAM resource-not-found failures retained them;
- synthetic nonexistent-resource events had no `resources` array and response bodies were null.

The docs' generic Partner Central CloudTrail page does not currently name the new PRM event source. The live source above is therefore recorded explicitly for defenders.

## Cleanup

No Revenue Attribution, allocation, Marketplace Revenue Share, allocation task, tag, IAM resource, Marketplace object, Partner Central object or other fixture was created or changed. Only empty reads, unsigned controls, nonexistent-resource authorization probes and expiring STS sessions were used. Final production and Sandbox inventories remain empty in both allowed Region inputs.
