# AWS Backup Search audit — 2026-09-27

## Decision

Publish the service inventory and the existing-result metadata read/export path. Do not publish
`StartSearchJob` by itself as an attack: without an eligible indexed recovery point it has no useful
result, and its required `backup:*` permissions already authorize searching the protected backup.

## Current authorization surface

- The current Backup Search model exposes 12 operations.
- Search jobs use
  `arn:aws:backup-search:<region>:<account>:search-job/<id>`; export jobs use
  `arn:aws:backup-search:<region>:<account>:search-export-job/<id>`.
- `GetSearchJob`, `ListSearchJobBackups`, and `ListSearchJobResults` support the exact search-job
  resource. Creating a search additionally depends on
  `backup:ListIndexedRecoveryPointsForSearch` and `backup:SearchRecoveryPoint`.
- `StartSearchResultExportJob` depends on `iam:PassRole`. The role writes the materialized result to
  S3; it is not a general-purpose source-data execution role.

## Safe live checks

Preflight in account `228478051196`, `us-east-1`, found zero search jobs, zero result-export jobs,
and zero indexed recovery points. Search jobs cannot be deleted and their records remain for seven
days, so no paid or retained job was created merely to exercise result retrieval.

A disposable caller was granted only these actions on one exact, nonexistent synthetic job ARN:

```text
backup-search:GetSearchJob
backup-search:ListSearchJobBackups
backup-search:ListSearchJobResults
```

All three calls passed IAM authorization and reached `ResourceNotFoundException`. The role had no
Backup, S3, EBS, or KMS permissions. This isolates authorization of existing results to the
search-job resource. CloudTrail Event History contained `GetSearchJob` and
`ListSearchJobBackups` as management reads with `eventSource=backup.amazonaws.com`.
`ListSearchJobResults` was absent, matching the documented Backup Search data-event resource type
`AWS::Backup::SearchJob`.

## Export PassRole matrix

The same nonexistent job ID was used so no export could be created:

| Caller policy | Result |
| --- | --- |
| `StartSearchResultExportJob` only | Explicit `iam:PassRole` denial |
| Plus unconditional `iam:PassRole` on the exact role ARN | Reached `Search job not found` |
| Plus exact-role PassRole conditioned on `iam:PassedToService=backup.amazonaws.com` | Explicit `iam:PassRole` denial |

The Service Authorization Reference documents the PassRole dependency but no usable passed-to-service
value. Public guidance therefore scopes the grant to the exact role ARN and does not invent a service
condition. An attempted trust-policy principal of `backup-search.amazonaws.com` was rejected as an
invalid principal before testing and is not presented as a valid trust configuration.

## Result sensitivity

Documented S3 result fields include backup/source ARNs, vault name, object key, object size,
creation time, ETag, and version ID. Documented EBS result fields include backup/source ARNs, vault
name, filesystem identifier, file path, file size, creation time, and last-modified time. These are
valuable reconnaissance metadata, not the underlying bytes.

## Cleanup proof

Final inventory:

```text
search_jobs=0
export_jobs=0
indexed_recovery_points=0
audit_roles(prefix ht-bs-)=0
```

No bucket, recovery point, KMS key, search job, or export job was created. No unexpected security
defect was found and no private vulnerability report was opened.
