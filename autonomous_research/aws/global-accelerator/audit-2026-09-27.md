# AWS Global Accelerator audit - 2026-09-27

- Authorized account: `228478051196`; Global Accelerator control plane and monitoring Region: `us-west-2`.
- Starting inventory: zero standard accelerators, custom routing accelerators, cross-account attachments and BYOIP CIDRs.

## Verified standard-accelerator results

### Wildcard-only lists and exact describes

A session policy allowing `globalaccelerator:ListAccelerators` on one exact accelerator ARN was denied. The same session's exact-ARN `DescribeAccelerator` succeeded and returned the name, enabled/status fields, generated DNS name and both static IPv4 addresses.

Unsigned `ListAccelerators` returned `MissingAuthenticationTokenException`. The generated hostname resolved publicly to the two static addresses even while the accelerator was disabled. This is expected public-DNS behavior, not an inventory/authentication defect.

### `UpdateEndpointGroup` is a full routing mutation

Fixture:

```text
disabled standard accelerator
TCP listener: 18080
endpoint group: us-east-1
original endpoint: EIP A, weight 128
replacement endpoint: EIP B
```

A least-privilege role session had only:

```json
{
  "Effect": "Allow",
  "Action": "globalaccelerator:UpdateEndpointGroup",
  "Resource": "<exact endpoint-group ARN>"
}
```

It could not call `DescribeEndpointGroup`, and it had no `AddEndpoints` or `RemoveEndpoints`. Nevertheless, one `UpdateEndpointGroup` request succeeded and returned:

```json
{
  "TrafficDialPercentage": 0.0,
  "HealthCheckPort": 65000,
  "HealthCheckProtocol": "TCP",
  "HealthCheckIntervalSeconds": 10,
  "ThresholdCount": 10,
  "EndpointDescriptions": [{
    "EndpointId": "<EIP B allocation ID>",
    "Weight": 0,
    "HealthState": "UNHEALTHY",
    "ClientIPPreservationEnabled": false
  }],
  "PortOverrides": [{"ListenerPort": 18080, "EndpointPort": 18081}]
}
```

This proves that the action can replace the full endpoint list and alter every principal routing/health control. It is expected API behavior and explicitly reflected by the API input model, not an authorization bypass. The defensive insight is that denying the narrower `AddEndpoints`/`RemoveEndpoints` actions does not constrain this update permission.

### Listener, accelerator and flow-log controls

- Exact-listener `UpdateListener` changed TCP port 18080 / affinity `NONE` to UDP ports 18081-18082 / `SOURCE_IP` without any describe permission.
- Exact-accelerator `UpdateAccelerator` renamed the accelerator and accepted the disabled state. AWS documents the same operation as the enable/disable control.
- Exact-accelerator `UpdateAcceleratorAttributes` independently accepted flow logs disabled plus a replacement S3 bucket/prefix field. Flow-log enabling/redirection was not tested because a service-writable logging bucket was not needed to prove the anti-forensics permission boundary. Do not treat the action as an arbitrary S3 write primitive.

### Cross-account attachment

`CreateCrossAccountAttachment` accepted:

```text
resource: victim-owned us-east-1 EIP ARN
principal: AWS account 418720621023
```

No consent or action from the principal account was required to create the share. This matches the documented owner-controlled sharing model. Full consumption from the second account was not attempted because its caller intentionally had no Global Accelerator identity permissions.

The meaningful persistence result is service/resource level: the external principal can use the listed resource with an authorized accelerator, but the attachment does not grant permission to modify the endpoint or provide general account access.

## Custom routing test and documented boundary

A disabled custom routing accelerator, a 32-port listener, an endpoint group for TCP/9000, and an isolated `/28` subnet were created. `AddCustomRoutingEndpoints` rejected the subnet because its temporary VPC had no internet gateway:

```text
InvalidArgumentException: <subnet> does not have an internet gateway in its VPC <vpc>
```

The fixture and VPC were immediately deleted. Per coordination scope, the test was not repeated with an internet gateway. The rejection confirms an important endpoint prerequisite; it is not a security defect.

The book's custom-routing coverage is limited to AWS-authoritative behavior: mappings correlate public ports with private destination sockets, traffic is denied by default, and `AllowCustomRoutingTraffic` can enable a specific destination or every destination in the subnet. No claim of a custom-routing authorization bypass is made.

## CloudTrail and data-plane logging

- AWS documents every Global Accelerator API as a CloudTrail management event and requires Event History to be viewed in `us-west-2`.
- This organization has an SCP that explicitly denies `cloudtrail:LookupEvents` in `us-west-2`. Lookup in `us-east-1` was permitted but correctly returned no Global Accelerator events. Therefore exact live request/response redaction fields could not be validated.
- The pages report named CloudTrail events and Region based on the authoritative integration documentation, without claiming locally observed response contents.
- Global Accelerator flow logs are opt-in S3 records, not CloudTrail data events. They include client/accelerator/endpoint addresses and ports, protocol, packet/byte counts, timestamps, action/status, edge/endpoint Regions, direction, and VPC/rejection fields where applicable.
- DNS lookups do not generate CloudTrail. Accelerator connections generate metrics and optional flow logs, not per-connection CloudTrail API events.

## Candidate vulnerabilities tested and rejected

- **Unsigned control-plane inventory:** rejected with `MissingAuthenticationTokenException`.
- **Wildcard/list resource-scope bypass:** rejected. Exact-resource `ListAccelerators` was denied as documented.
- **Endpoint mutation without `UpdateEndpointGroup`:** not found. The broad update behavior is explicitly part of that granted action, not a bypass of it.
- **Cross-account use of unowned resources:** rejected by design/documentation; an attachment owner must own the endpoint or BYOIP pool.
- **Cross-account attachment as endpoint modification/account access:** rejected. It grants use in an accelerator, not control of the shared resource.
- **Flow-log destination as arbitrary S3 write:** not established. Enabling delivery requires an S3 destination that permits the service.
- **Custom routing to a subnet without required public VPC edge:** rejected because an attached internet gateway is required.
- **Unauthenticated account-wide DNS discovery:** not found. Known names resolve publicly, but the generated label is opaque and the API remains authenticated.
- **BYOIP hijack without an owned/provisioned prefix:** not possible through the API model; no pool existed and destructive route operations were not invoked.

No unexpected AWS security defect or zero-day was confirmed, so no private bug-bounty report was created.
