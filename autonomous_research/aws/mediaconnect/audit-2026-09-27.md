## Scope and starting state

- Region: `us-east-1`; authorized target account `228478051196`.
- Initial inventory: zero flows, received entitlements, gateways, bridges, reservations, router inputs, router outputs and router network interfaces.
- No existing MediaConnect service, post-exploitation, persistence or research page was found. The generic media unauthenticated page contained only MediaConvert, MediaPackage and MediaStore URL templates.

## Verified results worth documenting

### Enumeration and sensitive reads

- `ListFlows` and `ListEntitlements` required `Resource: "*"`. An exact flow resource did not authorize `ListFlows`; the denial identified the synthetic `flow:*` list resource.
- Exact-flow `DescribeFlow` succeeded without list permission and returned source ingress IP/port, allowlist, source/output ARNs and protocols, destination IP/port, Availability Zone, status, subscriber account ID, and entitlement details.
- Exact-flow `DescribeFlowSourceMetadata` authorized correctly. On a standby flow it returned a service-state error; while active it returned program number/name, PCR/program/stream PIDs, H.264 codec and frame rate, and AAC channel/sample properties.
- Exact-flow `DescribeFlowSourceThumbnail` authorized correctly. With monitoring enabled and a healthy source it returned a base64 JPEG of the synthetic live stream.
- Encryption objects in API models expose role and secret ARNs, not Secrets Manager secret values.

### IAM parent/child resource enforcement

Live session-policy probes confirmed that each of these child writes needs both the parent flow and child resource ARN:

| Operation | Child-only allow | Parent + child allow |
| --- | --- | --- |
| `UpdateFlowSource` | Denied on the flow ARN | Succeeded |
| `UpdateFlowOutput` | Denied on the flow ARN | Succeeded |
| `UpdateFlowEntitlement` | Denied on the flow ARN | Succeeded |
| `AddFlowOutputs` | Not used child-only | Succeeded with flow + prospective output ARN |
| `GrantFlowEntitlements` | Not used child-only | Succeeded with flow + prospective entitlement ARN; tagged request also had `TagResource` |

This matches the starred resource types in the service authorization reference and is an important least-privilege review trap.

### Cross-account entitlement persistence

- `GrantFlowEntitlements` accepted subscriber account `418720621023` and returned an enabled entitlement.
- The base account user intentionally had no MediaConnect identity policy, so `ListEntitlements` and subscriber-side `CreateFlow` were denied at IAM. Full subscriber consumption was not forced by modifying that account.
- AWS's documented entitlement flow confirms that a subscriber with its own permissions can create one same-Region flow from the entitlement, producing a corresponding originator output.
- This is expected cross-account sharing and a strong service-level persistence path, not an AWS defect.

### Unauthenticated RTP ingress

- Unsigned MediaConnect API `ListFlows` and `DescribeFlow` requests returned `MissingAuthenticationTokenException`.
- In contrast, the media plane behaved according to its configuration: an active public RTP source with `WhitelistCidr=0.0.0.0/0` accepted a stream sent without AWS credentials or protocol authentication.
- MediaConnect parsed the anonymous synthetic stream into an H.264/AAC program map and generated its thumbnail. This confirms a practical content-injection condition when customers expose an RTP listener to arbitrary source IPs.
- The result is expected RTP/configuration behavior. It should be documented as a misconfiguration technique, not reported as a zero-day.

### Router and hybrid topology

- All router and gateway/bridge inventories were empty.
- The current authorization model exposes exact-resource `GetRouterInput`, `GetRouterInputSourceMetadata`, `GetRouterInputThumbnail`, `GetRouterOutput` and `GetRouterNetworkInterface` reads.
- `TakeRouterInput` is scoped to the router-output ARN and persistently changes the input feeding that output. Create/update router operations can require dependent network-interface, flow source/output and `iam:PassRole` actions.
- No router/gateway fixtures were created because they require materially broader networking/hybrid setup than needed to validate the flow findings.

### CloudTrail and detection observations

- MediaConnect control-plane reads and writes appeared as CloudTrail management events with `eventSource=mediaconnect.amazonaws.com`.
- Observed read events included caller/source details and a URL-encoded ARN in `requestParameters`, but `resources` was empty and `responseElements` was `null`. The flow configuration, transport metadata and JPEG were therefore absent from Event History.
- `CreateFlow`, `AddFlowOutputs`, `GrantFlowEntitlements`, update calls, `StartFlow`, polling `DescribeFlow`, output removal and thumbnail reads were all visible after normal delivery delay.
- RTP packets did not generate individual CloudTrail events. Detection needs MediaConnect/CloudWatch source bitrate, packet/continuity/error metrics, expected sender IPs and content monitoring.

## Candidate vulnerabilities tested and rejected

- **Unsigned control-plane enumeration:** rejected with `MissingAuthenticationTokenException`.
- **Resource-scope bypass on flow children:** rejected; writes enforced the parent flow plus child ARN exactly as documented.
- **Content reads under generic `DescribeFlow`:** rejected; metadata and thumbnails required their separate exact-flow permissions.
- **Secret-value disclosure:** not found. Configuration can reveal secret/role ARNs but not the secret material.
- **Generic `iam:PassRole` credential extraction:** not found. MediaConnect documents `PassRole` only for its encryption/VPC/router integrations, and no response returns assumed-role credentials.
- **Cross-account access without entitlement:** no resource-policy or anonymous path was found. The intended entitlement requires an explicit subscriber account and subscriber-side IAM.
- **Open RTP listener as AWS authorization bypass:** rejected as a vulnerability. Acceptance exactly followed the configured public address, active state and `0.0.0.0/0` allowlist.
- **CloudTrail response omission:** treated as documented/normal management-event behavior, not a logging defect; the API call itself remained visible.
