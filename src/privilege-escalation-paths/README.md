# Διαδρομές κλιμάκωσης προνομίων

{{#include ../banners/hacktricks-training.md}}

Το HackTricks Cloud διατηρεί τον μηχαναγνώσιμο κατάλογο κλιμάκωσης προνομίων που χρησιμοποιεί το [Blue-CloudPEASS](https://github.com/peass-ng/Blue-CloudPEASS). Κάθε τεχνική αναφέρει ποια δικαιώματα πρέπει να έχει ουσιαστικά ένας principal και σε ποιους πόρους, ώστε να αποκτήσει τα προνόμια ενός συνόλου principals-στόχων. Το Blue-CloudPEASS αξιολογεί αυτές τις εγγραφές εκτός σύνδεσης, με βάση ένα στιγμιότυπο απογραφής μόνο για ανάγνωση, και απεικονίζει διαδρομές επίθεσης από principal σε principal, παραθέτοντας ως τεκμήριο την πολιτική ή τη σύνδεση που παραχωρεί τα δικαιώματα, καθώς και τον μετριασμό που καταργεί τη διαδρομή. Επεξεργαστείτε εδώ τα κανονικά αρχεία και όχι τα αντίγραφά τους στον καταναλωτή.

Οι εγγραφές περιγράφουν μόνο τις προϋποθέσεις, τους προσβάσιμους στόχους και τον μετριασμό. Δεν περιέχουν εντολές, payloads ή βήματα εκτέλεσης· η συνδεδεμένη σελίδα του HackTricks εξηγεί την τεχνική.

## Δομή

Υπάρχει ένας κατάλογος ανά πλατφόρμα (`aws`, `gcp`, `azure`, `k8s`) και ένα αρχείο `<service>.yaml` ανά υπηρεσία, το καθένα από τα οποία περιέχει μια λίστα τεχνικών σε YAML. Τα αρχεία με ονόματα `_excluded*.yaml` καταγράφουν τεχνικές του HackTricks που εξετάστηκαν και σκόπιμα δεν έχουν εγγραφή, όπως τεχνικές post-exploitation, persistence ή τεχνικές που δεν μπορούν να μοντελοποιηθούν από τις ρυθμίσεις, μαζί με την αιτιολογία. Το `privesc-technique.schema.json` είναι το εξαγόμενο JSON Schema για αυτόματη συμπλήρωση και επικύρωση στον editor.

## Πεδία τεχνικής

- `id`: καθολικά μοναδικό, με πεζούς χαρακτήρες και kebab-case, με πρόθεμα την πλατφόρμα.
- `provider`, `service`, `title` και `summary`: μία πρόταση που περιγράφει τι αποκτά η πηγή.
- `source`: η σελίδα και το anchor του HackTricks που τεκμηριώνουν την τεχνική, σε σχέση με αυτό το βιβλίο. Το `source_revision` είναι το commit του βιβλίου που εξετάστηκε.
- `requires`: τα δικαιώματα που πρέπει να έχει η πηγή. Το `all_of` περιλαμβάνει όλα τα απαιτούμενα στοιχεία και το `any_of` τις εναλλακτικές. Τα στοιχεία AWS και GCP χρησιμοποιούν `action` και `resource`, τα στοιχεία Azure χρησιμοποιούν `action` (ή `data_action`) και `scope`, τα στοιχεία Entra ID χρησιμοποιούν `entra_permission` ή `entra_role`, ενώ τα στοιχεία Kubernetes χρησιμοποιούν `verb`, `resource`, `subresource`, `api_group` και `namespace`. Τα placeholders όπως `{target.arn}` συνδέουν μια απαίτηση με τον στόχο.
- `target`: το `kind` του στόχου, ένα `selector` του οποίου όλες οι συνθήκες πρέπει να ισχύουν για να είναι προσβάσιμος ένας principal, και το `scope` του.
- `conditions` και `blockers`: ό,τι μπορεί να εμποδίσει τη διαδρομή στην πράξη, όπως condition keys, SCPs, όρια ή πολιτικές admission.
- `confidence`, `severity`, `mitigation`, `references` και προαιρετικά `notes`.

Τα άγνωστα πεδία, τα είδη στόχων, τα κλειδιά selector και τα placeholders απορρίπτονται αντί να αγνοούνται, ώστε μια εγγραφή να μην μπορεί ποτέ να διευρύνει ή να περιορίσει σιωπηρά το σύνολο των στόχων της. Προσθέστε πρώτα υποστήριξη για νέο selector στον evaluator του καταναλωτή.

## Επικύρωση και συγχρονισμός

Εκτελέστε `python scripts/validate_privesc_paths.py --book-root .` με εγκατεστημένο το PyYAML πριν υποβάλετε αλλαγές. Ελέγχει τη δομή των καταλόγων, κάθε εγγραφή με τον strict loader του evaluator (`scripts/privesc_paths_schema.py`, αντίγραφο της μονάδας schema του Blue-CloudPEASS), τη μοναδικότητα των id, την ύπαρξη κάθε σελίδας `source` σε αυτό το βιβλίο και την επικαιρότητα του JSON Schema. Η ροή εργασιών pull request του βιβλίου εκτελεί την ίδια επικύρωση.

Κάθε Δευτέρα, το Blue-CloudPEASS κάνει checkout το τρέχον `master` αυτού του βιβλίου, επικυρώνει αυτά τα αρχεία και συγκρίνει το SHA-256 hash κάθε αρχείου με τα hash που καταγράφηκαν στον προηγούμενο συγχρονισμό. Οι προσθήκες, ενημερώσεις και διαγραφές upstream αντικαθιστούν τα αμετάβλητα αντίγραφα στον καταναλωτή. Αν ένα αρχείο έχει αλλάξει και στις δύο πλευρές, αναφέρεται ως διένεξη, ενώ τα id των τεχνικών δεν αφαιρούνται ποτέ χωρίς ρητό, εξετασμένο ledger. Άκυρο περιεχόμενο ή αποτυχία δοκιμής αφήνει αμετάβλητο τον προεπιλεγμένο κλάδο του καταναλωτή. Άσχετες αλλαγές στο βιβλίο δεν δημιουργούν commit στον καταναλωτή.
