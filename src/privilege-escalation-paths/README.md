# Διαδρομές κλιμάκωσης προνομίων

{{#include ../banners/hacktricks-training.md}}

Το HackTricks Cloud διατηρεί τον κατάλογο κλιμάκωσης προνομίων σε μορφή αναγνώσιμη από μηχανές, τον οποίο χρησιμοποιεί το [Blue-CloudPEASS](https://github.com/peass-ng/Blue-CloudPEASS). Κάθε τεχνική δηλώνει ποια δικαιώματα πρέπει να έχει ουσιαστικά μια αρχή και σε ποιους πόρους, ώστε να αποκτήσει τα προνόμια ενός συνόλου αρχών-στόχων. Το Blue-CloudPEASS αξιολογεί αυτές τις εγγραφές εκτός σύνδεσης, με βάση ένα στιγμιότυπο απογραφής μόνο για ανάγνωση, και σχεδιάζει διαδρομές επίθεσης από αρχή σε αρχή, χρησιμοποιώντας ως τεκμήριο την πολιτική ή τη σύνδεση που εκχωρεί τα δικαιώματα και ως μετριασμό την αλλαγή που καταργεί τη διαδρομή. Επεξεργαστείτε εδώ τα κανονικά αρχεία, όχι τα αντίγραφά τους στον καταναλωτή.

Οι εγγραφές περιγράφουν μόνο τις προϋποθέσεις, τους προσβάσιμους στόχους και τον μετριασμό. Δεν περιέχουν εντολές, payloads ή βήματα εκτέλεσης· η συνδεδεμένη σελίδα του HackTricks εξηγεί την τεχνική.

## Δομή

Υπάρχει ένας κατάλογος ανά πλατφόρμα (`aws`, `gcp`, `azure`, `k8s`) και ένα αρχείο `<service>.yaml` ανά υπηρεσία, το καθένα με μια λίστα τεχνικών σε YAML. Τα αρχεία με όνομα `_excluded*.yaml` απαριθμούν τεχνικές του HackTricks που έχουν ελεγχθεί αλλά σκόπιμα δεν έχουν εγγραφή, όπως post-exploitation, persistence ή τεχνικές που δεν μπορούν να μοντελοποιηθούν βάσει διαμόρφωσης, μαζί με τον λόγο. Το `privesc-technique.schema.json` είναι το εξαγόμενο JSON Schema για αυτόματη συμπλήρωση και επικύρωση στον επεξεργαστή.

## Πεδία τεχνικής

- `id`: καθολικά μοναδικό, πεζό και σε μορφή kebab-case, με πρόθεμα την πλατφόρμα.
- `provider`, `service`, `title` και `summary`: μία πρόταση που περιγράφει τι αποκτά η πηγή.
- `source`: η σελίδα και η άγκυρα του HackTricks που τεκμηριώνουν την τεχνική, σε σχέση με αυτό το βιβλίο. Το `source_revision` είναι το commit του βιβλίου που εξετάστηκε.
- `requires`: τα δικαιώματα που πρέπει να έχει η πηγή. Το `all_of` απαριθμεί όλα τα απαιτούμενα στοιχεία και το `any_of` τις εναλλακτικές. Τα στοιχεία AWS και GCP χρησιμοποιούν `action` και `resource`, τα στοιχεία Azure χρησιμοποιούν `action` (ή `data_action`) και `scope`, τα στοιχεία Entra ID χρησιμοποιούν `entra_permission` ή `entra_role`, ενώ τα στοιχεία Kubernetes χρησιμοποιούν `verb`, `resource`, `subresource`, `api_group` και `namespace`. Τα placeholders όπως `{target.arn}` συνδέουν μια απαίτηση με τον στόχο.
- `target`: το `kind` του στόχου, ένα `selector` του οποίου πρέπει να ισχύουν όλες οι συνθήκες για να είναι προσβάσιμη μια αρχή και το `scope` του.
- `conditions` και `blockers`: τι μπορεί στην πράξη να εμποδίσει τη διαδρομή, όπως condition keys, SCPs, boundaries ή admission policies.
- `confidence`, `severity`, `mitigation`, `references` και προαιρετικά `notes`.

Άγνωστα πεδία, είδη στόχων, κλειδιά selector και placeholders απορρίπτονται αντί να αγνοούνται, ώστε μια εγγραφή να μην μπορεί ποτέ να διευρύνει ή να περιορίσει σιωπηρά το σύνολο των στόχων της. Προσθέστε πρώτα υποστήριξη για νέο selector στον evaluator του καταναλωτή.

### Συνδέσεις σχήματος v2

Ο loader v2 προσθέτει δύο placeholders και έναν selector AWS, ενώ επιτρέπει τον υπάρχοντα selector running-pod της K8s σε στόχους GCP. Αυτά τα πεδία απαιτούν ακριβή σύνδεση με τη συλλεγμένη απογραφή· αν λείπει η απογραφή, η κάλυψη είναι άγνωστη και δεν προκύπτει προσβάσιμη διαδρομή.

| Πεδίο | Χρήση και απαιτούμενη μορφή |
| --- | --- |
| `{source.assumable_role_attached_policy_arn}` και `target.selector.via_assumable_role_attached_policy_covered_by: iam:CreatePolicyVersion` | Χρησιμοποιήστε τα μαζί σε στόχο AWS `aws_account_admin`. Κάθε εναλλακτική απαίτηση πρέπει να περιλαμβάνει `iam:CreatePolicyVersion` σε αυτό το placeholder. Η πολιτική πρέπει να είναι συνδεδεμένη με ρόλο που μπορεί να αναλάβει η πηγή στον ίδιο λογαριασμό· ο evaluator ελέγχει τη χωρητικότητα εκδόσεων πολιτικής και επανυπολογίζει τα ουσιαστικά δικαιώματα του ρόλου. Το `SetDefaultPolicyVersion` δεν καλύπτεται. |
| `target.selector.k8s_sa_used_by_running_pod: true` | Σε στόχο GCP `k8s_service_account` με `scope: cluster`, επιλέγει KSAs που χρησιμοποιούνται από εκτελούμενα pods με διαθέσιμο token στο αντιστοιχισμένο cluster GKE. Μην το συνδυάζετε με `k8s_sa_in_cluster` ή `k8s_sa_has_token_secret`. Η χρήση του σε K8s παραμένει αμετάβλητη. |
| `{source_rolebound_clusterrole}` | Χρησιμοποιήστε το ως `resource_name` σε απαιτήσεις K8s `clusterroles` με `api_group: rbac.authorization.k8s.io` και `namespace: "*"`. Κάθε εναλλακτική χρειάζεται `escalate` και `update` ή `patch` στο ίδιο όνομα. Ο στόχος πρέπει να είναι `k8s_service_account` με `scope: same_namespace` και `selector.k8s_sa_in_namespace: "{target.namespace}"`· ένα RoleBinding πρέπει να συνδέει την πηγή σε αυτό το namespace. |

## Επικύρωση και συγχρονισμός

Πριν υποβάλετε αλλαγές, εκτελέστε `python scripts/validate_privesc_paths.py --book-root .` έχοντας εγκατεστημένο το PyYAML. Ελέγχει τη διάταξη των καταλόγων, κάθε εγγραφή με τον αυστηρό loader του evaluator (`scripts/privesc_paths_schema.py`, αντίγραφο της μονάδας σχήματος του Blue-CloudPEASS), τα μοναδικά id, τις σελίδες προέλευσης και τις άγκυρες επικεφαλίδων, καθώς και ότι το JSON Schema είναι ενημερωμένο. Χρησιμοποιήστε το `--peaso-root /path/to/Blue-CloudPEASS` για να συγκρίνετε επίσης byte προς byte και τα δύο αρχεία σχήματος με εκείνα του καταναλωτή. Η ροή εργασίας pull request του βιβλίου εκτελεί την ίδια επικύρωση.

Κάθε Δευτέρα, το Blue-CloudPEASS κάνει checkout την τρέχουσα έκδοση `master` αυτού του βιβλίου, επικυρώνει αυτά τα αρχεία και συγκρίνει το SHA-256 hash κάθε αρχείου με τα hash που καταγράφηκαν στον προηγούμενο συγχρονισμό. Οι προσθήκες, ενημερώσεις και διαγραφές από το upstream αντικαθιστούν τα αμετάβλητα αντίγραφα στον καταναλωτή. Αν ένα αρχείο έχει αλλάξει και στις δύο πλευρές, αναφέρεται ως σύγκρουση, ενώ τα id τεχνικών δεν αφαιρούνται ποτέ χωρίς ρητά ελεγμένο μητρώο. Αν το περιεχόμενο είναι άκυρο ή αποτύχει κάποιος έλεγχος, ο προεπιλεγμένος κλάδος του καταναλωτή παραμένει αμετάβλητος. Οι άσχετες αλλαγές στο βιβλίο δεν δημιουργούν commit στον καταναλωτή.
